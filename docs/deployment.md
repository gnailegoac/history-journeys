## 做法

- **代码在 GitHub 上**，开发在分支上进行。
- **推送 `main` 分支后自动跑三步**：类型检查、内容校验、单元测试、构建和大小检查；浏览器端到端测试；发布到 GitHub Pages。前两步不通过就不发布。推送到 `ci/` 开头的分支时只跑前两步，不发布，用来在发布以前先在流水线的 Linux 上试跑（`decisions.md` 第 29 条）。
- **负责人说“发布”，才合并到 `main` 并推送。** 在此之前不推送 `main`。
- **线上是纯静态站点。** 讲解员在线上先只有界面；带大模型的版本以后在本机运行。
- **本机启动脚本**：在电脑上起服务，电脑和家里局域网的平板、手机都能打开，用来审核。
- **给负责人在真机上看的样张**放在线上站点的 `samples/` 路径下，正式页面不链接过去，用完删掉。发布它同样要负责人说“发布”。

## 两套环境

| 环境 | 用途 | 部署在哪 |
|---|---|---|
| 本机 | 开发、审核、平板实测 | 本机启动脚本，局域网可访问 |
| 线上 | 公开访问 | GitHub Pages |

不单设预览环境。电脑上的审核在本机完成；平板和手机上的审核，目前是发布到网上以后看（第一版原型就是这样，见 `decisions.md` 第 14 条）。

## 需要记住的限制

- GitHub Pages 规定发布的站点不能超过 1 GB，每月流量的软上限是 100 GB。每座沙盘的地形文件、图片和定格图都随仓库一起发，计入这 1 GB；人物多了要留意总量。
- github.io 在国内访问不稳定。家里使用以本机启动脚本为准。
- 仓库公开，全部正文和设计文档也随之公开。

- 只在负责人明确同意后提交和推送。
