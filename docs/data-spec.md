# 数据规格

状态：原型阶段的规格（2026-11-17）。机器可读的形式是 `src/domain/types.ts`，每个字段的含义写在那里的注释里。内容文件由 `npm run validate` 自动校验。要改规格，先改这里和 `types.ts`，再改内容和程序。

## 文件放在哪

```
content/figures/
  index.json                首页的人物卡片
  <人物>/figure.json         人物资料、各站的抬头、轨迹
  <人物>/stops/<站>.md       一站的正文
  <人物>/stops/<站>.json     一站的小注、原文、图片、凭据、示例问题
  <人物>/images/             图片文件
```

加一位人物只加这些文件，不改程序。

## 正文怎么写

正文是受限的 Markdown，只有三种写法：

- `## 小节标题`：正文必须从一个小节标题开始。
- 段落：段与段之间空一行。
- `> ` 开头的引用行：引用的原文句子，一行一句。

正文用“我”自述，只写他当时看到和知道的事。年纪：近代以前的中国人物用虚岁，并在文字里写明“虚岁”。不写别的格式（加粗、链接、列表、图片都不用）。图片和原文放在 `<站>.json` 里，用 `section` 指明跟在哪一小节后面。

## 校验规则

1. **坐标**：`[经度, 纬度]`，经度在 −180 到 180 之间，纬度在 −90 到 90 之间。
2. **站点与轨迹**：站的 `id` 不重复；`legs` 比 `stops` 少一个，并且依次首尾相连。
3. **文件齐全**：`status` 为 `complete` 的站必须同时有 `.md` 和 `.json`；为 `outline` 的站两个都没有。
4. **正文**：`complete` 的站正文在 800 到 1400 字之间，每个小节至少有一段，小节标题不重复（原文、图片、凭据都靠标题对上小节）。
5. **小注**：`anchor` 必须在正文的段落里原样出现；`kind` 是历史、地理、人文、科学四类之一；`sourceIds` 至少一个，并且都能在 `sources` 里找到。
6. **原文**：`section` 是正文里的小节标题；`sourceId` 能在 `sources` 里找到；原文和白话都不为空。
7. **图片**：文件存在；`section` 是正文里的小节标题；`alt`、`caption`、`credit`、`license`、`sourceUrl` 都填写。
8. **凭据**：正文的每个小节都有一组凭据，每组至少一条；依据不是“编写时补的”时，至少填一个出处。
9. **没有占位**：首页的人物卡片、人物资料和 `complete` 的站里，不能留占位或待办的括注：“（待”开头的文字，以及括号里带“待核、待填、待补、待定、待查、待写、起步稿”的话。还没写的站（`outline`）的抬头不在此列，但也应当填好。
