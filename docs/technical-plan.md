## 2026-11-24 改了什么（眉州的沙盘；有沙盘、正文还没写的站）

改的在第六、七、九节；页面上的样子记在 `data-spec.md`“人物页和没有自己的沙盘的站摆什么”。

1. **沙盘可以比正文先做好**（第九节第 7 步）。原来的次序是一站先写正文、再做沙盘，沙盘的小节照正文的小节摆；眉州（头一站）倒过来：正文还没写，沙盘先做好了。这样的站，场景文件里的“小节”是三到六个画面（眉州四处），出处写在场景文件自己的 `sources` 里；页面上没有正文带着镜头走，文字栏里是一句话和一张单子“沙盘上看的几处”，按哪一行，沙盘就换到哪一处，和写好了的一站读到另一小节走的是同一条路。后面五座沙盘哪一座先于正文做好，都照这个样子。
2. **第三家零件：小工程**（第六节）。浮桥、池、坟三样的程序是单独的一小块（`works`），眉州要它，徐州、黄州和全程沙盘不下载。零件库的装配多了一样通用的做法：同一样东西可以备几种做法，镜头远近过了线才换（浮桥远看是五只大船身，推近了是九只、十四只小的），不用每一帧重造。
3. **窄的河上不画水纹**（第六节）。看整块沙盘的时候，河在画面上只有三十来个像素宽，水纹的一道白线比河还长，成了一条条横在河上的杠。场景可以写一个数（`calmUnderPx`）：河在一幅 900 像素高的画面上窄过这个数就不画水纹，宽到一倍半才照常画，中间慢慢添。照的是镜头现在的远近，每一帧算一次，所以滑动、读者自己推近拉远的时候都跟得上。眉州写了这个数（48）；检查以后徐州也写了（26），只有“到徐州”一节的水面变了。黄州和全程沙盘的画面一个像素也没有变。
4. **量到的大小**（第七节）。页面程序离上限只剩五百多字节；摆全程沙盘要下载的程序离上限不到四千字节。添下一座沙盘以前先量。

## 2026-11-23 改了什么（从全程沙盘到一站自己的沙盘，镜头先拉近）

改的在第七节（页面程序的上限）；做法记在这里。

1. **做了什么。** 负责人在平板上看过第二次发布，只提了一处：从全程沙盘换到一站自己的沙盘（现在只有徐州）是一下子跳过去的。现在是“先潜下去，再换页”：读者在摆着全程沙盘的页面上（首页、人物页、没有自己的沙盘的一站）点一个通到“有自己的沙盘的一站”的站内链接（沙盘上的印和地名、目录里的那一行、“上一站”“下一站”都算），全程沙盘的镜头从它现在的地方朝那一站的地名点潜下去，用 0.9 秒，照钟点走（慢的设备上是画的帧少，不是潜得久）：镜头先转过去对准那一站，钟点走到六成的时候那一站已经在画面中间；一边转一边凑近，凑近是起步慢、越来越快。一起步别的题签都收起来，只留那一站自己的名字（它告诉读者镜头往哪儿去），留在原处、跟着镜头走；潜的这不到一秒里读者的手动不了镜头（碰一下、滚轮转一下都不算）。最后 0.3 秒，放画面的那一块淡进沙盘栏的底色里；潜完才把地址换成链接上写的那一个，那一站的沙盘栏照旧摆出来，只是头一张图片是从底色里浮上来的。点下去的那一刻就去取那一站的场景、图片的清单和头一张图片。
2. **什么时候不潜，一点就换（和以前一样）。** 按着别的键点的（要在新标签页里打开）、返回和前进、直接打开的地址；栏里放的是图片（设备带不动立体的沙盘）、全程沙盘还没摆好、画面断了、嫌慢了；窄屏上沙盘栏收起来了；系统设置了“减少动态效果”；地址里带 `?dive=none`。自动测试用的沙盘替身平时也不潜，地址里带 `?dive=1` 才潜。
3. **不会卡住，不会换两次。** 潜了 1.2 秒沙盘还没有回话，地址照样换过去；正在潜的时候同一个链接再点一下，什么也不变；点了别的链接，不潜了，照那个链接走；按了返回，马上回去，以后也不再换（按返回退出了这个网站也一样：再按前进回来，不会被送到那一站去）；沙盘半路断了、嫌慢了、关掉了，马上放行；正在潜的时候按着别的键点链接（要在新标签页里打开），照旧不管；沙盘栏拿走的时候，监听和定时器一起收掉——还在潜就被拿走、地址却没有变的话，地址马上换过去（现在的页面上读者做不出这件事）。读者在潜的时候把沙盘收起来、转屏，栏并没有拿走，照旧潜完才换。从首页潜过去，人物还在读的那一下版面是两栏的壳（沙盘栏空着，是绢的底色，栏上写的状态是“正在摆”），不换成独自一页纸的“加载中…”。
4. **程序放在哪。** 镜头怎么走（潜到哪、路怎么算）在全程沙盘自己的那一小块程序里（`src/stage/three/routeLevel.ts` 的 `diveEnd`、`divePath`），站点沙盘的页面不下载它；题签层多了一个“只留一条”（`src/stage/overlay/strips.ts` 的 `only`）；先后由换小节的那一个调度管（`sequencer.ts` 多了一个 `free`），沙盘的接口多了一个可有可无的 `dive`（`src/stage/types.ts`）。页面这一边的规矩和先后在 `src/ui/dive.ts`（不碰沙盘栏的组件，在 Node 里查），沙盘栏只接线，潜的时候在栏上写 `data-stage-dive`；淡出和浮上来各是样式表里的一条。徐州的沙盘没有动：它先画好的地面、它的定格图一个字节都没有变。
5. **没有做的。** 离开一站自己的沙盘回到全程沙盘时不拉远，还是直接换；设计第六节的“进一站先看来路”；黄州自己的沙盘那时还没有（后来做了，见第九节第 3 步）；放着图片的那一档上“图片朝那一站放大再淡掉”。读者在潜到最后几十毫秒时按返回，浏览器可能来不及：地址已经换了，再按一次返回就回去了。

## 一、工程思想

1. **内容与程序分离，数据驱动。** 网站是一个“阅读器”，人物是数据，每座沙盘上摆什么也是数据。（改）加一站、加一位人物，主要是加内容文件；零件库里没有的东西和新时代的样式要改程序。
2. **契约先行。** 人物、轨迹、站点、小注、场景、镜头长什么样，先用一份数据规格定死。程序和内容都以它为准，并由工具自动校验。
3. **纵向薄切片，逐步放宽。** 先把“一位人物、一站”从内容到沙盘到页面完整做通，再加站、加人物。每一步结束都有能打开看的东西。

## 二、架构

纯前端静态网站，没有服务器、数据库和账号。只有 AI 答疑将来需要一个很薄的服务端接口。

```
内容层      每位人物一个文件夹：人物资料、轨迹、各站正文、图片、
   │        全程沙盘和各站沙盘的场景数据、地形文件
   │  构建时按数据规格校验
数据与领域层  读取内容；人物、轨迹、站、小注、场景的纯逻辑
   │
界面层      首页 · 人物页 · 站点页 · 讲解员面板
   │                    │
沙盘适配层              答疑适配层
   │                    │
沙盘程序                原型：占位；以后：服务端接口
 ├─ 地形和水
 ├─ 零件库（城墙、楼、亭、桥、船、田、树……）
 └─ 时代样式（颜色、题签、木框）
```

页面只对适配层说“摆出全程沙盘”“看从上一站到这一站的那段路”“摆出这一站的沙盘”“看第三小节”“回到这一节”，不直接碰沙盘程序。以后换画法或换大模型，只动一个模块。

## 三、分层

| 层 | 负责什么 | 怎么测 |
|---|---|---|
| 内容层 | 人物资料、轨迹坐标、各站正文、小注、图片、凭据；场景数据和地形文件 | 自动校验：原有各项，加上场景数据的检查（每样东西有位置、类别和依据，都落在沙盘范围内，每个小节有镜头） |
| 数据与领域层 | 读取内容，以及不依赖界面和沙盘的纯逻辑 | 单元测试 |
| 沙盘适配层 | 页面和沙盘之间唯一的接口 | 用“假沙盘”做界面的浏览器自动测试（原型已有这套做法） |
| 沙盘程序 | 地形、水、零件库、时代样式、镜头 | 纯计算部分做单元测试。每座沙盘的每个镜头出定格图；程序、零件或样式改了以后，工具重新生成并自动标出画面变了的那些，人只看变了的。三角形数量、贴图尺寸、文件大小自动量，超预算不通过。加载时间和流畅度在真机上由人量 |
| 界面层 | 三种页面和讲解员面板 | 浏览器自动测试走通主流程 |
| 制作工具 | 取地形并裁切、给地形上色、生成定格图、裁剪字体 | 在同一台机器上结果可重复生成 |

依赖只能从上往下；内容里不出现代码。

## 四、防止风险和失控的原则

1. **分阶段审核，不越级。** 整体设计、技术方案、风格样张、重做的每一步、扩充内容，每一关负责人通过后才进下一关。
2. **范围锁定。** “暂不做”清单有约束力；过程中冒出的新想法记入待办，不混进当前这一步。
3. **小步，随时可运行。** 每次改动都小，主干任何时候都能打开运行。
4. **用证据说话。** “完成”的标准是自动测试通过加浏览器实测；没验证的地方明说。
5. **单一事实来源。** 设计决定和数据规格各只有一份，放在 `docs/` 里；要改先改文档。
6. **易变的部分隔离。**（改）沙盘程序和大模型都在适配层后面；画法（时代样式）、零件、场景数据三者分开。
7. **性能有预算。**（改）每座沙盘的三角形数量、贴图大小、文件大小先定上限，自动检查；加载时间和流畅度定目标，在真机上量。
8. **史实有红线。**（改）没有填写凭据的内容通不过校验；摆上沙盘的东西没有写类别和依据，同样通不过；AI 不生成正文。

两点说明：

- **字体。** 样张里的楷体是 Windows 中文版自带的。iPad、iPhone、安卓设备上都没有楷体，照样张的写法，平板和手机上多半会全部显示成黑体（还没有在真机上看过）。Windows 的楷体不能随网站分发，所以换成开源的霞鹜文楷 GB；宋体用 Noto Serif SC（它和 Adobe 发行的思源宋体是同一套字，谷歌这一版没有保留字体名称）。两套都按 SIL 开放字体许可 1.1 版使用。做法（2026-11-19 定的）：
  - 只带网站用到的字。`npm run fonts` 把这些字从原字体里裁出来，做成三个 WOFF2 文件，放在 `src/fonts/`：`yanlu-kai`（用楷体排的字：标题、小节名、题签、按钮上的字）、`yanlu-song`（不用点开就看得见的字）、`yanlu-song-more`（点开小注、原文、凭据、“说明”才看得见的字，用到时才下载）。哪些字归哪个文件，工具照页面自己的程序去数，见 `data-spec.md`“随站的字体”。
  - 原字体（两个文件，共约 38 MB）不进仓库，放在制作的机器上的 `.cache/fonts/` 里；做好的三个文件进仓库。发布的流程只用做好的文件，不裁剪，也不下载。
  - 忘了重做会怎样：网站上有一个字不在字体文件里，`npm test` 通不过，说出是哪个字、在哪里用的、该跑哪条命令。
  - 页面怎么取：楷体和头一个宋体文件一打开网站就取；第三个文件用到时才取，写好了正文的站点页空下来两秒以后也会先把它取来（还没写的站不取）。文件还没到的时候，字先用设备自带的字体显示，到了再换，按钮和标题上不会空着。全角的标点都占满一个字宽，挨着的两个不挤紧：Chrome 和 Safari 的做法不一样，不这样，同一段话在平板上和在开发的机器上会断在不同的地方。靠的是随站的字体里没有带把标点挤窄的那几项排版功能，浏览器想挤也挤不了（在 Chromium 里量过：样式表里那一句 `text-spacing-trim: space-all` 写不写都是两个字宽）；样式表里那一句管的是设备自带的字体顶着的那一会儿。细处见 `data-spec.md`“页面怎么用这两套字体”。
  - 字体里保留着让小字更清楚的提示信息（hinting）。去掉它宋体能小 16%，但是普通的 Windows 屏幕上字会不会变糊，开发用的机器上看不出来，所以留着。
  - 现在的大小（2026-11-20 量的，两站正文、徐州和全程两座沙盘、“来源”页）：`yanlu-kai` 65,508 字节（295 个字），`yanlu-song` 240,408 字节（994 个字），`yanlu-song-more` 229,364 字节（793 个字）；首次打开要下载的是前两个，合计 305,916 字节。（全程沙盘接进来以前是 55,988、238,988、189,476 字节，合计 294,976：全程沙盘的地名和题记进了头两个文件，它的“说明”和凭据进了第三个。）原来估的“楷体每位人物几十 KB、宋体常用字一份约 300 KB”偏小：宋体要是做成一个文件，连同楷体首次打开就要下载约 453 KB，已经过了上限，所以分成两个。每多一个新字，文件大约长 280 字节。
- **支持的设备。** 最老支持到 2021 年的 iPadOS 15（iOS 15）和 Safari 15。只考虑平板和电脑，不考虑手机（`decisions.md` 第 22 条；手机上网页仍然打得开，但不为它调画面，也不拿它检查）。iPad 从 iPadOS 15 起，安卓平板和电脑上近几年的浏览器，都打得开网站，也看得了立体的沙盘（立体的沙盘要浏览器支持 WebGL2，网页画三维用的功能）。比这更老的浏览器不在支持之列：页面本身启动不了，定格图也就显示不出来，这时只显示一句话：“这个浏览器太旧，打不开这个网站。换一个新一点的浏览器再来看。”（页面的程序没取到，比如网断了一下，是另一回事，说的是另一句：“网页没有加载完整，刷新一下再试。”）页面打得开、但画不了三维的设备（或者太慢，或者画面中途丢失），看定格图。
  - 竖着拿的大平板（12.9 英寸的 iPad，1024 × 1366）和别的竖着拿的平板是同一种版面：沙盘在上，占屏幕高度的 56%，正文在下。它有 960 像素以上宽，原来照宽度分版面，它得到的是左右两栏，沙盘栏又窄又高（584 × 1366）；现在左右两栏要窗口够宽、而且横着（`(min-width: 960px) and (orientation: landscape)`，`decisions.md` 第 28 条）。它是第四种标准的画面（沙盘栏 1024 × 765）：题签的检查、沙盘栏四边留的空、定格图怎么摆，都把它算进去（`tests/stage/support/standardPanes.ts`、`tests/e2e/large-upright.spec.ts`）。
  - 老平板（系统停在 iPadOS 15 的那些）上，沙盘栏和新平板是同一种排法。沙盘旁边那块字有宽、窄两种排法，原来靠样式表里“按栏宽查询”的写法（`@container`、`cqw`）来分，iPadOS 15 不认，在它上面不管栏多宽都只有窄的那一种，沙盘四边留的空也就和定格图、题签的检查不是同一套数。现在由页面量了栏宽以后在栏上挂类名来分（`src/ui/StagePane.tsx`、`src/styles/stage.css`），样式表里不许再有那两样（`npm test`、`npm run check:size` 守着；浏览器测试里另有一个照 iPadOS 15 的读法改过样式表的替身，`tests/e2e/pane-look.spec.ts`）。Safari 本身这台机器和发布流程都跑不了，真机上还要看。
- **页面的样子**（重做顺序第 2 步）。三种材料：纸（正文那一页）、绢（沙盘栏的底，和没有纸的地方露出来的底，`#c5b189`）、纸条（摆在绢上的东西：按钮、题签、展开的说明）。沙盘栏的底是平的一种颜色：定格图的边要淡进它里面，底上有纹理就会露出一个方框；改了它，定格图要重拍。绢上的字都是墨色，红只做记号。沙盘座子落在案上的影子是半透明地盖在这块底上的，颜色取深一些的绢色（`src/stage/three/table.ts`）。各处的颜色、字号都是 `src/styles/tokens.css` 里的记号。

## 六、沙盘程序怎么组织（新）

- **场景数据**（全程沙盘每位人物一个文件，站点沙盘每座一个文件）写明：范围和地形文件；对地形的修整（哪里抹平、哪里垫高、河道挖在哪）；水（河道、湖岸、平时和大水时的水位）；摆件（城墙、城门、楼、亭、堤、船，各自的位置）；题签；每个小节的镜头，以及这一节沙盘处在什么状态（水位多高、哪些东西已经有了）。
- **每一样摆件和每一处修整都带类别和依据。** 类别就是整体设计里的五类：真的、今天的位置、按史料摆的、示意的、点缀。页面上沙盘旁边的那句说明从这里生成。
- **零件库**：城墙、城门楼、角楼、殿、亭、民居、桥、堤、船、田、树、石。每个零件是一段带参数的程序（几间宽、几层、什么屋顶）。黄州的大江是用地面的修整加水位做的（不是新零件）；黄州新添了崖壁、不闭合的矮土墙和一座小门、崖脚的石头、竹和柏。**只有一部分沙盘用得着的零件按“家”分块**（2026-11-23）：它们的程序不在沙盘程序里，一家一小块（2026-11-24 起三家：石和土 3,400 字节，草木 197 字节，小工程——浮桥、池、坟——3,191 字节，眉州添的），登记在 `src/stage/families.ts`，场景里写到了才下载；徐州和全程沙盘一家也不下载。这样以后各站的新零件（塔、水门、廊桥……）不占沙盘程序的地方，添一家不用动沙盘程序。每一家的文件里要写一句 `import '../engine'`（和全程沙盘那一块一样）：不写的话，打包的工具会把两边共用的东西另拆一块，哪座沙盘都要多下载一个文件、多五千来字节。崖壁是一个合起来的块，对着地形板量（`src/stage/three/meshHeight.ts`）：地形板的网格 59 米一格，立不住陡坎。
- **时代样式**：一套颜色、题签的样子、木框和底座、光线。苏轼用设色这一套。
- **制作时先做好的东西**：地面的颜色和田的标记在制作时画好存成图片，不在打开网页时现画（样张是现画的，占了启动计算的大半）。这两张图由 `npm run bake` 做，放在 `baked/` 里；`scenes/` 里只放手写的场景文件和地形文件。山的明暗不存成图：打开网页时照地面现算，只要十几毫秒，所以换了光，这两张图不用重做。
- **定格图**：同一段程序在制作时把每个镜头存成图片，宽、窄各一张，窄的给竖着拿的平板（这时沙盘栏在正文上面，是扁的，不是竖的）。图上不带字：题签还是页面自己的字，照和图一起存下的位置摆，所以定格图上古名、今名照样能换。由 `STILLS_OUT=content/figures npm run stills` 在同一台机器上生成、压缩后放进仓库（放在 `stills/` 里；不带 `STILLS_OUT` 只是试拍，不动仓库里的图），发布时不重新生成（没有显卡的机器一张要好几秒，不同机器画出来的也略有差别）。定格图或者先画好的地面比做它的东西旧了，`npm test` 不通过。用处有四个：三维画面没加载好时先显示它；设备不支持、太慢或画面中途丢失时代替三维；首页和目录里的小图；每座沙盘拼成一页给负责人看。
- **全程沙盘是同一种格式里的第二级场景**（2026-11-20）。场景文件、类别和依据、题签、小节、定格图、三档画质都和站点沙盘是同一套；不同的是：范围用圆锥投影，山高按一条曲线夸大（矮山多夸）；有路；它的“小节”是看法——头一节看全程，后面每一节看到某一站去的来路，人物页和首页看头一节，没有自己的沙盘的站看它自己的那一节。它的地面一定是制作时画好的（上色的程序是工具，不随网站发），页面打开时不现画；图没有或者取不到，就放定格图或者一句话。定格图在这一级还多一个用处：没有自己的沙盘的站上，立体的沙盘摆好以前、或者摆不了的时候，显的是那一段来路的图片。画路和印的那一小块程序（十千字节上下）是单独的一块，摆全程沙盘时才下载，摆站点沙盘时不下载。
- **一块画布。** 全程沙盘和站点沙盘共用一块画布，同一时刻只有一座沙盘在内存里；离开一站时把它的模型和贴图释放掉。人物页和没有自己的沙盘的各站用的是同一座全程沙盘，在它们之间来回不重摆，镜头滑过去（首页是另一页，从首页进人物页时重摆一次）。
- **沙盘的框和高度夸大的方式是数据**，不写死在程序里：别的人物范围不同。

**样张能留用多少。** 样张（`spikes/art-direction/b`）的画面程序约三分之二能留用，其中一多半要改成由参数驱动；另外三分之一是写死的徐州（城的位置、堤、船、镜头、题签的位置），要改成数据。页面不搬样张的，照它的样子改现有的 React 页面。有三处不管怎样都要重做：远近两套模型来回切换（会跳），改成一套模型按远近连续变化；题签位置是按一种屏幕大小手调的，改成自动摆放、互相避让；每个镜头各调一套光，改成一种样式一套光。

**另外两份文档要跟着改的地方。**

- `data-spec.md`：加场景数据；一站可以有一座以上的沙盘，可以有沙盘之外的远处地点；每一小节有自己的镜头和沙盘状态，取代原来的“总览镜头”和“每站一个镜头”；轨迹的每一段注明走水路、陆路还是海路，水路沿着河画；题签只用汉字、不超过七个字；用到的字都要在随站的字体里；去掉“加一位人物只加这些文件，不改程序”一句。
- `deployment.md`：去掉“地形瓦片”的说法，改成“每座沙盘的地形、图片和定格图随仓库发，计入 1 GB 的上限”；写明平板和手机上的审核要先发布到网上。

## 七、性能预算（改）

样张里徐州那座沙盘：13 万到 18 万个三角形，一张 2048 的阴影图；启动时单是计算就要 2 秒多（不是在浏览器里量的，还没算显卡上的准备），其中 1.5 秒是给地形上色。**样张没有在平板和手机上跑过。**

自动检查的上限：

- 一座沙盘不超过 20 万个三角形。
- 贴图不超过 2048 像素见方。
- 一座沙盘的文件（地形文件、地面的颜色图、田的标记图）合计不超过约 1.5 MB；每张定格图不超过约 300 KB。

做法上的规矩：

- 只在镜头移动或水位变化时重画，读正文的时候一帧都不画，省电、不发热。阴影也只在变化时重算。
- 三档：完整；减配（屏幕像素比降到 1.5、雾减为一层、阴影图减小、树和房屋减半、不做抗锯齿）；定格图。
- 怎么选档。浏览器不会告诉网页是什么设备，所以分两步：屏幕大小只定像素比（画面的像素太多，就把像素比调低）；用哪一档看启动时一次试画的用时，够快用完整，慢了用减配，连减配也带不动就用定格图；浏览器自己说只能用软件画的时候，不等试画，这一次访问最高只用减配。之后只降不升：镜头自己滑动的时候（换小节、回到这一节）量相邻两帧隔多久，太慢就重建画面降一档。往回升只有一条路，是读者自己点“试试立体的沙盘”这个按钮。
- 多少毫秒算太慢，要在真机上量过才定。程序里先放的是起步的数，量过以后会改：试画一次超过 50 毫秒降一档，超过 200 毫秒直接用定格图；镜头滑动一次，相邻两帧隔的时间取居中的数，超过 42 毫秒算慢，连着两次滑动都慢就降一档，超过 125 毫秒马上降。沙盘栏太小的时候先不试画，等它够大了、下一次摆好画面再试：面积不到八万平方像素的不试；不到 100 像素高的也不试，不管多宽——上下排的版面上收起来的沙盘栏是 59 像素高的一条，和窗口一样宽，竖着的窗口再宽也是上下排，只看面积拦不住它（`src/stage/three/tier.ts` 的 `bigEnoughToTry`）。换档是设备慢的时候本来该走的路，不是出了错：页面只在浏览器的控制台里记一笔（`console.info`），不算警告。
- 自动测试和做图的工具（拍定格图、拍给人看的照片）不让程序自己选，在网址里写 `?tier=` 指定一档，每次的结果才一样。

## 八、最大的风险（改）

- **沙盘在平板上的流畅度。** 样张只在开发机上看过。动手重做之前先把样张原样发到真机上量一次（第 0 步）；第 1 步做完再量一次，这时减配一档和定格图已经做好，不流畅当场能换。
- **每站一座沙盘的工作量。** 每座都要考证、摆、检查。靠零件库和场景数据把每一座的工作量压下来；先做两座，量出实际用时，再排后面的。
- **沙盘上的史实。** 画面会把城墙、河道画在确定的位置，比文字更容易画错。工作量最大的是水：八站的河道、湖岸、江岸、海岸和全程沙盘上的黄河、淮河、汴河、苏北海岸，都不能照今天的画；查得到依据的按依据画，多数只能画成示意。每座沙盘动手之前先列出“要考证什么”。考证由谁把关，见整体设计“请负责人定”第 4 条。
- **全程沙盘好不好看还不知道。** 范围大了一百多倍，最高的山也只有沙盘宽度的百分之二三（徐州样张里约是百分之十），要靠颜色和明暗把山画出来。先出样张，出两种给负责人挑：全图一个倍数（山更平），或者低山多夸、高山少夸（说明里写范围）。
- **夜景做了，雨、雪不做。** 黄州有三小节写的是夜里的事：夜里的光先在徐州的沙盘上试过，黄州的三节从它的沙盘头一回摆出来就是夜里（月光多强跟着月亮的高矮走）。夜色在真的平板上、亮屋子里看着怎样，还没有在真机上看过。
- **有两站不止一个地方。** 眉山一站是出川的两段路，惠州和儋州相隔六百多公里。
- **汴京几乎全是示意。** 地是平的，宋代的地面埋在今天的地面下，城墙只有大致范围。动手前先给负责人看一张草样，定是照样做、做成一眼看得出是示意的简图，还是这一站不做站点沙盘。这三站放在后面做。
- **内容产能。** 每位人物约八站，每站约千字且要有凭据。（不变）

原来的风险“地形和底图依赖外部的开放服务”不再存在。

每一步做完都有能打开看的东西，负责人看过再进下一步；发布到网上仍由负责人决定。每一步都带着自己的自动测试做完，不留到最后。
