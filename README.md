# 沿着他走过的路

选一位历史名人，以“我”的身份，沿着他一生走过的路一站一站读下去，在每个地方看见当时的时代、山川、风物和技艺。是学习网站，不是游戏。

整体设计见 [docs/overall-design.md](docs/overall-design.md)。

现在做到哪：第一位人物是苏轼，写好了两站的正文（徐州、黄州），另外六站只有抬头。有四座立体的沙盘。一座是全程沙盘：他一生走过的八站和站与站之间的路，摆在首页和人物页上；每一站的名字下面有一方红印，写着它是第几站，按了就进那一站。一座是徐州的沙盘，镜头、水位和题签跟着读到的小节换。一座是黄州的沙盘：宽的大江（水有水落、平时、高水三种高低）、对岸的山、寺和屋子、小船，九个小节，其中三节是夜里；赤壁的石崖、水落才露出来的崖脚的石头、山坡上的竹和承天寺院里的竹和柏；白天的城——几段塌了的矮土墙和篱笆、一座小东门、东坡西边和两座寺四周的竹林，东坡的田画成青苗的草绿，承天寺的院子画成浅色。“一天一百五十钱”和“寒食，沙湖”两节用同一个镜头看临皋亭，一比就看得出春水涨到了门口。沙盘上不画月亮，夜里的光从那一夜月亮的方向来。一座是眉州的沙盘（头一站，正文还没写，沙盘先做好了）：平地上一座有城墙的小城，城东一条又宽又浅的江（当时叫玻璃江），江东是一道青绿的山；看四处——整座沙盘、城里纱縠行的家（篱笆、竹子、一口小池）、正月里出东门过江上蟆颐山的路（渡口、卵石滩、一座船搭的浮桥、半山的一座殿）、东北山里的老翁泉（一大一小两座坟、泉边的亭子和小池、四周的小松树）。这一站的页面上没有正文带着镜头走：文字栏里是一句话和一张单子“沙盘上看的几处”，按哪一行，沙盘就换到哪一处；四处各有各的时间，写在每一行里。别的五站还没有自己的沙盘，沙盘栏里是全程沙盘上到这一站去的那一段来路。从摆着全程沙盘的页面进徐州、黄州、眉州，镜头先朝那一站潜下去，再换成它自己的沙盘。“进一站先看来路”在有自己的沙盘的站上还没有做：这三站一打开就是它自己的沙盘。打开一页，先显出先拍好的定格图，立体的沙盘摆好了再换上去。设备慢的时候，沙盘自己降到减配的画质（树和成片的民居各留一半，雾只画一层，不做抗锯齿，影子粗一些）；再慢，就一直放定格图，读者可以按“试试立体的沙盘”；浏览器画不了立体的画面时也一直放定格图（这时没有这个按钮）。只照平板和电脑做，不考虑手机。沙盘上每样东西是真的、按史料摆的还是示意，沙盘旁边有一句话说明（点“说明”展开完整的几句），每一站的“凭据”里逐样列着。

## 运行

双击 `启动.cmd`。窗口里会写出要打开的地址：这台电脑用 <http://localhost:5400/>，家里同一个网络里的平板、手机用窗口里列出的那个地址。用的时候不要关窗口。

也可以在命令行里运行（需要 Node.js，开发时用的是 24）：

```
npm install
npm start
```

## 检查和测试

| 命令 | 做什么 |
|---|---|
| `npm run typecheck` | 类型检查 |
| `npm run validate` | 内容校验：按数据规格检查 `content/` 里的每位人物、每一站，把不合规格的地方逐条列出来；人物的行迹（规则 22：时间轴和沙盘上的小像照它走）也在这里查 |
| `npm test` | 单元测试；每座沙盘的验收（地面、镜头、题签、预算，先画好的地面和定格图旧不旧）；随站的字体够不够、对不对 |
| `npm run build` | 构建，结果在 `dist/` |
| `npm run check:size` | 查刚构建出来的 `dist/` 有多大（要先构建）：摆沙盘时才下载的沙盘程序、页面一打开就下载的程序和样式表、随站的字体、整个文件夹，超过上限就通不过，每次都印一张表；顺带查随站的字体在构建出来的网站里带得对不对（正好是那四个文件，`index.html` 预先声明的正好是记录里标着的那两个、和样式表里写的是同一个），构建出来的样式表里没有老平板读不懂的几种写法 |
| `npm run check` | 上面五项依次跑一遍 |
| `npm run test:e2e` | 浏览器端到端测试（第一次先运行 `npx playwright install chromium`）。页面的各项用不画沙盘的替身来测；另有六项用真的沙盘（徐州的沙盘和人物页上的全程沙盘，各有完整的画质、减配的画质、让它自己挑三种），看它摆不摆得出来、换不换得动小节、一个画面要画的东西在不在预算里，全程沙盘上按一方印到不到得了那一站（`tests/e2e/real-table.spec.ts`）；还有一组在浏览器里把网站走一遍，看每一个字是不是随站的字体画的（黑体的只用黑体，楷体的只用楷体、而且只在题签上）、有没有请求出了网站自己的地址、字体文件来得晚时按钮和题签上有没有字（`tests/e2e/fonts.spec.ts`）；一组量正文那一栏：一行多少个字、可以点开的词下面有没有虚线、能点的东西够不够 44 像素见方，还有贴着底边的那一条（上一站、问讲解员、下一站）和点开的讲解员面板在四种标准的窗口上的样子（`tests/e2e/leaf.spec.ts`）；一项把每一站的大标题在各种窗口宽度上过一遍，折了行的标题最后一行不能只剩一个字（`tests/e2e/titles.spec.ts`）；一组看首页和“来源”页：四种标准的窗口上首页的文字栏、卡片和沙盘栏里的全程沙盘（按一方印进那一站），“来源”页上三套字体、每一行出处、每一张图片对不对得上随站发的文件，五份许可全文打不打得开，那一页里面的程序是不是点进去才下载（`tests/e2e/home-sources.spec.ts`）；一组量沙盘栏：框架的字是不是都垫着带子或者板（不直接落在沙盘栏的底色上）、够不够深，字有没有小于 14 像素的，题记写满 40 个字在各种栏宽上放不放得下，按钮和题签的样子，题记那一条在四种标准的窗口上每一小节有没有截掉的字、“说明”按钮在不在右头，还有照老平板（iPadOS 15）的读法改过样式表以后是不是还一样（`tests/e2e/pane-look.spec.ts`）；一组看竖着拿的大平板（1024 × 1366）：沙盘在上、文字在下，收起、横过来、再竖回去，只放图片时用的是窄的那一张（`tests/e2e/large-upright.spec.ts`）；一组看全程沙盘下面的时间轴（`tests/e2e/time-bar.spec.ts`，用沙盘的替身）：拖、按、按键、播放的时候圆钮、两行字和小像怎么跟着走，什么时候叫沙盘换小节，每一段的两行字在各种栏上放不放得下，哪些页面上没有它 |

各种上限只写在两个地方：文件有多大（定格图、一座沙盘的文件、随站的字体、程序的下载量）在 `tests/content/budgetRules.ts`，一个画面的三角形数、画几批、贴图多大在 `tests/stage/support/budgets.ts`。

沙盘画得对不对要人看。先设环境变量 `REAL_SHOTS=1`，再运行 `npx playwright test tests/e2e/real-shots.spec.ts`，会用真的沙盘给人物页和有沙盘的那一站的每一小节各拍一张照，最后一节再拍一张点开“说明”的（电脑 1440×900、横着拿的平板 1024×768、竖着拿的平板 768×1024 和竖放的大平板 1024×1366 各一套），存在 `tests/shots/real/`（不进仓库）。想另存一套留着对比，再设 `SHOTS_DIR`（存到哪个文件夹）；想看减配的画质，再设 `TIER=reduced`（不设拍的是完整的画质）；想看只放定格图、不摆立体沙盘时的样子，设 `TIER=still`（这时只拍有沙盘的那一站的每一小节，不拍人物页和“说明”）。只拍一种窗口，命令后面加 `-g "1440"`（电脑）、`-g "横着"`、`-g "竖着"`（两种小平板）或 `-g "1366"`（竖放的大平板）。页面别的几种状态（首页、“来源”页、人物页的各站目录和它后面的链接、一站正文的末尾、点开的小注、原文、凭据、讲解员面板、还没写的一站、没有沙盘的一站、两种“没找到”）另有一条：`npx playwright test tests/e2e/state-shots.spec.ts`，用的是同样的几个环境变量，存在同一个文件夹。拍照之前都等随站的字体到齐。同样设了 `REAL_SHOTS=1`，运行 `npx playwright test tests/e2e/zoom-shots.spec.ts`，会在两个小节上把镜头从近拉到远拍一排，看模型跟着远近变的时候连不连得上，存在 `tests/shots/zoom/`。只看界面的照片同理：设 `UI_SHOTS=1`，运行 `npx playwright test tests/e2e/shots.spec.ts`，存在 `tests/shots/ui/`。

## 工具做出来的三样：先画好的地面，每一小节的定格图，时间轴用的那一份行迹

每座沙盘另有两样东西，是工具照着场景文件和沙盘程序做出来的：做好以后放进仓库，随网站一起发，发布的流程不重新做。清单和图片都不手改。每座沙盘都要有这两样：新加了一座沙盘（`scenes/<站>.json`，全程沙盘是 `scenes/route.json`）而没有做，`npm run validate` 通不过（规则 17、18）。

一座新沙盘要分几步才接得进来（场景文件先进 `content/`，沙盘程序画得出它以后才做得了这两样）。中间这一段，把它的名字（如 `su-shi/huangzhou`）写进 `tests/support/pendingTables.ts` 的表里：校验先不要求它有这两样，下面的 `npm run bake` 和 `npm run stills` 也跳过它。要给表里的沙盘做这两样，命令前面加 `INCLUDE_PENDING=1`（`INCLUDE_PENDING=1 npm run bake`；`INCLUDE_PENDING=1 STILLS_OUT=content/figures npm run stills`）。两样都放进 `content/` 以后把名字从表里拿掉——忘了拿，`npm run validate` 通不过。这张表平时是空的。

| 命令 | 做什么 |
|---|---|
| `npm run itinerary` | 照手写的行迹（`content/figures/<人物>/itinerary.json`）做出时间轴用的那一份（`itinerary.bar.json`）。不开浏览器，一两秒。手写的那一份改了就重做，两份一起提交。 |
| `npm run bake` | 给每座沙盘的地面上色，存成两张图和一份清单，放在 `content/figures/<人物>/baked/`。有了它，沙盘打开时不用现画地面（开发机上徐州摆好快一秒上下）。一座沙盘十几秒；地面没有变时什么也不写 |
| `node tools/fetch-dem.mjs <输出文件，不带后缀> <西> <东> <南> <北> [每格多少米]`（在 `spikes/art-direction/` 里跑） | 取一站沙盘的地形文件：一块地方今天的高程，存成一张网格。要连外面的高程瓦片服务，所以只在添一座新沙盘时跑一次，取下来的 `.bin` 改名放进 `content/figures/<人物>/scenes/<站>.terrain.bin`，范围和行列数写进场景文件的 `terrain`。不带参数取的是徐州那一张。黄州的是：`node tools/fetch-dem.mjs out/huangzhou 114.80 114.92 30.385 30.49 60`（193 列 × 195 行，每格约 60 米） |
| `npm run route:terrain`、`npm run route:today` | 做一位人物的全程沙盘的地形文件和“今天的海岸、湖、河”（`content/figures/<人物>/scenes/route.terrain.bin`、`route.today.geojson`）。只照 `tests/tools/route/figures.ts` 那张表里这位人物写的源数据做（苏轼的是 `spikes/art-direction/route/data/` 里的文件），不连外面的服务；文件没有变时什么也不写。平常用不着跑 |
| `npm run route:map` | 画一位人物的全程沙盘的检查图：从正上方看，场景文件里的每一条线、每一圈、每一条路，放在 `tests/shots/route-check/`（不进仓库）。改了 `scenes/route.json` 里的线以后跑一遍，看一眼 |
| `npm run route:bank` | 做全程沙盘上走水路的路贴着河岸走的线：路画在河的一边，离河心几公里，河才露得出来。只把线印出来，不改文件；看过以后贴进 `scenes/route.json` 里那条路的 `line`，再跑 `npm run route:map` 看一眼。`WAY=w-min npm run route:bank` 只做一条路；每条路离河多远、在哪一边，写在 `tests/tools/route/figures.ts` 里这位人物那一行的 `banks` 里。改了河的线或者这几条路的两头以后才用得着 |
| `STILLS_OUT=content/figures npm run stills` | 把每座沙盘的每一小节拍成定格图，宽、窄各一张，连同一份清单，放进 `content/figures/<人物>/stills/`。一座沙盘半分钟上下；画面没有变的图片不重写 |
| `npm run stills` | 同上一条，只是试拍：存到 `tests/shots/stills-trial/`（不进仓库），不动 `content/` |

四条 `route:` 的命令给哪一位人物做，用环境变量 `ROUTE_FIGURE` 说（人物的文件夹名）：`ROUTE_FIGURE=su-shi npm run route:terrain`。`tests/tools/route/figures.ts` 那张表一位人物一行，写着他的源数据在哪、岸线裁到哪个方框、源数据里哪个湖要放回原来的大小、沿河的路离河多远；地形文件的格子（多少列、多少行、四边在哪）和两个文件叫什么，工具从他的场景文件 `scenes/route.json` 里读，不另存一份。表里只有一位人物的时候（现在只有苏轼）不写 `ROUTE_FIGURE` 做的就是他；有两位以上不写，工具停下来说表里有谁。添一位人物：先有他的场景文件和源数据，再在表里添一行。一行里的方框和湖是跟着源数据走的，不是随意定的：工具不裁陆地，方框得是源数据的陆地已经裁到的那一个；源数据里写着改过的湖，每一个都要列出来——不然工具停下来说，什么也不写。一行要写全了才提交（`npm test` 对每一行都查）；来做文件的时候只查正在做的那一位，别人的一行没写全不碍事，他自己的沿河的路还没配全，工具照做、照印，末了说他那一行和场景里沿河的路对不上，以失败收场。

`STILLS_OUT=… npm run stills` 是 bash 的写法（`ROUTE_FIGURE=…` 也是）；PowerShell 里写 `$env:STILLS_OUT = 'content/figures'; npm run stills; Remove-Item Env:STILLS_OUT`。每次拍完，`tests/shots/stills/<人物>-<站>.html` 是给人看的一页（不进仓库，直接用浏览器打开）：每张图上用红点标着各条题签指的位置，画面变了的那几张有标记。

这两条命令都会打开一个浏览器。同一时刻只能开一个，所以不要和 `npm run test:e2e`、上面拍照的命令同时跑。先后不能反：先 `npm run bake`，再拍定格图（定格图是在先画好的地面上拍的，清单里记着用的是哪一份地面）。

|---|---|---|
| 地面的颜色（JPEG） | 279,735 字节，质量 0.95 | 560,935 字节，质量 0.90 |
| 第二张图（徐州是田的标记，全程沙盘是水纹的标记） | 254,181 字节 | 75,228 字节 |

全程沙盘的定格图是在人物页上拍的（徐州的是在徐州那一站上拍的）。它有三张压得比别的重才进了上限，最大的一张（“出川”，宽的）离上限只有 8,798 字节：改了那一节的镜头或者路以后重拍，留意工具印出来的质量。

改了场景文件或者沙盘程序以后要不要重做、重做哪一条，见 [docs/data-spec.md](docs/data-spec.md) 的“制作时做好的两样”。忘了重做，`npm test` 通不过（存着的图比做它的东西旧了），并且说出是哪一样变了：

- 说“和手写的那一份现在做出来的不一样”：运行 `npm run itinerary`，再提交（这一句是 `npm run validate` 说的：规则 22 的最后一句）。
- 说“先画好的地面是旧的”：运行 `npm run bake`，再运行 `STILLS_OUT=content/figures npm run stills`（地面变了，在它上面拍的定格图也算旧的）。
- 说“定格图是旧的”：运行 `STILLS_OUT=content/figures npm run stills`（那句话里写的就是这一条）。不带 `STILLS_OUT` 只是试拍，不动仓库里的图，检查还是通不过。

重做以后，把 `baked/`、`stills/` 里变了的文件和改动一起提交。文件不齐、对不上清单时，通不过的是 `npm run validate`（规则 17、18），办法一样。

## 随站的字体

网站自己带着三套字体，打开网页时不向别的网站要：黑体是 Noto Sans SC 的 Medium（思源黑体的谷歌发行版），宋体是 Noto Serif SC（思源宋体的谷歌发行版），楷体是霞鹜文楷 GB，都按 SIL 开放字体许可 1.1 版使用。只带网站用到的字，做成四个文件放在 `src/fonts/`，随仓库走，发布的流程不重新做；这些文件都不手改。哪些字归哪个文件、记录里记了什么，见 [docs/data-spec.md](docs/data-spec.md) 的“随站的字体”。页面上，黑体排标题、名字、标签、按钮和单独摆着的日期、数字，宋体排正文和每一句成句的话，楷体只排沙盘上的题签和印（它是苏轼这位人物自己的，不是框架的）；怎么用、什么时候下载，见同一节的“页面怎么用这三套字体”。黑体是 2026-11-24 添的：那一天框架换成了中性的样子。

|---|---|

同一组检查（`tests/fonts/font-files.test.ts`）还守着几条写法上的规矩：界面上的字要原样写在程序里（不用转义、HTML 实体、`String.fromCharCode`、`Intl`、`toLocale` 打头的函数）；样式表的 `content:` 里不写字，每套字体只用它自己的那一种粗细（黑体 500，别的 400；设黑体的每一条规则都同时写粗细），不用斜体，框架的样式和题签的样式各读各的那一套记号，不用 Safari 15 读不懂的写法。换字体以前的页面留下过几处，在那个文件的 `PENDING` 里一处一处点了名，改到哪里删到哪里；现在这张名单是空的，新冒出来的不往里加，改掉它。

## 内容在哪，怎么加一站

内容都在 `content/figures/` 里，程序里不写内容。文件怎么放、正文怎么写、有哪些校验规则，见 [docs/data-spec.md](docs/data-spec.md)。

人物一生哪一段年月在哪里，写在他的行迹里：`content/figures/<人物>/itinerary.json`（手写：每个日子的出处、范围、说不准的都在里面）和 `itinerary.bar.json`（工具照它做的，时间轴用，不手改）。人物页和首页上全程沙盘下面的时间轴、沙盘上的小像都照它走。改了日子、句子、路上的一处，运行 `npm run itinerary` 和 `npm run validate`；动了日子或者农历年的表，发布以前还要有人对着历表读一遍（数据规格“行迹”）。

加一站：

1. 在 `content/figures/<人物>/figure.json` 的 `stops` 里写这一站的抬头。`legs`、`overview` 和每一站的 `camera`、`localPlaces` 现在没有程序读，新写的人物可以不写；已经写着的（苏轼），添一站时 `legs` 里也要接上它和前后两站，校验照旧查（数据规格“停用的字段”）。这一站有了自己的沙盘（`scenes/<站>.json`），就在它的抬头里添一行 `"table": true`：页面照这一行决定沙盘栏先摆什么，校验两头都查（规则 3）。到这一站去的路画在全程沙盘上：在 `scenes/route.json` 里添地名点、路和看这一段来路的那一节（数据规格“全程沙盘的场景数据”），再照上面重做先画好的地面和定格图。正文还没写时，`status` 写 `outline`。正文还没写的站也可以先有自己的沙盘（眉州）：`scenes/<站>.json` 里的小节是三到六个画面，出处写在场景文件自己的 `sources` 里；页面上是一句话和一张单子“沙盘上看的几处”（数据规格“正文还没写的站的沙盘”“人物页和没有自己的沙盘的站摆什么”）。
2. 写 `stops/<站>.md`（正文）和 `stops/<站>.json`（小注、原文、图片、凭据、示例问题），图片文件放进 `images/`。
3. 把 `status` 改成 `complete`，运行 `npm run validate`，按列出的问题改到通过。
