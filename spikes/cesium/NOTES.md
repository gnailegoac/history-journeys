# CesiumJS 验证说明

引擎：CesiumJS 1.147.0（npm 包 `cesium`，Apache-2.0）。测量日期：2026-11-17。

## 先说结论

- 场景做出来了：地球到山谷连续、地形立体、轨迹贴地、地名、古今切换、自由操作、“回到这一站”都能用，全程没有用任何账号或密钥。
- **帧率目标无法在这台机器上验证。** 这台机器是没有显卡的云主机（显示适配器只有 Microsoft Basic Display Adapter），WebGL 实际跑在软件光栅器上：`ANGLE (Microsoft, Microsoft Basic Render Driver … Direct3D11)`。在这个条件下飞行平均 4.3 帧/秒，最慢的一帧在 7 到 9 秒之间，首个可用画面 10.8 秒。这些数字说明的是“软件渲染下 Cesium 很慢”，不能代表有显卡的电脑、平板和手机。要判断 C8，必须在有硬件加速的设备上重测。
- 三处是引擎本身的短板，换机器也不会消失：没有地名自动避让；入口脚本 gzip 后约 1 MB；没有现成的免密钥地形和自然底图，两样都得自己接。

## 怎样运行

```
cd spikes/cesium
npm install
npm run dev          # http://localhost:5412/
npm run build        # 生产构建到 dist/
npm run preview      # 用 5412 端口预览 dist/
```

实测脚本（先 `npx playwright install chromium`，并让 dev 或 preview 在 5412 端口运行；每个脚本都是无界面模式，自带不超过 5 分钟的强制超时）：

```
node tests/measure.mjs      # C8、C9、C10 → metrics.json、shots/globe.png、shots/flight-mid.png（需先 build）
node tests/shots.mjs        # 其余截图，C2、C5、C7 的检查 → checks.json
node tests/zoom.mjs         # C1：滚轮从地球缩到夔门 → shots/zoom-1..7.png、zoom.json
node tests/perf-probe.mjs   # 诊断：帧时间花在哪 → perf-probe.json
node tests/gpu-probe.mjs    # 只打印本机无界面浏览器拿到的 WebGL 渲染器
```

## 数据源与条款（C9）

整个页面只访问两个主机（`metrics.json` 的 `hostsContacted`）：本机和 `s3.amazonaws.com`。没有任何请求发往 Cesium ion。

| 用途 | 地址 | 条款 |
|---|---|---|
| 地形网格、自然底图（同一份数据） | `https://s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png` | AWS 开放数据登记页 `https://registry.opendata.aws/terrain-tiles/`：由 Mapzen（Linux 基金会项目）维护，注明“无需 AWS 账号”；许可一栏指向署名文档 `https://github.com/tilezen/joerd/blob/master/docs/attribution.md`。正式使用前要按该文档逐条署名（本次只核对了登记页，没有逐条核对署名文档）。 |
| 引擎 | npm `cesium@1.147.0` | Apache-2.0。默认的 “Cesium ion” 徽标已换成纯文字 “CesiumJS”，因为页面不使用 ion。 |
| 轨迹、站点、地名 | `spikes/shared/route.json` | 项目自有 |

没有使用 ArcGIS 高程服务、卫星影像和 world-atlas。

做法：`src/dem.ts` 把 Terrarium 瓦片解码成高程，一份数据两用——

- 地形：`CustomHeightmapTerrainProvider`，每块 65×65 个高程点，海面以下压平为 0。
- 底图：自定义影像图层，按高程着色加山体阴影（光源在西北），高程不大于 0 的画成海。
- 淡水：数据里没有水体掩膜，靠“这一小片是水平的”推断湖和大江。

## 各条目结论

地形夸张：**1.5 倍**（`scene.verticalExaggeration = 1.5`，网格、轨迹、地名一起抬高）。

| 编号 | 结论 | 证据与说明 |
|---|---|---|
| C1 地球到山谷连续 | 通过 | `tests/zoom.mjs` 用滚轮从 6500 km 一路缩到 3.4 km，在 2316 / 823 / 293 / 74 / 26 / 9.5 / 3.4 km 各截一张（`shots/zoom-1..7.png`，`zoom.json`），每张截图时瓦片都已加载完，没有换模式、没有黑屏。看过 zoom-3、zoom-5、zoom-7：26 km 和 293 km 清楚；3.4 km 时底图已经发虚、有台阶状色块，这是 30 米高程数据的极限，不是引擎问题。 |
| C2 真实地形立体 | 通过 | `shots/sanxia.png`（倾角 69.9°）：峡谷和两岸山体立起来，江面是谷底的一条平带。`shots/dayuling.png`（64.8°）：山岭和山间平地分明。`shots/huangzhou-close.png`（61.9°）：江是一条宽带，左下角是对岸的西山；但江面只有一部分被涂成蓝色，见“限制”。角度数值在 `checks.json`。 |
| C3 轨迹贴地 | 通过 | 轨迹用贴地折线（`clampToGround`）。`shots/globe.png` 从地球上看得见；`shots/sanxia.png`、`shots/dayuling.png` 里线顺着山坡起伏，翻过山脊后被山挡住，没有悬空。远处贴地的线在很斜的视角下会断成虚线（`shots/flight-mid.png` 上方）。 |
| C4 镜头飞行 | 部分通过 | 逻辑有了：镜头注视点沿轨迹折线（含途经点）移动，缓入缓出，设计时长 4 到 9 秒，飞行中升高视点。实测八段飞行时长 5.8 到 11.4 秒，其中一段 11.41 秒超过了 10 秒上限（最后一帧来得太晚）。本机软件渲染下平均 4.3 帧/秒，第一段（地球到眉山）9 秒里只画了 3 帧，看上去是跳的，谈不上平滑。徐州到汴京一段画了 50 帧，采样到的注视点离五个途经点最近 5 到 25 km；其余几段帧数太少，采样证据弱。有显卡时是否平滑，未验证。 |
| C5 地名 | 部分通过 | 地名贴在地面高度、始终朝向屏幕，中文正常（`shots/names-ancient.png`）；古今切换有效（`shots/names-modern.png`，`checks.json` 的 `namesModeAfterSwitch`）。200 km 以内的地名不做地形遮挡测试，更远的交给地形和地平线去挡。**缺陷**：今名模式下“黄冈市黄州区”和“东坡旧址”叠在一起，Cesium 没有地名避让。另外没有专门找一个“站点在山脊背后”的视角来验证不被遮挡。 |
| C6 自然底图 | 通过 | 底图完全由高程数据画出，只有高程着色、山体阴影、海和部分淡水，没有道路、城市、国界和外文地名（看过全部截图）。左下角有一行英文的数据署名链接（“CesiumJS Data attribution”），属于署名，不是地图内容。 |
| C7 自由操作 | 通过 | `checks.json`：鼠标左键拖动（中心点移动）、Ctrl+左键拖动（倾角 61.9°→86.6°，方位 −15°→29.2°）、滚轮（距离 18→6.6 km）；触摸单指拖动、双指张开（18→13.5 km）、双指同向上推（倾角 61.9°→72.5°）；点“回到这一站”后中心点、倾角、方位、距离都回到预设值。触摸是通过 DevTools 协议发的真实触摸输入。 |
| C8 性能 | 部分通过 | 数字都是实测（`metrics.json`），但两个暂定指标在本机都没达到，而且帧率指标要求的“硬件加速”条件本机不具备。见下表。 |
| C9 无账号无密钥 | 通过 | 见上节。请求失败数 0，页面报错 0。 |
| C10 体积 | 已报告 | JS 3,938,437 字节，gzip 后 1,040,384 字节；CSS 2,614 字节，gzip 后 901 字节。另外引擎要求随站点部署一个静态目录 `dist/cesiumStatic`（7,043,231 字节，342 个文件），按需加载；整段巡览实际取了 21 个文件、285,154 字节（工作线程内部发出的请求可能没计入）。 |

### C8 实测数字

条件：视口 1440×900；Playwright 1.65.0 无界面 Chromium，参数 `--use-angle=d3d11 --enable-gpu --ignore-gpu-blocklist`；生产构建经 `vite preview` 提供，浏览器缓存为空；16 核 Xeon 8488C 云主机，**无显卡，软件渲染**；同一台机器上可能同时有另一组浏览器测试在跑。

| 项目 | 数值 |
|---|---|
| WebGL 渲染器 | `ANGLE (Microsoft, Microsoft Basic Render Driver (0x0000008C) Direct3D11 vs_5_0 ps_5_0, D3D11)` |
| 首个可用画面（打开页面到 `ready`） | 10,846 ms（暂定指标 5 秒：本机未达到） |
| 飞行平均帧率（八段飞行的动画部分） | 4.3 帧/秒 |
| 飞行最低帧率（最慢一帧的倒数） | 0.1 帧/秒（记录时保留一位小数；那一帧出现在第一段飞行里，9 秒只画了 3 帧） |
| 整段巡览的瓦片请求 | 1,093 个，44,131,900 字节 |
| 整段巡览传输总量（瓦片＋引擎静态文件＋页面） | 45,461,103 字节 |
| 首个可用画面之前的瓦片请求 | 43 个，4,216,129 字节 |

`perf-probe.json` 是为了弄清时间花在哪做的诊断（同样是软件渲染，样本少，只看量级）：夔门视角静止时默认设置 1.3 帧/秒，画 126 块地形瓦片；把地形精度放粗一倍（屏幕误差 4）后瓦片减到 62 块；汴京到黄州一段飞行，默认 6 到 7 帧/秒，分辨率降到四分之一后 13.7 帧/秒。卡顿期间页面主线程仍能每 200 毫秒应答一次查询，据此推断停顿主要在软件光栅化一侧，不在脚本一侧——这是推断，没有用性能分析工具证实。

## 限制

1. **没有硬件加速的数据。** 上面已说。全尺寸的 Chromium（新无界面模式）在本机启动失败（`spawn UNKNOWN`），所以只测了 headless shell。
2. **地名不会自动避让。** 引擎不提供，站点密集处要自己写避让或手工定位置。
3. **淡水靠推断，不完整。** 黄州近景里江面只有一段是蓝的，边缘成块；三峡段的江完全没有被认成水。离远一些（18 到 25 km）黄州的江、杭州的西湖和钱塘江是完整的。极平的田地也可能被误认成水。正式做需要一份真正的水体数据。
4. **山体阴影在瓦片交界处有接缝**（`shots/zoom-3.png` 左上能看到方块边），因为每块瓦片各算各的阴影，不同层级的强度也不同。
5. **底图直接用原始高程瓦片，流量大。** 一趟八站 44 MB。正式做应当把自然底图预先渲染成小得多的图片瓦片自己托管，高程瓦片只给地形用。
6. **近于 8 km 时底图发虚**：高程数据约 30 米一格，底图最多取到 13 级。
7. **两极有洞（推断，未实测）。** 地形用的是 Web 墨卡托切片，纬度 85° 以外没有瓦片。初始视角看不到极点。
8. **海面以下压平成 0**，低于海平面的陆地会被画成海。
9. 飞行中途底图是模糊的（`shots/flight-mid.png`），瓦片加载跟不上；本机帧率低会放大这一点。
10. `resetView()` 是直接跳回预设镜头，没有做过渡。

## 这个引擎用于本项目的利弊

利：

- 真正的地球：从整个地球到几公里的山谷是同一个场景、同一套镜头，不需要切换投影或模式。
- 地形是引擎的核心功能：夸张倍数一行设置；贴地折线、贴地地名、对地形拾取都是现成的。
- 镜头自由度高：注视点、距离、倾角、方位可以逐帧设定，沿轨迹飞行约 60 行代码。
- 鼠标和触摸操作默认就有，实测都能用。
- 地形和底图的数据接口是开放的，可以接任意自备数据，不依赖 Cesium ion。

弊：

- 体积大：入口脚本 gzip 后约 1 MB，另带约 7 MB 的静态目录要一起部署。
- 重：近景一帧要画一百多块地形瓦片（每块 65×65 点）。平板和手机是否流畅是最大的未知数，本次没法回答。
- 没有地名避让，也没有矢量瓦片样式这类制图能力；“自然底图”要么自己画（本次做法），要么自己预制。
- 不用 ion 就没有现成的地形和底图，免密钥的开放数据要自己写接入代码（本次 `src/dem.ts` 约 250 行）并自己解决水体、接缝、流量问题。
- 类型声明有小缺口（`VERSION` 运行时有导出、声明里没有）；Vite 下要额外配置静态目录拷贝。

## 文件

- `src/main.ts`：场景、轨迹、地名、镜头、面板、`window.__spike`。
- `src/dem.ts`：高程瓦片的下载解码、地形、自然底图。
- `shots/`：`globe`、`sanxia`、`huangzhou-close`、`dayuling`、`stop-huangzhou`、`flight-mid`、`names-ancient`、`names-modern`，另有 `zoom-1..7`（C1）和 `after-user-zoom`（C7 滚轮之后）。`stop-huangzhou.png` 与 `names-ancient.png` 是同一画面。
- `metrics.json`、`checks.json`、`zoom.json`、`perf-probe.json`：实测原始记录。

`window.__spike` 在规定接口之外多了几项，供检查用：`terrainExaggeration`、`timings.readyMs`、`rangeKm()`、`lastFlight()`（最近一次飞行动画的时长和帧率）、`widget`（Cesium 实例）。`fps().min` 的定义是“1000 除以最长的一帧间隔”。
