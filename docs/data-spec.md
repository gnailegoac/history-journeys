## 正文怎么写

正文是受限的 Markdown，只有三种写法：

- `## 小节标题`：正文必须从一个小节标题开始。
- 段落：段与段之间空一行。
- `> ` 开头的引用行：引用的原文句子，一行一句。

正文用“我”自述，只写他当时看到和知道的事。年纪：近代以前的中国人物用虚岁，并在文字里写明“虚岁”。不写别的格式（加粗、链接、列表、图片都不用）。图片和原文放在 `<站>.json` 里，用 `section` 指明跟在哪一小节后面。

## 场景数据：沙盘上摆什么

每一站的沙盘由两个文件定下来。场景文件（`scenes/<站>.json`）写沙盘的范围、地形怎么修整、水、摆什么东西、每一小节镜头看哪里。地形文件（`scenes/<站>.terrain.bin`）是这块地方今天的高程网格。机器可读的形式是 `src/domain/scene.ts`。

还没有场景文件的站，沙盘栏不摆沙盘，先放人物页的那张定格图。

每座沙盘动手之前，先写一份考证记录，放在 `docs/research/`（徐州的是 `xuzhou-scene.md`）：逐项写史料怎么说、今天的位置、结论、还没弄清的。场景文件里每一处的 `basis` 是这份记录的摘要。两边对不上时，先改记录。

### 通用的写法

- **坐标**都写 `[经度, 纬度]`，十进制度。
- **高度**都写真实的米（海拔），不用自己乘夸大的倍数，程序去乘。要留意：平地经过整理以后都在 `plainBaseM` 这个数上下（徐州是 40 米），不再是今天的海拔。城里的地面、水位、堤顶都比着它写：比平地高 1.2 米，就写 41.2。
- **小节**用正文里的小节标题来指，和原文、图片、凭据的做法一样。
- **id**：带 `id` 的东西，id 在整个场景文件里不能重复。`frame`、`terrain`、`recipe`、`levels`、`banks` 这五个词另有用处，不能当 id。
- **查得比别的文件严**：不认识的字段、写错的参数名都通不过。这是为了防一类错：把 `from` 错写成 `form`，程序会当成“一直有”，黄楼就会在大水那几节出现在东门上。

### 类别和依据

摆上沙盘的东西分五类（见 `overall-design.md`“分清真的和示意的”）：

| `class` | 类别 | 是什么 |
|---|---|---|
| `real` | 真的 | 山的位置和形状，来自今天的高程数据 |
| `today` | 今天的位置 | 今天还找得到的地点，不一定是当时的原处 |
| `text` | 按史料摆的 | 正文或史料说了在哪，细节说不准 |
| `schematic` | 示意的 | 没有可靠依据 |
| `dressing` | 点缀 | 只为让人看出这是城、是村、是岸 |

全程沙盘上另有一样记号（小像），不在这五类里，见“全程沙盘的场景数据·小像”。

下面这些都要写类别和依据：地形，整理的办法，每一处修整，水位，河岸的规矩，每条河和壕，急滩，水漫不进去的地方，地名点，每样摆件，每条点缀规则，每个远处。写法是同一组字段：

| 字段 | 含义 |
|---|---|
| `class` | 五类之一 |
| `basis` | 依据：为什么这样摆，一两句话 |
| `sourceIds` | 出处：这一站 `stops/<站>.json` 的 `sources` 里的 id。真的、今天的位置、按史料摆的，至少写一个。正文还没写的站没有那个文件，出处写在场景文件自己的 `sources` 里（见下面“正文还没写的站的沙盘”） |
| `unsure` | 可以不写。这样东西里说不准的部分 |
| `note` | 可以不写。给读者看的一句话。哪一节的 `explain` 点到了这样东西，那一节点“说明”展开的几句话里就有它；没有哪一节点到，这句话读者看不到 |

**一样东西一半有依据、一半没有，怎么归类。** 按有依据的那部分定类别，说不准的写进 `unsure`。黄楼是例子：在东门上、临着泗水、墙刷黄土，有五家当时的文字，类别是 `text`；楼有几层、多高、木头是什么颜色、在东墙的哪一点没有记载，`unsure` 写“层数、高矮、木头的颜色和它在东墙上的位置”。`unsure` 要写成能接在“黄楼的”后面的一个词组，程序会把它拼成“黄楼的层数、高矮、木头的颜色和它在东墙上的位置是示意”。不能是半句话：“在南墙的哪一点”“搭在哪一段城墙”接在“南门的”“棚子的”后面读不通，要写成“位置（在南墙的哪一点）”“位置（搭在哪一段城墙）”；末尾不带标点（规则 12 查这两样）。不用“线位”这样的行话，写“路线”。整样东西都没有依据的（城墙的位置），类别直接写 `schematic`。

**题签自己不写类别。** 题签必须指着一样东西（`of`），类别和依据跟着那样东西走。只有名字、没有模型的地方（云龙山、黄茅冈）先登记成地名点，题签再指它。

**用了谁的数据要写出来。** `credits` 里一条写一家：地形用的高程数据，借了今天地图上哪条河的线。页面上“沙盘上的东西”一栏的末尾照着印。

### 场景文件里有什么

按下面的顺序写，后面的要用到前面的：

1. **范围**（`frame`）和**地形**（`terrain`）：沙盘裁哪一块，平地怎么整理，哪几处另外修整。
2. **水**（`water`）：水位，河岸的规矩，河和壕，急滩，水漫不进去的地方。
3. **地名点**（`places`）、**摆件**（`things`）、**点缀**（`dressing`）。
4. **题签**（`strips`）和**远处**（`far`）。
5. **小节**（`sections`）：正文每个小节一项，写镜头、水位、摆哪几条题签、旁边的说明先讲什么。

另外有四样：`stopId`（哪一站）、`style`（时代样式，苏轼用 `song-qinglv`）、`credits`、`notDrawn`（史料里有、沙盘上故意不画的东西）。正文还没写的站多一样：`sources`（出处）。

**正文还没写的站的沙盘**（2026-11-23 加的；眉州是头一座）。沙盘可以比正文先做好：站在 `figure.json` 里还是 `outline`，`stops/` 里没有它的两个文件（规则 3 不变），`scenes/<站>.json` 照样可以有。这样的场景文件和别的站点沙盘只有三处不一样：

- **出处写在场景文件自己的 `sources` 里**，写法和 `stops/<站>.json` 的 `sources` 一样（`id`、`basis`、`cite`；`basis` 是 `own-words`、`record`、`later` 之一），依据里的 `sourceIds` 指的就是它们。一站的出处只放一处：`outline` 的站，场景文件必须有 `sources`；`complete` 的站，场景文件不能有 `sources`（规则 12）。
- **小节是三到六个画面**（规则 14）。没有正文可对，`heading` 就是这一个画面的名字（眉州：眉州、纱縠行的家、正月上蟆颐山、老翁泉），`date`、`line`、镜头、题签、`explain` 的写法都不变；`when` 里写的还是这些名字。每一个画面的字要自己站得住：没有正文替它交代，题记说的就是画面上看得见的。
- 先画好的地面、每一小节的定格图照旧要有（规则 17、18），做出来以前名字写在 `tests/support/pendingTables.ts` 里（眉州的这两样 2026-11-24 做好了，名字拿掉了）。

**正文写好的那一天**把站改成 `complete`，校验会一直红到下面两件事做完：场景的小节和正文的小节一一对上（规则 14）——正文的每个小节接过一个画面的镜头、题签和 `explain`，两个小节可以用同一个画面的镜头，题记各写各的，`when` 里的名字跟着改，定格图重拍（清单里写着小节）；`sources` 原样挪进 `stops/<站>.json`，id 不变（规则 12）。所以不用另立一条“画面的名字不能和以后正文的小节标题重了”的规则。

页面在这样的站上做什么（正文那一栏里的一句话、单子“沙盘上看的几处”、按一行沙盘换到那一处），写在后面“人物页和没有自己的沙盘的站摆什么”里。画面的名字、年份、题记原样印在那张单子上，比沙盘栏的题记那一条多一个地方看得到。

### 范围（frame）

| 字段 | 含义 |
|---|---|
| `center` | 沙盘的原点。程序以它为原点把经纬度换成米（沙盘只有十几公里，按原点的纬度换算就够准） |
| `westM` `eastM` `northM` `southM` | 从原点到西、东、北、南四条边各多少米 |
| `datumM` | 这个海拔是沙盘上平的桌面，一般和 `plainBaseM` 一样 |
| `relief` | 山的高度夸大多少。站点沙盘只有一种写法：`{ "kind": "uniform", "times": 6 }` 是统一夸大 6 倍 |

### 地形（terrain）

| 字段 | 含义 |
|---|---|
| `file` | 地形文件的名字。文件里是今天的高程网格：16 位整数（低位在前），单位分米，第 0 行最北，第 0 列最西，逐行存 |
| `cols` `rows` | 网格多少列、多少行 |
| `west` `east` `south` `north` | 网格盖住的经纬度范围，要盖得住整块沙盘 |
| `recipe` | 整理的办法（见下） |
| `edits` | 一处一处的修整，按写的先后做 |

地形本身的类别说的是山，一般是 `real`。

**整理（recipe）。** 现在只有一种办法，`plain-and-hills`：平地抹平，摆到一个高度上下（今天比它低的地方是垫高，比它高的地方是压低）；山留着，但跟着矮了一截。

| 字段 | 含义 |
|---|---|
| `plainBelowM` | 今天海拔低于这个数的算平地 |
| `hillAboveM` | 高于这个数的算山，两个数之间慢慢过渡 |
| `plainBaseM` | 平地抹到这个海拔上下：今天比它低的垫高，比它高的压低 |
| `plainKeep` | 平地的起伏留几成，0.1 是一成 |
| `edgeTaperM` | 离沙盘边这么多米以内，山收低到平地，切面才齐整 |

山的位置留着，形状大体留着，但山是矮了的：照算法，整座山先跟着平地降 `plainBelowM − plainBaseM` 米（徐州是 7 米）；地面还要整个抹一遍，山顶被抹圆，又矮一截，窄的小山会抹得看不出来；离沙盘边 `edgeTaperM` 以内的山收低到平地。平地垫高了多少、山顶一共矮了多少、哪几座小山看不出来了、哪座山是在边上被收低的，都要在摆出来的地面上量过，如实写进 `basis`（“真的”这一类说的是山的位置和形状来自今天的高程数据，动过的地方要交代）。

`recipe` 的 `note` 必须写：每一节点“说明”展开的几句话里都有这一句。它要把方向说对：平地是抹平的，有垫高也有压低；山跟着矮了。不要笼统写“压低”。

**修整（edits）。** 两种：

| `op` | 做什么 | 字段 |
|---|---|---|
| `level` | 把一块地方压成、垫到或压到一个高度 | `area`（一圈闭合的线）或 `inside`（一道城墙的 id，指城墙里面），二选一；`mode`；`toM`；`featherM`（往外多少米以内慢慢过渡） |
| `mound` | 垫一个土丘 | `at`；`addM`（中心垫高多少）；`innerM`（这个半径以内垫足）；`outerM`（到这里减到零） |

`mode` 有三种：`set` 是整块变成 `toM`；`raise` 是低于它的垫上来，高的不动；`lower` 是高于它的压下去，低的不动。每一处修整都有 `id` 和 `name`。闭合的线不用把第一点在最后再写一遍。

写了 `area` 的 `raise` 垫出来的是一块平地，不是山：程序上色、种树的时候把垫高的那一截减掉，所以垫高的地面和四周的平地一个颜色，上面照样画田，不长山上的树，只是高出一截，四边是缓坡。要一座看着像山的小山，用 `mound`（徐州的戏马台）。垫出来的东西没有依据的，`basis` 里要说，还要写一句 `note`，列进用得着它的那一节的 `explain`（徐州城南垫高的地面，列在“住在城墙上”一节）。

程序做的先后是：整理，按先后做修整，挖河，最后把写了 `inside` 的那一处再压一遍（城里才是一块平地）。

### 水（water）

| 字段 | 含义 |
|---|---|
| `levels` | 水位。`values` 里是名字和海拔，必须有 `normal`（平时），别的名字自己起（`rising`、`flood`）。除了 `normal`，每一个水位都要有小节在用（规则 14）：最低的那个水位决定江底哪里画成沙、崖脚的石头摆在哪，留着一个哪一节也不用的水位会悄悄改了地面。`note` 必须写 |
| `banks` | 河岸的规矩，所有的河共用（见下） |
| `rivers` | 河和壕 |
| `rapids` | 乱石急滩。现在一座沙盘最多写一处 |
| `dry` | 水漫不进去的地方，各是一圈闭合的线 |
| `calmUnderPx` | 可以不写。一个门槛，单位是“900 像素高的画面上的像素”：最宽的一条河照这一帧的镜头不到这么宽，水面不画水纹；到它的一倍半，照常画；中间匀着过去（见下面“窄的河上不画水纹”）。要有至少一条河才能写。它不算进地面的记号（改它不用重画地面） |

**河岸的规矩（banks）。**

| 字段 | 含义 |
|---|---|
| `bankM` | 河两边的岸最高到这个海拔：高出来的压下去，低的不动。修整过的地方不受它管 |
| `bedM` | 河床比平时的水面低多少米 |
| `keepOffWallsM` | 河离城墙的线至少这么多米。河画宽了也不切进城墙；壕不受这一条管 |

**河和壕（rivers）。**

| 字段 | 含义 |
|---|---|
| `kind` | `river` 是河。`moat` 是壕：窄，只在画的宽度里挖，从水边往中线慢慢深下去（到中线才有河床那么深），不压两边的岸；岸边只留一道细的留白，田一直画到离它十几米的地方 |
| `line` | 中线，可以伸到沙盘外面 |
| `drawWidthM` | 沙盘上画多宽（米），比实际宽 |
| `crossings` | 可以不写。路或堤从这里跨过去，这里不挖 |

程序挖河的时候，河的中线先顺成一条圆滑的线，离写的折线最多差二十几米，岸边的宽窄还有几十米的出入；壕是人挖的，照写的折线走，拐角不抹圆。`crossings` 的每一点留出一个圆不挖，半径是画的宽度的一半加 25 米。地面是 20 米一格算的，壕又是从岸边往中线慢慢变深的：画得比 40 米还窄，水就浅得看不出来，会断成几截。

**急滩（rapids）**写 `river`（在哪条河上）、`at`、`lengthM`（多长）。

**窄的河上不画水纹（`calmUnderPx`，2026-11-24 加的；眉州和徐州用它）。** 水纹是横在画面上的一道一道白线，一道有二十到七十个页面像素长，不管河多宽。看整块沙盘的时候，几百米宽的河在画面上只有十几、二三十个像素，又是竖着流的，白线就从这一岸横到那一岸，一条河上十来道，像坝，也像桥。眉州的头一节就是这样（河宽 13 到 20 个像素；徐州“到徐州”的定格图上泗水也有几道，缘故一样）。这件事没有一条“照河多宽来定”的规矩可以只治眉州、不动徐州：两座沙盘上的河在画面上差不多宽，徐州的定格图又是照有水纹的样子拍的。所以是场景里的一个数：写了 `calmUnderPx`，程序每画一帧算一遍——这座沙盘上最宽的一条河（`rivers` 里 `drawWidthM` 最大的）照这一帧真的镜头（离对准的那一点多远、视角多大）在一幅 900 像素高的画面上合多少个像素——不到这个数，整片水面一道水纹也不画，岸边的留白照旧；到这个数的一倍半，照常画；中间水纹一团一团匀着少下去（着色器里“哪几团水纹留着”的那个门槛 `uDense` 从平常的数匀着升到 1），没有哪一帧是一下子变的。摆好的一节、从一节滑到另一节的一路上、读者自己把镜头推近拉远，用的都是这一条（2026-11-24 第三段改的：原来只在摆好一节的时候算一次，滑到头一节的路上白线一直在，到了才一下子没有）。水纹朝哪边、平常多密还是照小节的镜头定（`rippleFor`），只在一道水纹也不剩的那一帧换成要去的那一节的：换的时候看不见。

为什么照 900 像素高的画面算，不照这块沙盘栏上真的像素算：同一节的镜头在高的沙盘栏上河宽的像素多，在矮的上少，可画面是同一幅，只是放大缩小了。照真的像素算，分不开眉州的两节——头一节在 1600 像素高的沙盘栏上最宽的河有 61.7 个像素，“正月上蟆颐山”在 573 像素高的沙盘栏上只有 56.7 个——哪一个门槛都会让其中一种沙盘栏上的画面和定格图不一样（定格图是照 900 和 573 像素高拍的）。折到 900 像素高以后，同一节在哪种沙盘栏上都是同一个数：眉州的头一节是 31.9 到 34.7（沙盘栏窄得镜头要退远的时候小一点），“正月上蟆颐山”是 89.0，“纱縠行的家”158.7 到 254.4，“老翁泉”314.2。眉州写 48：头一节在 48 以下，不画；另外三节都在 72 以上，照常画；48 到 72 之间只有滑动的半路上和读者自己推拉镜头的时候才到（`tests/stage/meishan-figures.test.ts` 在 573 到 1600 像素高的二十几种沙盘栏上量着；`tests/stage/view.test.ts` 从真的沙盘上读水面的数：摆好的一节、滑到半路、滚轮推近）。不写这个字段，程序和原来一个数不差（黄州没有写）。徐州写 26（2026-11-24 眉州检查以后添的，治“到徐州”那一节泗水上的几道白杠）：照同一批沙盘栏量，“到徐州”是 9.3 到 21.9，另外六节最窄的是 44.2（“云龙山和百步洪”在又高又窄的沙盘栏上；电脑上最窄的是“要走了”，64.7）。48 在徐州分不开——“要走了”落在 48 到 72 之间，水纹会少一截；门槛要在 21.9 以上、一倍半在 44.2 以下，取 26：只有“到徐州”一节不画，别的六节和原来一个数不差，定格图也只重拍了这一节的两张（`tests/stage/xuzhou-figures.test.ts`）。这个字段不算进地面的记号（`src/stage/ground/key.ts`）：它不动地面的一个像素，改它只要重拍定格图。

**大水漫到哪里不用画。** 水面是一个平面：哪里的地面比这一节的水位低，哪里就有水。闭合的城墙里面和 `dry` 里的地方不进水。所以要改大水的范围，改的是地形的修整，不是另画一片水。贴在城墙外侧的土坡（见摆件的 `bank`，要写了 `on`），坡脚外面一直是水。

**修整压出来的宽水面**（2026-11-23 加的；黄州的大江是这样做的）。几百米、上千米宽的水面不用一条河的中线挖：用地形的修整把江底压到平时的水位以下，水面还是那一个平面，水位一节一节换，沙洲、滩和崖脚的石滩就自己露出来、没下去。规矩是：

- **修整把地面压到平时的水位以下的地方也是水。** 程序认得它（`src/stage/ground/fields.ts` 的 `openWater`）：岸边照河岸上色（留白、水底的淡花青、河边的草色），树、村子、房子不摆进去，船和水里的石头认得哪里是水、离岸多远。岸线是地面和平时的水位相交的那条线，不用另外画。
- 这一条只在“真有这样的地方”时才起作用：至少有一格地面比平时的水位低 0.25 米以上，而且在每条画出来的河的岸外 20 米以外。没有这样的地方（徐州），程序什么也不动，一个数也不差。徐州离这两个门槛有多远，`tests/stage/xuzhou-ground.test.ts` 记着。
- 画出来的窄水道不跟着变：半宽不到 100 米的河和壕，里面和岸外 20 米以内的格子还照它自己的岸上色（壕只留一道细边，没有河那样的留白和水纹）。一座沙盘上既有壕、又有修整压出来的宽水面时，壕还是壕（`tests/stage/ground.test.ts` 在小沙盘上查着）。
- 宽水面里照旧可以写河（`rivers`）：名字的题签要指着一条河，水名才是花青色。河的 `drawWidthM` 写在压低的江底里面，它自己不再挖什么。写在宽水面里的河，`drawWidthM` 写 200 米以上：比这窄的会被当成上一条说的窄水道，在宽水面中间留下一道窄水道的颜色，两边各有一条 20 米的“岸”（现在还没有校验查这一条；黄州的两条是 600 和 240）。
- **最低的水位露出来的地面是沙色。** 水位里最低的一个比平时低的时候（黄州的 `low`），比它高、平时又在水下的地面（滩、石滩）上的是沙色，不是水底的淡花青：水落下去以后，露出来的是一片沙滩，不是一片淡蓝。比最低的水位还低的地方照旧是水底的颜色。地面的颜色是先画好的一张，不跟着水位换，所以只有“哪一节也淹不到”和“最低的一节露出来”两种。最低的水位就是平时的水位时（徐州），和原来一样。
- 立体的地面是 59 米一格的，比 90 米窄的滩、汊在它上面靠不住，画的时候留意。

### 地名点（places）

只有名字、没有模型的地方：一座山、一片山坡。写 `id`、`name`、`at`，加上类别和依据。地名点可以不立题签，只是让镜头的 `mustShow` 有个点可指（徐州的“云龙山的南头”：写进“云龙山和百步洪”一节的 `mustShow`，整道山才都在画面里）；这样的地名点照样列在凭据里，依据里要说明它是做什么用的。

### 摆件（things）

| 字段 | 含义 |
|---|---|
| `id` `name` | `name` 是给读者看的名字，如“东南的堤” |
| `kind` | 用零件库里的哪一种（见下表） |
| `at` 或 `line` | 位置。一个点的写 `at`，一条线、一圈线的写 `line` |
| `facing` | 可以不写。正面朝哪边，0 朝北，顺时针。不写由程序定 |
| `on` | 摆在哪样东西上（它的 id）：城门在城墙上，楼在城门上，棚子在城墙顶上 |
| `params` | 可以不写。这种零件的参数 |
| `when` | 可以不写。什么时候有 |

**零件和参数。** 参数都可以不写，不写用零件库的默认。表里没有的参数通不过校验。模型的大小不在这里：模型都放大了，不按比例，多大由样式定。

| `kind` | 是什么 | 位置 | 可以摆在（`on`） | 参数 |
|---|---|---|---|---|
| `wall` | 城墙 | 一圈闭合的线，形状不限 | — | `face`：`earth` 夯土、`brick` 包砖；`parapet`：有没有垛口 |
| `gate` | 城门 | 一个点 | 城墙（必须写） | `face` 同上；`big`：门墩加大 |
| `tower` | 楼（城门楼、角楼） | 一个点 | 城门、城墙 | `storeys`：几层，1 或 2（写得再多也只造两层；摆在城墙上的角楼不看这个数）；`size`：`small`、`large`；`walls`：`plaster` 白墙、`yellow-wash` 刷黄土；`timber`：`red` 上红漆、`plain` 素的 |
| `pavilion` | 亭 | 一个点 | 城墙 | `roof`：`tile` 瓦、`thatch` 草 |
| `hall-group` | 一组院落（官署、寺） | 一个点 | — | `halls`：几进；`galleries`：有没有长廊；`enclosed`：有没有围墙；`terraced`：顺着山坡一级一级下来；`paleYard`：院子的地面画成浅色（见下面“浅色的院子”） |

| `bank` | 墙脚到水边的土坡 | 一条线 | 城墙（贴在外侧） | — |
| `timber-bank` | 木桩护岸 | 一条线 | — | — |
| `cliff` | 崖壁（一段石崖，连同崖顶） | 一条线：崖脚 | — | — |
| `earth-wall` | 一段矮土墙，不闭合 | 一条线 | — | `ruined`：塌了的（高高低低，隔几段缺一段）；`fence`：中间三分之一是篱笆，两头是土墙；`low`：只有一半高（水边的矮土堤） |

**什么时候有（when）。** 写的是小节标题，三种写法：

- `{ "from": "水退以后" }`：从这一节起有。
- `{ "until": "住在城墙上" }`：到这一节为止（含这一节）。`from` 和 `until` 可以一起写。
- `{ "only": ["住在城墙上"] }`：只在这几节有。

不写就是一直有。一样东西前后样子不同（徐州的东门，1078 年以后门墩加大、包了砖石），写成两样东西，`when` 前后接上。

城墙不能写 `when`，点缀里的路（`roads`）和田（`fields`）也不能：城里的平地、水漫不进去的范围、画在地上的路和田，程序只算一次，不跟着小节变。成片的民居和村子可以写，房子跟着小节有或没有，地上的街巷不变。

**几样零件摆出来的规矩。**

- 城门落在哪：程序把它挪到城墙线上离 `at` 最近的地方。城台有宽度，不能伸出这一面墙，所以离这一面墙的两头至少 86 米（`big` 的 100 米）；写得太靠墙角的会被挪开。模型、城里的大街、指着这座城门（或门上的楼）的题签，用的都是挪过以后的这一点。
- 城墙的墙角不是直角也行：角台做成一个斜的墩子，四个面各和一面墙平行。
- 城墙里面的一组院落占着一块地（两进的约 234 米宽、195 米深）：民居让开它；城门到城门的大街也不从它的围墙里穿过去，在围墙外 20 米停住，停在正面的那一头再接到大门口。
- 木桩护岸（`timber-bank`）：线写在哪，桩就立在哪。每根桩落在它脚下的地面、盖在地面上的土坡（`bank`）、平时的水面三样里最高的那个上面，不会埋在土坡里，也不会整根没在水里。要它是水边的一排桩，就把线写在土坡的水边上（徐州是离墙线 96 米）。
- 墙脚到水边的土坡（`bank`）是旧土的颜色，在平地和城墙之间；堤（`dike`）是新筑的土，亮一些。
- 崖壁（`cliff`）：线写的是崖脚，哪一边是山由程序看（线两边 45 米处哪边的地面高）。它是一个合起来的块，不是一面墙：崖面从崖脚（埋进地面 12）斜到崖顶的边（离崖脚 14 米，高度取山上 60 米处的地面），崖顶从这道边往山里铺 100 米，收进地形板下面，后面和两头各有一道裙边。这样做是因为地形板的网格 59 米一格，立不住陡坎：只摆一面墙的话，墙后面是一道沟。离线的两头 45 米以内崖慢慢矮下去，接进岸里。崖面是红褐色，崖脚一带深一些，中间有一道窄台；崖顶照这座山在那个高度本来的颜色上色，和后面的山接得上。崖不跟着镜头远近放大，也不分画质。四周 150 米以内不起云气（和单座的屋、亭一样）：云气的高度正好横在崖面上。
- 矮土墙（`earth-wall`）：顺着线的一道夯土矮墙，脚宽 14 米、顶宽 6 米、高 11（真的一米八，乘了山高夸大的 6 倍），切成 24 米上下的一段一段，每段落在自己脚下的地面上。它不是城墙（`wall`）：不闭合，不算一座城，里面没有“城里的地面”和街巷，水照样漫得进去，城门（`gate`）也不能摆在它上面。`ruined` 的每段只有三成半到全高，四段里缺一段；`fence` 的中间三分之一换成篱笆（木桩加编起来的矮篱，和单座的屋四周的那种一样）。`low` 的只有一半高（5.5）：黄州夏澳边的那道旧土堤原来和墙一样高，在近看的一节里立得同旁边的屋子一般高，所以减了一半。颜色是夯土色，比平地深一点。不跟着镜头远近放大。
- 单立的小门（`small-gate`）：两个夯土的门墩（宽 9、高 16，中间的口子宽 14 米），上面一根木过梁、一个小瓦顶；`facing` 是门朝哪边，路从两个门墩之间穿过去。不靠城墙，不跟着镜头远近放大。
- 浮桥（`pontoon-bridge`）：线的两个点是两岸的桥头，都要写在干地上，离同一条河的岸不到 60 米。校验照场景里写的数查一遍（规则 13：两个桥头各在同一条河的中线的一边，离中线在“画的宽度的一半减 30 米”到“加 90 米”之间——河岸画出来比写的宽窄有二三十米的出入；两个点不能是同一个点）；照地面量的那一遍（两头真的是干的、离岸不到 60 米）在 `tests/stage/scene-models.test.ts`，每一座沙盘的每一座浮桥都查。有水的一截是程序从地形板上读出来的：沿桥线每两米量一次，地形板低过平时的水面、那里的水也画得出来（地面比水面低 0.25 米以上）的算有水，取连着的最长的一截。船只摆在这一截里，一条挨一条横在水上（船身顺着水流，两头尖，没有篷和桅）；桥板在水上是平的，到了岸边顺着读者看得见的那块地（高程和地形板里低的那个，和别的脚一样）搭上去：桥头的顶面比那块地高 0.8（板厚 1.2，底面贴着地），往水边匀着升到水上桥板的高，中间地要是鼓起来就贴着地走——不埋进地里，也不悬在岸的上空；两头各立两根桩，立在那块地上。贴近了看，一条船占桥上 10 米（船宽 9 米、长 34 米）。镜头远了，十米宽的船在画面上只有两个像素，所以船造得大一些、少一些：这座桥在场的各节里镜头最近的一节写的距离，除以 480，比 10 米大就用它（眉州只在“正月上蟆颐山”一节有桥，镜头 12,000 米：五条船，一条宽 24 米、长 93 米，在电脑上是 5 × 19 个像素）。**读者把镜头推近，不能还是那五条大船**（2026-11-24 第三段）：桥造三套——贴近的（十米一条，眉州 14 条）、中间的（两头的几何平均，眉州 9 条、船宽 14 米）、远看的（上面那一套）——折算过的远近到了“最近的一节写的距离”的 32%、50%（眉州 3,840 米、6,000 米）换。三套都只造一遍，各并成自己的网格，换的时候只是开关（零件库的 `Bucket.steps`，`src/stage/three/kit/assemble.ts`）；正在界线上来回的时候不来回换：读者自己推近拉远时，出了显着的那一套的那一段再多走 12% 才换，所以那时候远近落在界线上下 12% 里显哪一套要看镜头是从哪边来的。程序摆的画面——摆好的一节、换小节滑动的一路上、“回到这一处”——只看远近：同一个摆好的画面在哪种沙盘栏上、从哪一节来，都是同一套。“正月上蟆颐山”在 573 到 1600 像素高的沙盘栏上摆好的远近都在 6,750 米以外，离 6,000 × 1.12 还有余地：摆好的这一节在哪种沙盘栏上都是远看的一套，和定格图一样。远看的一套本来就差不多十米一条的（桥在一节贴近的画面里）只造一套。船总是一条挨一条，桥不往两岸外面长。它是照平时的水位造的，不跟着水位走，也不跟着镜头远近放大：所以只能摆在水位是 `normal` 的小节里（规则 13），别的小节用 `when` 让开。木头的颜色，桥板是浅色的木板。
- 池（`pool`）：一片平的十边形水面（样式里平时的水色，边上淡一点），四周一圈池沿（小的宽 2.5 米，大的 3.5 米）。它不是沙盘上那一片水面：不看水位，城墙里面、山坡上都可以有。水面比池沿脚下“读者看得见的那块地”最高的一处高 1——看得见的那块地是高程和地形板里低的那个：地形板 59 米一格，每个顶点取四周最低的地面，坡上比高程低好几米——所以地形板盖不住它；池沿的外面往下接到那块地以下 3，坡上的池，下坡那一面就是一道砌起来的沿（眉州的老翁泉露出来 7.9）。池子里面的地形板（圆周上四十处、里面两圈各十二处）也都在水面以下。`stone` 的池沿是浅色的石头，比水面高 1.6；不写是旧土色，高 0.4。挨着一座单座的屋、亭、坟的池跟着它整组放大（眉州家里的小池跟着屋子，老翁泉跟着坟）。**跟着一组放大的池，水面不落在地面那一层里**（2026-11-24 第三段）：池绕着水面的中心放大、从主角的脚摊开；摊开的一路上取十四处，每一处要水面比它脚下放大以后那一圈里最高的地形板高出“1 × 这时候放大的倍数”，折成“摊开到头时水面多高”，取最高的——放大到几倍，水面离地也高到几倍（眉州家里的小池在头一节放大 4.3 倍，水面比地形板高 4.3；原来放大到头时正好落在地面上，和地面抢着画）。坡上的池摊开以后宁可池沿高一点，不让地盖住水。**一户人家园子里的池（跟着一座屋的）小一号**：半径和池沿都乘 0.72（连池沿半径 8.3 米）——篱笆里屋前的院子只有 19 米深，平常的小池连池沿 23 米，摆不进去；它在屋的那一块地里，不另占一块。不分画质。
- 坟（`grave-mound`）：一座圆的土冢，十二面，没有碑、没有墙、没有石头。最下面一圈的每个顶点落在它自己脚下读者看得见的那块地上（顺着坡），冢顶比这一圈的平均高出 17（小的 10.5），下面一道裙边再往下埋 3。浅土色，顶上草色。**坟和地上的亭是一类，远了跟着放大**（2026-11-24 第三段）：坟自己是一组的主角，它四周三十米（放大到头是一百一十四米）里排在它后面的摆件——挨着的小坟、泉、泉上的亭——跟着它整组放大、从它的脚摊开，远近怎么变，几样东西的位置都是原来的样子。所以一处墓地要把大的那座坟写在最前面。眉州的两座坟比头一稿大了三成（原来半径 22、14 米）：“老翁泉”一节在电脑上大的一座 41 个像素、小的 26 个，竖着拿的平板上（这一类在那里放大 1.19 倍）31 和 19 个。
- 城墙里面一户带篱笆的人家、一口池各占一块地（2026-11-24 加的）：带篱笆的单座的屋（`house` 写了 `fence`，不在城墙顶上）从屋子往四边各 45 米，池是它的半径再加 15 米。这一块里大街不过（和院落一样，在外面 20 米停住，停在正面的那一头再接到正面的正中），小巷也不过（切掉穿过去的那一截，剩下不到 40 米的一截不要），成片的民居离它 26 米以上。没有这样的东西的城（徐州），街巷和民居一个数也不变。屋旁的树、竹要自己写在这块地里（眉州的竹写在屋子北面的一块 `area` 里）。**这一户人家远了放大，它的这一块地跟着大**（2026-11-24 第三段）：单座的屋从四千米起放大，到头是 4.3 倍，比民居（一万二千米起）早得多。民居这一边：近看时就在“这块地放大到头时占的那一块”里的民居，远了一座不留，而且排在最后头——民居一开始去掉，它们一起先走；放大到头时留着的民居让开的是放大以后的那一块（和院落一样）。剩下的一小段：折算过的远近七千到一万二千多米之间，这一户人家已经放大到两三倍，挨着它的民居还没有去掉（到一万二千米正缩到四成），会碰着它的篱笆角——这一段只在读者自己推拉镜头的半路上和“正月上蟆颐山”那样的远近上到，那一节里它在画面的最下边。跟着屋摊开的东西（家里的小池、屋旁一个点周围的几棵树）要写在篱笆里外的那一圈里：摊开到头是 4.3 倍远，写远了会摊到城墙上去（眉州园子里的树 `radiusM` 写 32，放大的一路上离墙身最近 66 米；`tests/stage/meishan-figures.test.ts` 量着）。
- 浅色的院子（`hall-group` 的 `paleYard`）：这组院落围墙里面的地面在“先画好的地面”上画成浅色（样式里的 `court`），不是另铺一块板。只给正文里写到“院子很亮”的那一处用（黄州的承天寺：“庭下如积水空明”），依据里要写明这是示意。院落顺着山坡的（`terraced`）不要写。写了 `when` 的院落、没有围墙的院落（`enclosed: false`）也不能写：这块浅色画在先画好的地面上，那张地面只有一张，哪一节都在——院落不在的小节里，空地上会剩一块浅色；它又是“围墙里面的地面”，没有围墙就没有边（同城墙、路、田不写 `when` 是一个道理）。

**不写参数时的默认。** 城墙：夯土，有垛口。城门：墙面同它的城墙，门墩不加大。楼：小的；小的一层，大的两层；白墙，红漆。亭：瓦顶。一组院落：两进，有长廊，有围墙，不顺坡。单座的屋：草顶，没有篱笆。矮土墙：整的，没有篱笆。堤：不靠城墙的，堤顶比堤线上最高的地面高 4 米；贴在城墙里侧的，比城里的地面高出一截，多少由样式定。

### 点缀（dressing）

写的是规则（哪一片、多少、多密），不是一座一座地摆。类别只能是 `dressing` 或 `text`。

| 字段 | 含义 |
|---|---|
| `id` `name` `kind` | `kind` 见下表 |
| `inside` `area` `line` `at` | 摆在哪，最多写一个：一道城墙里面（它的 id）、一块地方、沿一条线、一个点周围。都不写就是整块沙盘，程序按样式的规矩摆（树在山上，田在平地） |
| `except` | 只有树的规则可以写：这几处不种。写的是地形修整的 id（见下面“这里不种”） |
| `exceptAreas` | 只有树的规则可以写：这几圈里不种。直接写几圈闭合的线（见下面“这几圈里不种”） |
| `params` `when` | 同摆件 |

| `kind` | 是什么 | 可以摆在 | 参数 |
|---|---|---|---|
| `houses` | 成片的民居 | 城墙里面、一块地方 | `density`：多密，1 是平常；`lanes`：排成街巷；`seed` |
| `villages` | 村子 | 整块沙盘、一块地方 | `count`：几个；`seed` |
| `fields` | 田 | 整块沙盘、一块地方 | `seed`；`green`：青苗（见下面“青苗的田”） |
| `trees` | 树 | 整块沙盘、一块地方、沿一条线、一个点周围 | `type`：`mixed` 杂树、`pine` 松、`willow` 柳、`fruit` 果树、`bamboo` 竹、`cypress` 柏；`density`；`radiusM`；`seed`；`young`：刚种下几年的小松树（见下面“小松树”） |
| `boats` | 船 | 沿一条线、一个点周围 | `type`：`cargo` 货船、`small` 小船；`count`；`moored`：系着不动；`radiusM`；`seed` |
| `rocks` | 露着的石头 | 一个点周围 | `type`：`grey`、`pale`、`shore`；`count`；`radiusM`；`seed` |
| `roads` | 路 | 沿一条线；写城墙的 `inside` 是城里从城门到城门的街 | `type`：`street` 街、`road` 城外的路、`wide` 城外的大路（见下面“大路”） |

`seed` 是随机数的种子：写同一个数，每次摆出来一样。`radiusM` 是“一个点周围”多大的半径。

不写参数时的默认：民居密度 1，不排街巷（城里要有小巷，民居的规则写 `lanes: true`；要有城门到城门的大街，另写一条 `inside` 这道城墙的 `roads`）。村子的个数按沙盘的大小定，大约每 6.7 平方公里一个。树是杂树，密度 1，半径 150 米。船是货船，系着不动，沿一条线 24 条、一个点周围 4 条，半径 150 米。系着的船沿一条线摆时，松松地分成几组：三到六条一组，组和组之间至少空 70 米，各组的船头朝向不一样，城门前面留出空；线上这样摆不下 `count` 那么多条，就少摆（徐州的东墙外写 30 条，摆得下 22 条）。石头是灰的，54 块，半径 260 米；浅色的 46 块，半径 150 米。

**竹和柏。** 都是细高的苔点，没有另外的形状：竹宽 7 到 10 米、高是宽的 1.9 到 2.4 倍，三到五竿一丛（丛里相距 6 米以内），淡绿；柏宽 6 到 8 米、高是宽的 3 到 3.6 倍，墨绿。写在一块地方里的，一处一丛（竹）或一棵（柏）；写在一个点周围的，种的也是这种细高的苔点（别的树在一个点周围种的是细做的一棵），镜头贴近了也不换。院落里的竹、柏跟着那一组院落放大。**位置只能写一块地方（`area`）或者一个点周围（`at`）**（规则 13）：沿一条线、摆满整块沙盘时，程序种出来的是平常的树涂上竹或柏的颜色，不是细高的苔点；点落在一座单独的屋子（`house`）的地块里时，种的也是屋旁那种细做的树，竹和柏不要这样写。

**小松树**（`trees` 的 `young: true`，2026-11-24 加的；眉州墓地四周的松）。只给松（`type: pine`），位置只能写一块地方（`area`）或者一个点周围（`at`）（规则 13）。种在哪、种多少和不写时一样，只是每一棵只有平常的一半大，矮胖一点（苔点宽 6.5 到 11.5 米，高是宽的九成）：刚种下几年的松，不该和山上的老树一般高。

**大路**（`roads` 的 `type: wide`，2026-11-24 加的；眉州东门到渡口的路）。城外的路（`road`）在地面上是一道九到二十四米宽、比平地深十几级的赭色细线，看整条路的画面上只有五六个像素宽，不指给人看就找不到。小节里要人顺着走的那条路写 `wide`：宽一倍半，颜色上到九成（平常的路是六成），在眉州“正月上蟆颐山”的画面上有十个像素宽，比两旁的平地深二十级。颜色还是样式里那一种路的颜色，没有另添。别的路不写它：处处都是大路，就又分不出哪一条要紧。陡坡上不要写（眉州上蟆颐山的那一段还是 `road`）：地面是贴在地形板上的，陡坡上一道宽带子成了一条直上直下的坡道。

**崖脚的石头**（`rocks` 的 `type: shore`）。摆在一个点周围，只留落在这一带里的：地面比最低的水位高 0.2 米以上、比平时的水位低 1.5 米以上。所以水落的小节它们露着，平时和高水时都在水下，不用写 `when`。石头是扁的（宽 16 到 41、深 13 到 30、高 4.5 到 8），脚埋在地面和地形板里低的那个下面 1；三种石头的颜色（红褐、灰褐、深褐）轮着上，不用黄的和浅的（小的时候看着像花瓣）。不写 `count` 是 20 块，半径 240 米。最大的一块放大到头（1.5 倍）时，顶还在平时的水面以下。场景里要有一个比平时低 1.7 米以上的水位（规则 13）：不然那一带是空的，一块也摆不出来。

**青苗的田**（`fields` 的 `green: true`）。只能写在一块地方里（`area`）。这一块整块画成草绿色（样式里的 `sprout`），田块之间留细细的一道底色；不看“是不是平地”，也不轮着上那三种浅色。给正文里写到庄稼长出来了的那一块田用（黄州的东坡：“地里一片青”），四周的平地还是茶色，一眼分得出。

**这几圈里不种（`exceptAreas`，2026-11-24 第三段加的）。** 也只有树的规则可以写：直接写出来的几圈闭合的线（每圈至少三个点），这条规则种下的树落在哪一圈里面的都不要；别的树种在哪不跟着变。它和下面的 `except` 是一回事，只是圈不借地形的修整：眉州整块沙盘的那条树的规则把墓地四周圈了出来（小松树那一片的外沿，离两座坟 260 到 340 米），平常的树——苔点有三四十米宽，比坟还大——不长到坟的跟前，那一片里只有小松树。写了别的点缀、哪一圈不到三个点，通不过校验（规则 13）。它算进地面的记号（和 `except` 一样：点缀那一块整块算）。

**这里不种（`except`）。** 只有树的规则可以写：几处地形修整的 id（`terrain.edits` 里 `level` 一类、自己带着一圈范围 `area` 的），这条规则种下的树落在那几处的范围里的都不要；别的树种在哪不跟着变。给整块沙盘的那条树的规则用：黄州的江是修整压出来的，江心的长洲平时露着、高水时淹掉，洲上、敞开的水面上不该有树（黄州写的是江底、湖荡、门前的滩和夏澳四处）。不写就是哪里都可以种。写了别的点缀、写了不存在的 id、写了没有 `area` 的修整，通不过校验（规则 13）。

**散着摆的民居（不写 `lanes` 的 `houses`）远了留哪几座。** 屋子远了放大、去掉一些，留下的不能压在一起。散着摆的屋子各有各的朝向（差着十来度），比的时候各照自己真的朝向，算出它在沙盘的东西、南北两个方向上占多宽，两个方向上都隔不开才算碰到。沿巷子排的（徐州）还是原来的比法。

**按家分块的零件。** `cliff`、`earth-wall`、`small-gate`、`shore`、`bamboo`、`cypress`、`pontoon-bridge`、`pool`、`grave-mound` 这几样只有一部分沙盘用得着，它们的程序不在沙盘程序里，按“家”分成几小块（现在三家：石和土——`cliff`、`earth-wall`、`small-gate`、`shore`；草木——`bamboo`、`cypress`；小工程——`pontoon-bridge`、`pool`、`grave-mound`），登记在 `src/stage/families.ts`：一家叫什么、管哪几种、从哪里取。场景里写到了哪一家的东西，造模型以前才下载那一家；一样也没写到的沙盘（徐州、全程沙盘）不下载。以后的沙盘添新零件，在登记表里添一行、添一家的文件；`tests/build/dist-size.test.ts` 对每一座沙盘查“沙盘程序加上它要下载的几家”不超过上限。

### 题签（strips）和远处（far）

**题签。**

| 字段 | 含义 |
|---|---|
| `text` | 当时的名字。只能是汉字，一到七个，不带标点、数字和空格 |
| `modern` | 可以不写。今天的名字，同样的限制。当时和今天叫法一样、或者今天没有对应的名字，就不写 |
| `of` | 指着哪样东西：摆件、点缀、地名点、河、急滩、远处的 id。必须写 |
| `at` | 指在那样东西的哪一点。那样东西只有一个点时不用写；是一条线、一片地方时必须写，而且要落在它上面 |
| `side` | 可以不写。题签最好摆在那一点的哪一边：`above`、`below`、`left`、`right` |
| `lean` | 可以不写，写了就要同 `side` 一起写。沿着那一边往哪一头偏一格，题签就斜着站在那一点的一角上：`side` 是 `above`、`below` 时写 `left` 或 `right`，是 `left`、`right` 时写 `above` 或 `below`。指着远处的题签不能写 |

指着河或急滩的题签是水名，字用靛青。题签只给正文里提到的东西立；正文没有提到的东西可以摆模型，但不立题签。（这一条校验查不了，靠审阅的人对着正文看。）

**远处。** 正文提到、却在沙盘外面的地方（徐州的白土镇）。写 `id`、`name`、`at`（它的坐标）、`gloss`（括注，如“今安徽萧县白土镇”），加上类别和依据。给它立一条题签（题签的 `of` 写它的 id），程序把题签摆在沙盘边上朝着它的那一点，并在沙盘旁边印“白土镇：往西南约 24 公里（今安徽萧县白土镇）”。方向和距离是程序按坐标算的，不用写。沙盘栏窄的时候，这句话接在题记后面，两样合起来只有两行的地方，所以带着远处的小节题记要短一些（规则 14）。

方向和距离都从沙盘的原点（`center`）算。方向用东、南、西、北和东南、西南、东北、西北八个词；距离不到 100 公里取整公里，100 公里以上取最近的 5 公里（徐州到商丘印“往西约 145 公里”）。

**只在题记下面说、不立题签的远处（小节的 `farLine`）。** 可以不写。平常，一节要说到远处，就给它立一条题签，镜头得把题签站的那一段沙盘边留在画面里。有一种时候做不到：这一节要近看一样东西，远处的方向又只是当时人的一句话（黄州“寒食，沙湖”：要近看春水到了临皋亭的门口，沙湖只知道“东南三十里”）。这时小节写 `farLine`：远处的 id 的名单。写在里面的远处，这一节的题记下面照样印它那一句（“沙湖：往东南约三十里（今天是哪里没有查到）”），沙盘上不立它的题签，镜头也不用管它；它不在沙盘上，所以不算进“这一节沙盘上哪些是示意”的那个数里，要交代它，就在 `explain` 里点它，它的 `note` 印在展开的说明里。管得很紧（规则 14）：名单里只能是写了 `inHisWords` 的远处——坐标确实的远处（汴京、汝州、白土镇）还是只能立题签，题签的规矩一条不松；同一节里它不能又有题签；不能写两遍。现在整个 `content/` 里只有黄州这一节的沙湖用了它，`tests/stage/scene-cameras.test.ts` 钉着：再有一处要用，先改那条测试。

**照他的话写的远处（`inHisWords`）。** 可以不写。只知道当时人说的方向和里数、今天在哪没有查到的地方（黄州的沙湖：“黄州东南三十里为沙湖”），写 `inHisWords`：一句“往哪边约多少里”，只能是汉字，2 到 12 个（如“往东南约三十里”）。写了，沙盘旁边印的就是这一句（后面照样接括注），不印程序算的方向和公里数：坐标是照这句话推出来的，再印成公里就像量过一样。题签还是摆在沙盘边上朝着 `at` 的那一点。

### 题签摆在哪

题签摆在画面的哪里由程序定，文件里不写像素：摆在它指的那一点旁边，躲开别的题签、别的题签指的点和它自己指的那样东西；`side` 只是一个愿望，那一边摆得下就摆那一边；`lean` 也是愿望，那一边偏一格的位置摆得下就摆那里（摆在上边、下边时一格是半条题签宽，题签的一条边正好让开那一点；摆在左边、右边时一格是题签高的三分之一），摆不下先试同一个位置再远一档的，然后才是正对着的。想摆的那一边摆不下、或者只剩被推回来很多的位置时（读者把镜头推近，那一点到了画面的边上），写了 `lean` 的题签先退到 `lean` 说的那一边（写 `above` 和 `left` 的退到左边），再照原来的先后试剩下的两边；没写 `lean` 的照原来的先后试（上、右、左、下，去掉想摆的那一边）。远处的题签摆在沙盘边上朝外的那一边。朝外的那一边摆不下、只好摆在旁边时，它指的那一点上另画一个朝外的小箭头：那一点只是沙盘的边，地方还在外面很远。读者转动沙盘时，题签跟着它指的那一点走，能不换位置就不换。

**每一节的题签必须都摆得下。** 照这一节自己的镜头，在下面四种标准的画面上，一条也不能少，自动检查（`tests/stage/scene-strips.test.ts`，随 `npm test` 跑）：

| 沙盘栏（宽 × 高） | 上、下各留出 | 是什么 |
|---|---|---|
| 940 × 900 | 62、130 | 1440 × 900 的电脑窗口 |
| 584 × 768 | 62、130 | 1024 × 768 的窗口 |
| 768 × 573 | 54、131 | 竖着拿的 768 × 1024 平板（沙盘栏占屏幕高度的 56%，`decisions.md` 第 23 条） |
| 1024 × 765 | 54、131 | 竖着拿的 1024 × 1366 大平板（12.9 英寸的 iPad）：有 960 像素以上宽，可它是竖着的，版面和竖着拿的小平板一样（见“页面怎么用这三套字体”里的“上下排还是左右排”） |

这四个数只写在 `tests/stage/support/standardPanes.ts` 一处；浏览器测试到真的页面上再量一遍（`tests/e2e/pane-boxes.spec.ts`），量到的要和它一样。

只考虑平板和电脑，不考虑手机（`decisions.md` 第 22 条）：不为手机的画面调镜头、调题签，也不拍照检查。

**题签有多大。** 题签是一张竖着的纸条，脚上画着一方小红印。沙盘栏（连它的一像素边线）584 像素宽起用大的：字 17 像素，宽 29 像素，高 22 + 19.04 × 字数（上垫 6，下垫 16，印就画在下面这 16 像素里）；不到 584 像素宽用小的：字 14 像素，宽 24，高 17 + 15.68 × 字数。四种标准的画面用的都是大的。这几个数在 `src/styles/stage.css`（`.strip`）里，检查照同样的数算（`tests/stage/support/stripSizes.ts`），浏览器测试再量一条真的题签来对（`tests/e2e/pane-stills.spec.ts`）。添那方印以前，两种各矮 4 像素和 3 像素。

检查不过时，三种改法：少立一条题签；挪镜头（改 `target`、`distanceM`，或者写 `closest`）；改这条题签的 `side`。检查都过了、图片上题签却站在这一节要看的东西上，也用 `side`：黄州两节赤壁的“大江”写 `below`，挂在它那一点的下面——立在上面的话，竖着拿的平板上它盖住崖脚石滩的右头和上面的石头（`tests/stage/huangzhou-figures.test.ts` 查那一点比石滩更靠近镜头）。四边正对着的位置都站在要看的东西上时，用 `side` 加 `lean`：眉州“正月上蟆颐山”一节的“浮桥”指着卵石滩上的桥头，写 `above` 和 `left`，题签站在桥头的左上角（上游那一边）——正上面是山上的殿，左边是渡船，下面是卵石滩，右边是桥（`tests/stage/meishan-figures.test.ts` 在四种标准的画面上查它不压这几样）。

**“摆不下时从后面去掉”只管两种情形**：读者自己转动、缩放了沙盘以后；窗口的大小不在上面这三种里（比如沙盘栏上面多了一行说明的时候）。这时排在后面的题签不摆，它指的那一点上留一个空心的圈，表示这里有一处没标出。

**全程沙盘上的题签。** 摆法、大小和上面说的一样，另有四条：

- 一节最多十二条（站点沙盘六条）。看全程的那一节立十条：各站的名字，加上大江和海。
- 地名点写了 `stops` 的题签，脚上不画那方小红印，画的是站号的印：这个地方是哪几站，就有几方，印里是这一站的号码（一、二、三……），和人物页目录里圆点里的数字是同一个。写好了正文的站是红底纸色的字，还没写的是红框红字。这只说明这一站写没写好，不是读没读过：沙盘上不记读者读到了哪。
- 印是通到这一站的链接，点了进这一站；点题签上的名字，进的是它头一方印的那一站。用键盘的读者从目录进各站，印不另占一轮 Tab。这一小节讲的那一站，印外面多一圈墨线（惠州和昌化军是同一站，两处都有）。印在宽的栏上是 19 像素见方，窄的栏上 16 像素；按得到的地方比印大，至少 44 像素见方，上下挨着的两方印各管到两方中间。带印的题签接手指：从它上面起手拖，沙盘不转。每一站的印怎么写、通到哪，是页面用 `src/domain/stopMarks.ts` 从 `figure.json` 里拼好交给沙盘的（`StageOptions.marks`）；没有交，题签上就没有印。
- 四种标准的画面上，古名、今名两种叫法，每条题签离它指的那一点都不超过 48 像素：全程沙盘在竖着拿的平板上只有四百来像素宽，一条题签有七八十像素高，摆远了，名字就落到别的地方头上了。沙盘栏上面多一行说明的时候（只放图片的那一档；写好了正文、还没有自己的沙盘的一站，像黄州，摆着立体的沙盘也有这一行），看来路的各节只保证每条都摆得下，不保证这 48 像素。超了的改法依次是：给这条题签写 `side`；挪这一节的镜头；这一节少立一条水名。站名不去掉。
- 看全程的那一节管得更严（2026-11-20 检查以后加的）。人物页和首页一打开看的就是它，八站的名字都在上面；沙盘栏矮了，整块沙盘就小，题签最挤。出过的事：竖着拿的平板上徐州的名字站到了密州的东边、海里，上面多一行说明时汴京的名字落到了大江以南。所以这一节在量过的每一种沙盘栏上都查：四种标准的，它们上面多一行说明的四种，首页的两种，别的竖着拿的平板五种（`standardPanes.ts` 的 `UPRIGHT_PANES`：窗口 744 × 1133、800 × 1280、810 × 1080、820 × 1180、834 × 1194，沙盘栏 744 × 634、800 × 717、810 × 605、820 × 661、834 × 669，上下留 54、131，多一行说明时上面留 84）连它们多一行说明的，一共二十种。规矩是：一条不少，不压点、不相叠，引线不超过 48 像素，站名不站到别的站那一边去（两个站的题签差不多一样高时，左右的先后要和它们指的两个点一样）。屏幕越扁沙盘越小，最挤的是 810 × 605 上面多一行说明的时候（沙盘四百像素宽），不是 768 × 573。为了过这一条，看全程的那一节用的是它自己的两条题签：`s-hangzhou-all`（杭州，摆在点的下边）、`s-mizhou-all`（密州，摆在点的右边）；看来路的各节用的还是原来的两条（摆在左边，不挡住路的那一头）。“海”那一条摆在点的右边，落在海上。量到的最长的引线是 32 像素。这几种栏的大小在浏览器里量过（`tests/e2e/pane-boxes.spec.ts`）。
- 首页摆的也是这座沙盘，只看头一节（全程）。宽屏上首页的文字栏比人物页的宽，沙盘栏就窄一些：1440 × 900 的窗口上是 800 × 900（上、下各留 62、130），1024 × 768 的窗口上是 553 × 768（上、下各留 62、94：栏不到 584 像素宽，题记是窄的那一种，题签是小的那一种）；沙盘在上的两种窗口上和人物页一模一样。这两种栏也写在 `standardPanes.ts` 里（`HOME_PANES`），头一节在它们上面照同样的规矩查（一条不少，不压点、不相叠，不超过 48 像素，沙盘摆在正中；`tests/stage/route-views.test.ts`），浏览器测试到首页上再量一遍。量到的最长的引线是 32 像素和 24 像素（徐州）。

**这一节讲的小东西要认得出来。** 模型放大多少由样式定（`src/stage/three/style/`），场景文件里不写；镜头离得越远、画面越小，放得越大。每座沙盘另有一张表（`tests/stage/<站>-figures.test.ts`）：哪一节讲的哪样东西（徐州是草屋、棚子、系在城下的船、放鹤亭、百步洪的乱石和小船、黄楼），在宽屏和竖着拿的平板两种画面上最少多少像素。表里的数是照着截图定的。检查不过时改样式里的数或者这一节的镜头，不往场景文件里加字段。

**依据里说了数目、怎么分组的东西，远看时一样也不减。** 民居、村子、树是点缀，远看时会少摆一些、摆大一些。船和石头不减：徐州“系在城下的船”的依据写的是“三到六条一组，一组一组分开系”，百步洪的是“两条小船”，乱石要“西边留出一线水路”，所以它们只放大到互相不挤、不堵住水路为止，画面小的时候会比别的东西小。大水那几节里，立在水里的屋（张山人的草屋）是照着水面放大的：水到门扇的一半，放大以后还是一半。这些也有自动检查（`tests/stage/scene-figures.test.ts`）。

### 小节（sections）

和正文的小节一一对上，顺序相同。正文还没写的站没有正文可对：小节是三到六个画面，见上面“正文还没写的站的沙盘”。

| 字段 | 含义 |
|---|---|
| `heading` | 正文里的小节标题。正文还没写的站：这一个画面的名字 |
| `date` | 这一节是什么时候，如“熙宁十年（1077）九月” |
| `line` | 题记：一句话，说沙盘上这一节看什么，不超过 40 个字。这一节的题签指到远处时，题记连同远处的那句话不超过 50 个字宽。头一节的镜头不是朝北看的，题记开头先说从哪边往哪边看，写成“从城的北边往南看：……”（黄州）：全程沙盘和地图都是上北下南，读者会照着那样想，城却可能在画面里江的另一边。朝的方向说成东、南、西、北和四个斜的方向里最近的一个；`tests/stage/scene-cameras.test.ts` 照镜头的 `bearing` 查这半句 |
| `camera` | 镜头（见下） |
| `water` | 水位，写 `levels.values` 里的名字 |
| `sky` | 可以不写。天色：`day`（白天，不写就是它）或 `night`（夜里）。见下面“夜里的小节” |
| `moon` | 夜里的小节必须写，白天的不能写。月亮在天上的哪里：`azimuth` 是方向（0 是正北，顺时针，度），`altitude` 是离地平线多高（度，5 到 85 之间） |
| `mist` | 可以不写。这一节山脚的云气几成：0 到 1，不写是 1（样式定的浓淡）。记载里说那一天没有雾的小节写 0（黄州“十月，再到赤壁”：水落下去，云气横在干的滩上像一道污痕） |
| `strips` | 这一节摆哪几条题签（题签的 id），一到六条，要紧的在前。照这一节自己的镜头，在四种标准的画面上必须都摆得下（见“题签摆在哪”） |
| `farLine` | 可以不写。只在题记下面说、不立题签的远处（远处的 id）。只给写了 `inHisWords` 的远处用，见上面“只在题记下面说、不立题签的远处” |
| `explain` | 沙盘的说明先讲哪几样，最容易看错的在前，至少一样。点到的每一样，它的 `note` 都印在点“说明”展开的几句话里 |

`explain` 里可以写带类别和依据的任何一样东西的 id、没有画的东西的 id，或者四个词：`levels` 指水位，`banks` 指河岸的规矩，`terrain` 指地形，`recipe` 指地形的整理。点到的东西都要有 `note`。

**夜里的小节**（2026-11-23 加的；规则 21）。正文写的是夜里的事（黄州的赤壁两夜、承天寺一夜），这一节的 `sky` 写 `night`，再写 `moon`：那一夜、那个时辰月亮在哪个方向、多高，是照日期算出来的，算法和出处写在这一站的研究记录里。沙盘上不画月亮，也不点灯；变的只有光：

- 光从月亮那边来，是冷的、淡的，带一点蓝（照到月光的平地在屏幕上是淡淡的青灰，不是暖灰：暖灰的夜看着像阴天）；天光补得多，夜色不黑到看不清地形。颜色是时代样式里的一套（`src/stage/three/style/` 里那种样式的 `light`），每一夜都一样；方向跟着 `moon` 走，月光、天光的强弱也跟着月亮的高矮走：月亮在 12 度以下用强的一头，68 度以上用弱的一头，中间照高度的正弦匀过去。这样定是因为月亮高的时候光直着下来，两头用一样的强弱的话，月亮高的一夜平地比月亮低的一夜亮得多，看着像阴天的下午；现在平地在这两种夜里的亮，差不到白天的一成（`tests/stage/rig.test.ts` 记着）。影子也跟着月亮：月亮低，影子长。
- 月亮低的时候，月光直接照到的水面亮一些（影子里的水面不亮）；月亮高的时候水面不另外加亮。亮多少只看 `altitude`（`src/stage/three/rig.ts` 的 `sheenFor`）：12 度时多亮出 9.1 倍，24 度时 5.1 倍，68 度以上是 0，中间照高度的正弦匀着降（`tests/stage/rig.test.ts` 里记着这张表）。这是对着黄州七月那一夜的图定的：敞开的江面比照到月光的平地亮二十来级，水纹不比白天白。
- 远处的雾、山脚的云气、座子木头上的反光不受光照，夜里跟着压暗（压到“这一套光照在平地上的亮”比白天的几成，`rig.ts` 的 `lightDim`）；云气夜里淡一些。
- 地面的颜色、模型、题签都不变：地面还是先画好的那一张，题签还是纸条。所以夜里的小节不用另外画地面（`sky`、`moon` 不在“先画好的地面”的记号里），定格图要拍（它们在定格图的记号里）。沙盘栏的底色夜里也不变。
- 从白天的一节换到夜里的一节，现在是一下子换过去的。

`sky`、`moon` 只有站点沙盘的小节能写；全程沙盘只有白天。徐州没有夜里的小节：2026-11-23 先在徐州的沙盘上试看过（沙盘测试页 `stage-dev.html?sky=night&moon=103,12`，只在那一页上有）；黄州是头一座，它的“赤壁”“十月，再到赤壁”“承天寺”三节是夜里。“赤壁”一节（七月十六）写的是那一夜九点上下的月亮：方位 111 度、高 24 度。那一夜八点月亮才 12 度高，沙盘上的山夸大了 6 倍，那么低的月亮照出来，江面的三成到四成在一道拖得很长的影子里，小船也在里面，和“水光接天”对不上；原文是“少焉，月出于东山之上，徘徊于斗牛之间”，说的是月亮已经升起来了，所以取晚一个钟头的月亮（2026-11-23 定的）。

**镜头（camera）。**

| 字段 | 含义 |
|---|---|
| `target` | 镜头对准哪 |
| `targetUpM` | 可以不写。对准的那一点比那里的地面高多少米。看一座楼时写楼的半腰 |
| `distanceM` | 镜头离那一点多远（米）。按宽和高差不多的画面定 |
| `pitch` | 倾角，0 为正俯视 |
| `bearing` | 朝哪边看，0 朝北，顺时针 |
| `fov` | 可以不写。视角，度。不写用 21 |
| `closest` | 可以不写。要看的东西都还看得见时，镜头最多可以靠近到 `distanceM` 的几成，0.8 是八成。不写就不靠近 |
| `mustShow` | 可以不写。画面再窄也要看得见的东西的 id，或 `frame`（整块沙盘，连装裱和座子一起算）。不写就是这一节的题签指的那些点；写了就只管写的这几样，题签指的东西要保证看得见，也得写进来 |

画面窄了（比如平板竖着拿），程序自己把镜头退远，退到 `mustShow` 里的东西都看得见为止。“看得见”是落在画面留出来的那一块里（上面让开按钮，下面让开题记）。`mustShow` 里写的每样东西，顶上和脚下都算：只算顶上，斜着看时它的脚会压在题记底下；城墙还要算到墙脚和角台的外面。一段急滩不止算它写的那一点：顺着河往上、往下各半段长（`lengthM` 的一半）的两头也算，画面窄了整段乱石滩才都在画面里。

`mustShow` 里写了 `frame` 的一节是看整块沙盘：程序把镜头对准的那一点在地面上挪一挪，让沙盘（连装裱和座子）在留出来的那一块里上下、左右都居中。这种小节的 `target` 只要写个大概。

**一站自己的沙盘上小像站在哪（第二期，还没有做）。** 到时候每一小节要写两样：这一节讲的是哪一段日子（写法就是行迹里“一个日子”的那一种，要落在行迹里住在这一站的年月里面），小像站在哪一点、或者这一节没有他。这两样不算进定格图和先画好的地面的记号里。字段叫什么到时候定（`when` 这个名字摆件和点缀已经用了，小节上不再用它），所以**场景文件里现在不要写**：不认识的字段通不过校验。**做一站沙盘的时候，这两样先写在这一站的考证记录里**（每一小节一句：讲的是哪一段日子、依据是什么；他站在哪一点，或者这一节讲的不是一个地方、没有他），第二期照它填，不用再考一遍。

### 没有画的（notDrawn）

史料里有、沙盘上故意不画的东西（徐州的外小城：有这道墙，在哪查不到）。写 `id`、`name`、`why`（为什么不画，给读者看的一句话，必须写）、`sourceIds`。正文提到而沙盘上没有的东西，都要在这里交代。

### 沙盘旁边的说明是怎么来的

说明不用另写，程序从场景文件拼出来（`src/domain/sceneText.ts` 的 `sectionInfo`）。每一节的说明一定说到四样：哪些是示意；地形修整了哪里；山高夸大了几倍；模型都放大了，河画宽了。它有三种写法：

**常印在沙盘旁边的一句（`short`）。** 沙盘栏宽的时候用，最多占两行，如“城墙、河道、水位等 31 样是示意；平地修整过；山高夸大 6 倍；模型和河都放大了”。示意的点前三样的名字（只有一部分示意的写成“某某的细节”），再多写“等几样”（数的是总数）。整句不超过 60 个字：名字太长放不下时少点几样，一样也放不下就只说一共几样。

**栏窄时的一句（`brief`）。** 沙盘栏不到 584 像素宽时用（平板上遇不到；电脑上只有窗口 960 到 1023 像素宽时才遇到），只占一行，不点名字，只说一共几样：“31 样是示意；平地修整过；山高夸大 6 倍；模型和河放大了”。

**完整的几句话（`lines`）。** 不常印着：上面那一句的后面有一个“说明”按钮，点了才展开，盖在沙盘的下边，再点一下、按 Esc 或者换了小节就收起。展开的那一块平常在按钮那一排和题记之间；窗口很矮的时候（把网页放大到两倍，或者横着拿、宽度不到 960 像素的平板：上下排的版面上沙盘栏只有窗口的 56% 高），那里剩不下几行，这一块至少有 160 像素高，差多少就往下盖住题记多少（最多盖到题记的下边，不伸到沙盘栏外面：按钮下面还有一行话的时候它就只有 150 像素上下），里面滚得动，“关闭”点得到（四种标准的窗口上地方都够，和原来一样；`tests/e2e/main-flow.spec.ts` 在 720 × 450 的窗口上量）。依次是：

1. **哪些是示意。** 这一节沙盘上有的东西里，类别是 `schematic` 的，列出名字；类别是 `text` 又写了 `unsure` 的，写成“某某的某某”。`explain` 里点到的排在前面；其余的先是水（水位、河岸的规矩、河、急滩、水漫不进去的地方），再是地名点、摆件、点缀、远处，最后是地形的修整。最多列五样，再多写“等几样”（数的是总数）。地形的整理不列在这里，它在第 2 样里单说；远处只算这一节的题签指到的。
2. **地形修整了哪里。** `recipe` 的 `note`。
3. **这一节特别要说的。** `explain` 里点到的每一样东西的 `note`，按点的先后；同一句话不印两遍。
4. **山高夸大了几倍；模型都放大了，河画宽了。**

沙盘旁边的这一块字（小节和时间、题记、上面那一句、远处）高度是定死的，栏宽、栏窄各一个数，哪一小节都一样高：换小节的时候沙盘四边留的空不变，画面不会跳。所以这几样的长短都有上限（题记 40 个字，`short` 60 个字，`brief` 一行），超了就显示不全。

**栏宽、栏窄怎么分。** 页面自己量沙盘栏的宽度（`src/ui/StagePane.tsx`），量到的结果写在栏上，样式表照着排（`src/styles/stage.css`）；不用“按栏宽查询”的样式写法（`@container`、`cqw`）：老平板（iPadOS 15）不认，用了的话，它上面不管栏多宽都只有窄的排法。

- 栏（连它的一像素边线）584 像素宽起是宽的排法（栏上挂 `is-wide`）：这块字 130 像素高，题记自己一行，说明是最多两行的 `short`，远处另起一行。584 就是横着拿的平板上沙盘栏的宽；四种标准的画面都是宽的排法。
- 不到 584 像素是窄的排法：94 像素高，题记和远处接着排、合起来最多两行，说明是一行的 `brief`；题签也小一号。
- 宽的排法里题记的字号照栏宽算，让最长的 40 个字一行正好放得下：（栏里面的宽度 − 21）÷ 40，往下取成整数的像素，最小 14 像素，最大 19 像素。字号是页面算的，和栏里面的宽度一起写在栏上（`--line-size`、`--pane-w`），样式表照着用；还没写上的那一下是 14 像素。横着拿的平板上是 14 像素，竖着拿的平板上 18 像素，电脑上 19 像素。取整数是因为有的系统上一个字只占整数个像素（Linux 上的 Chromium，平常的设置）：14.95 像素的字在那里一个占 15 像素，40 个字比算好的宽出 2 像素，行尾就被截掉了（发布流程的机器上量到过；Windows 和 macOS 上字可以排在半个像素上，看不出来）。字号是整数，40 个字在哪里都是 40 × 字号那么宽，不超过这一行。栏有多宽，页面在三种时候量：每次重画以后，窗口的大小变了以后，还有窗口没变、栏自己变宽变窄了的时候（页面长出或者收掉了滚动条；靠浏览器的 `ResizeObserver` 看着这一栏，只认宽度的变化，没有这样东西的浏览器照前两种时候量）。量完重排题记，再告诉沙盘大小变了。
- 题记是一句话，多大都是宋体（2026-11-24 起，第 51 条；原来够 16 像素用楷体，栏上另挂一个 `is-kai`，现在这个类名不挂了）。正文还没写的一站，文字栏那张单子里每一行印着的题记是同一句话，也是宋体。

在浏览器里量（`tests/e2e/pane-look.spec.ts`）：从 560 像素宽的栏往上换三十来种栏宽，40 个字的题记都放得下，584 起一行不截断、不小于 14 像素；题记多大都是宋体，栏上不挂 `is-kai`；每一种栏宽上字号都是整数、就是算法取整以后的那个数，40 × 字号不超过这一行的宽（这一句是算术，在哪种系统上跑都查得出来）。

**宽的排法在哪种版面上都是 130 像素高。** 上边 8，小节和时间 26，题记 26，说明两行 40，远处一行 20，下边 10。竖着拿的平板上画面最紧，想过把这块字改矮，量过以后没有改。量法：在浏览器里，把徐州七节、黄州九节的字各排一遍（黄州的沙盘还没做：字是拿它的场景草稿交给同一个函数生成，再摆进页面上这块字里量的），栏宽 768 和 1024 像素，都是上下排的版面。结果：说明两行、又带远处一行的小节三行都用上了，字排到第 120 像素——黄州的“到黄州”就是；只看徐州的话，字最多排到第 100 像素，110 像素高就够。说明最长许可 60 个字（`short`）。说明这一行占满这一条的宽，右头立着“说明”按钮（和上面的比例尺、指北一样靠右）：电脑上这一行能排 861 像素，竖着拿的大平板上 946 像素，60 个字也是一行；竖着拿的平板（768 像素宽）上 690 像素，量到的是 53 个字还是一行、54 个字起两行——黄州有四条 54 到 59 个字的说明，“到黄州”那一条下面还带着远处一行，字还是排到第 120 像素；横着拿的平板上 505 像素，哪一条说明都是两行。所以要把这块字改矮，得先把说明的上限减到 768 像素宽的平板上一行放得下的字数。（这一行原来最宽只许 704 像素，“说明”按钮立在这一条的中间，栏再宽长的说明也折成两行；2026 年 11 月改成占满这一条。）在浏览器里量（`tests/e2e/pane-look.spec.ts`）：四种标准的窗口上每一小节，说明的字到不了按钮底下，题记、说明、远处都没有截掉的字，远处那一行紧接在说明下面。

凭据里“沙盘上的东西”一栏也是拼出来的：按五类列出每样东西的名字、依据和出处，后面是没有画的东西，最后是 `credits`。

**全程沙盘的说明**也是这样拼出来的，一定说到的还是那四样，有三处说法不一样（生成这几句话的程序在 `src/domain/sceneText.ts`，和站点沙盘的是同一个）：

- 山高：完整的写“山的高度夸大了约 8 到 25 倍，矮山夸得多、高山夸得少”，常印着的那一句里写“山高夸大 8 到 25 倍”。两个数是 `relief` 的 `highTimes` 和 `lowTimes`。
- 地形修整了哪里：常印着的那一句里写“平地抹平”。
- 第四样不说“模型和河都放大了”（全程沙盘上没有模型），说的是“河和路都画宽了，不按比例。”；常印着的那一句里写“河和路都画宽了”，栏窄时的那一句写“河画宽了”。

“哪些是示意”里，一趟路的每一截各算一样，用它自己的名字；这一节没有画的路（后面各站的）不算。远处的那句话从题签指的那一点量（见“全程沙盘的场景数据”里的“题签和远处”）。题记里只说站名和这一节立了题签的山和水。全程沙盘的凭据（“沙盘上的东西”一栏）在人物页的目录下面：折着的一行“凭据”，和站点页上是同一个组件，点开才取里面的东西，出处用场景文件自己的 `sources`。

点名字的先后，头一节（全程）和站点沙盘一样照 `explain`；看来路的一节（写了 `stop` 的）不看 `explain`：到这一站去的路里整截是示意的排在最前，再是水，再是别的（地名点、远处、别的路、抹成海的地方）。“还有”后面接的名字是数字打头的（“1097 年……的路”）时，前面空一格。看来路的一节，到这一站去的路里没有整截示意的（到黄州、到示例城那样）：常印着的那一句不点名字，只说一共几样（“28 样是示意；平地抹平；……”）——点出来的只会是别处的水，这个画面上不一定找得到；点开“说明”的那一句照旧点名字。

### 场景文件里不写的

题签摆在画面的哪里、光从哪来、阴影、雾、镜头离多远时模型放大多少、远看时点缀少摆多少，都由程序按样式定，文件里没有这些字段。文件里也不写像素。一种样式只有一种光，不跟着镜头换。

## 全程沙盘的场景数据

每位人物另有一座全程沙盘：他走过的各站和站与站之间的路，摆在一块两千公里见方的地面上。它由三个文件定下来：场景文件 `scenes/route.json`，地形文件 `scenes/route.terrain.bin`，今天的海岸、湖、河 `scenes/route.today.geojson`。机器可读的形式是 `src/domain/scene.ts` 后半截的 `RouteScene`。动手之前同样先写考证记录（苏轼的是 `docs/research/route-table.md`）。

**做到哪了（2026-11-20）。** 这一节写的规矩、`scene.ts` 里的类型、经纬度的换算（`src/domain/sceneGeoRoute.ts`）和校验（`tests/content/routeRules.ts`）已经有了。苏轼的 `route.json` 已经在内容里，照它算地面的程序（`src/stage/ground/route.ts`）也有了；从正上方看的检查图用 `npm run route:map` 画（不进仓库）。照它把地面和水摆出来的程序也有了（`src/stage/three/routeLevel.ts`，沙盘程序碰到全程沙盘时才下载的一块；给地面上色的是工具 `tests/tools/route/paint.ts`），在沙盘测试页上看。路（`src/stage/three/routeKit.ts`）、沙盘旁边那几句话的生成（`src/domain/sceneText.ts`）、题签脚上的站号印（`src/stage/overlay`）也有了；页面把它摆在人物页、首页和没有自己的沙盘的各站（`src/ui/StagePane.tsx`）。“进一站，先看来路”在有自己的沙盘的站上（进徐州先看到徐州的路）这一轮没有做。

**它和站点沙盘是同一种文件。** 场景文件里写 `"level": "route"`、`"stopId": "route"`（站点沙盘的 `level` 可以不写，写了只能是 `stop`）。它的“小节”不对着哪一篇正文，是一个一个的画面：头一节看全程，后面每一站一节，看的是到这一站去的那段来路。所以小节、镜头、题记、题签、说明、古名今名、先画好的地面、每一小节的定格图，都照站点沙盘的办法来，前面“场景数据”一节里讲这些的话在这里一样管用。下面只写不一样的地方。

| | 站点沙盘 | 全程沙盘 |
|---|---|---|
| 范围 | 原点和四边的米数；照原点的纬度把经纬度换成米 | 一个投影（兰勃特等角圆锥）加一个比例；四边的米数在投影出来的平面上量 |
| 山高 | 统一夸大几倍 | 矮山多夸、高山少夸，照一条曲线 |
| 地形文件 | 一个数是 1 分米 | 一个数是 1 米；0 是海 |
| 水 | 一个水面；河是挖出来的 | 没有水面，不挖河：海、湖、河都画在地面上。照今天画的那些，线在另一个文件里，场景照名字去取 |
| 摆件、点缀、急滩、河岸的规矩、水漫不进去的地方、`when`、天色 | 有 | 没有：这些字段不写，写了通不过校验 |
| 路 | 是一种点缀 | 单有一组字段（`roads`）：一截一截的路，和一趟一趟的行程 |
| 出处 | 在这一站的 `stops/<站>.json` 里 | 在场景文件自己的 `sources` 里（全程沙盘没有那个文件） |
| 类别 | 五类 | 用四类，没有点缀 |
| 一节的题签 | 一到六条 | 一到十二条 |

### 通用的写法

- **高度**写真实的米（海拔）。**长度**也写真实的米（范围的四边、`smoothM`、`edgeTaperM`）。只有一样例外：**镜头的 `distanceM` 写的是沙盘里的米**，两层沙盘都是（站点沙盘上沙盘里的 1 米就是地上的 1 米，两样是一回事）。它是摆镜头用的数，不是地理上的数；这样写，两层的镜头可以比着看（徐州看全景是 52,000，苏轼的全程沙盘看全景是 62,800）。
- **id** 在整个文件里不重复，不能带“/”，路的 id 不能以“-”开头（这两个符号另有用处，见“路”）。留用的词是 `frame`、`terrain`、`recipe`、`levels`、`coast` 五个：没有 `banks`，多一个 `coast`（照今天画的海岸）。
- `route` 这个词留给全程沙盘：不能当站的 id。
- `credits` 至少两条：地形一条，今天的海岸、河、湖一条。
- `sources`：依据里的 `sourceIds` 指的出处，写法和一站的 `.json` 里的 `sources` 一样（`id`、`basis`、`cite`）。

### 范围（frame）

| 字段 | 含义 |
|---|---|
| `center` | 投影的原点，也是沙盘的原点 |
| `projection` | 投影。只有一种：`{ "kind": "lambert-conic", "lat1": 22, "lat2": 35 }`，兰勃特等角圆锥，`lat1`、`lat2` 是两条标准纬线。形状不走样；这两条纬线上长度是准的，中间略短，南北两头略长（苏轼的沙盘上差百分之一上下） |
| `scale` | 沙盘上的 1 米是地上的多少米，50 到 1000 之间。苏轼的是 171：两千公里宽的地面摆成 11.7 公里宽的沙盘，和徐州的沙盘一样宽，镜头、灯、座子都不用另配 |
| `westM` `eastM` `northM` `southM` | 从原点到四条边各多少米：真实的米，在投影出来的平面上量 |
| `datumM` | 这个海拔是沙盘上平的桌面。全程沙盘写 0（海面） |
| `relief` | 山高怎么夸大（见下） |

投影出来的沙盘是方的，可是它的边在地球上是弯的：北边的正中比两个角更靠北（苏轼的沙盘北边两个角在北纬 38.01 度，正中在 38.44 度）。所以“在不在沙盘里面”“地形文件盖不盖得住”都是换成沙盘里的米以后再比的，不拿四个角的经纬度比。

**山高（relief）。** 只有一种写法，“矮山多夸、高山少夸”（`decisions.md` 第 19 条）：

```json
{ "kind": "low-hills-more", "lowBelowM": 300, "lowTimes": 25, "power": 0.6, "highTimes": 8 }
```

海拔 `lowBelowM` 以下夸大 `lowTimes` 倍；再往上，夸大以后的高度是 `lowTimes × lowBelowM ×（海拔 ÷ lowBelowM）的 power 次方`。照上面的数：300 米以下夸大 25 倍；300 米是 7,500；再往上按 7500 ×（海拔 ÷ 300）的 0.6 次方算，1,000 米是 15,445（15 倍），4,650 米是 38,838（8 倍多）。`highTimes` 写的是做出来的地面上最高的山夸大了大约几倍，取整数；说明里印“山的高度夸大了约 8 到 25 倍，矮山夸得多、高山夸得少”，这两个数就是 `highTimes` 和 `lowTimes`。`highTimes` 是照做出来的地面量了写的，不是照地形文件里最高的那个数算的（地面抹过以后山顶矮了）；对不对由 `npm test` 照做出来的地面核。`lowBelowM` 大于 0，`lowTimes` 不小于 1，`power` 大于 0、不大于 1，`highTimes` 是 1 到 `lowTimes` 之间的整数。

### 地形（terrain）

| 字段 | 含义 |
|---|---|
| `file` | 地形文件的名字，`route.terrain.bin`。今天的高程，经纬度的网格：16 位整数（低位在前），第 0 行最北，第 0 列最西，逐行存 |
| `cols` `rows` | 网格多少列、多少行 |
| `west` `east` `south` `north` | 网格盖住的经纬度范围，要盖得住整块沙盘：四条边都算，不只看四个角 |
| `heightUnit` | 地形文件里一个数是多少米。全程沙盘写 `m`（一个数是 1 米；16 位整数按分米最多存到 3,276 米，这里最高的山有五千多米，存不下） |
| `recipe` | 整理的办法（见下） |
| `edits` | 抹成海的地方（见下） |

**地形文件里也记着哪里是海。** 今天是海的格子存 0；今天是陆地的格子存它的海拔，最小存 1（海拔不到 1 米的陆地也存 1）。读者的浏览器拿不到今天的海岸线，沙盘程序就靠这个 0 分海和陆地。

**整理（recipe）。** 全程沙盘只有一种办法，`plain-smoothed`：平原抹成缓坡，山照原样。今天的平原上有后来才有的东西——黄河和它的旧河道高出两边的垄，洪泽湖、微山湖这些后来的湖留下的盆——照今天的高程画，当时没有的东西就显出来了，所以抹掉。

| 字段 | 含义 |
|---|---|
| `plainBelowM` `hillAboveM` | 一个地方四周（约 20 公里）的平均海拔低于前一个数的算平原，高于后一个数的算山地，两个数之间慢慢过渡 |
| `smoothM` | 平原抹成的缓坡：把平原自己的高度抹开这么多米。山地和海的高度不算进去 |
| `plainKeep` | 平原上的小起伏留几成，0.1 是一成 |
| `rippleM` | 两个数。平原上比缓坡高出或低下不到前一个数（米）的起伏只留 `plainKeep`；超过后一个数的算山，照原样；中间匀着过渡 |
| `edgeTaperM` | 离沙盘边这么多米以内，地面收低到海面，切面才齐整 |
| `blank` | 路没到的地方：一圈或几圈线，里面留白（夸大以后的地势压到百分之三，上空绢的颜色，海岸只留一道细线）。圈可以伸到沙盘外面。圈是直线围的，画出来的边不是：东经 106 度以西，程序用噪声把边打散，顺着山谷伸进去（往东最多 0.4 度、往西最多 0.6 度、南北最多 0.6 度），再抹开 40 公里；颜色比地势先淡完，河跟着陆地一起淡。所以沙盘上留白的边和这里写的线差着几十公里，这是画法，圈只说“大约到哪里” |

`recipe` 的 `note` 必须写。它的 `basis` 和站点沙盘一样，要照做出来的地面量过再写：哪几处的台阶从几米降到了几米，山动了没有，平原上还剩多少处抹不掉的台阶。

**抹成海的地方（edits）。** 全程沙盘的修整只有一种，`"op": "sea"`：`area` 这一圈里面今天的陆地不画，抹成海（当时的海岸比今天靠里的地方：苏北、长江口、杭州湾南岸）。写 `id`、`name`、`area`（一圈闭合的线，最后一点不用重复第一点，可以伸到沙盘外面），加上类别和依据；类别只能是 `schematic`。

### 水（water）

| 字段 | 含义 |
|---|---|
| `levels` | 海面。`values` 里只写 `normal`，是 0。`note` 必须写 |
| `todayFile` | 今天的海岸、湖、河放在哪个文件里：同一个文件夹里的一个 `.geojson` 文件，只写文件名 |
| `coast` | 照今天画的那条海岸：`name`，加上类别和依据。`explain` 和题签的 `of` 里用留用的词 `coast` 指它 |
| `rivers` | 河和运河 |
| `lakes` | 有岸线的湖 |
| `washes` | 只染一片水色、不画岸线的水（梁山泊、射阳湖这样只知道有、不知道岸在哪的） |

**今天的海岸、湖、河（`route.today.geojson`）。** 一个 GeoJSON 的 `FeatureCollection`，工具做一次，放进仓库；地面上色的工具、校验和测试读它，**页面不下载它**。里面每样东西的 `properties` 写两项：`kind` 是 `land`（陆地，面）、`lake`（湖，面）或 `river`（河，线），`name` 是它的名字（数据里原来的名字；原来没有名字的由工具照位置起一个）。工具不替场景挑：画哪条、不画哪条，由场景文件照名字取。文件不超过 300 KB。

**照今天的数据画，怎么取（`today`）。** 写一条或几条“取法”，一样东西是它的几条取法合起来。一条取法是 `{ "names": ["Chang Jiang", "Yangtze"] }`：取文件里叫这些名字的线；再写上 `west`、`east`、`south`、`north`（可以只写一两个），就只取这个范围里的点。数据里一个名字指着两条河，或者只要一条河的一段时，分成几条取法写（数据里岷江和闽江都叫 `Min`：岷江那一条写 `"east": 106`）。

**河和运河（rivers）。**

| 字段 | 含义 |
|---|---|
| `kind` | `river` 是河；`canal` 是运河，画成一道细线，淡一点 |
| `weight` | 画多粗：`trunk`、`major`、`river`、`minor` 四档，各是多少公里由样式定。河必须写，运河不写 |
| `line` 或 `today` | 正好写一个。`line` 是自己写的线（照史料连出来的河道），可以伸到沙盘外面；`today` 是照今天的数据画 |

类别照实写：照史料连出来的是 `schematic`；照今天的数据画、当时差多少没有查的是 `today`。颜色跟着类别走，示意的淡一点。

**湖（lakes）**写 `id`、`name`、`today`。当时比今天小的湖，可以写 `except`：`{ id, name, area }` 加上类别和依据（类别只能是 `schematic`），这一圈里面的湖面不画。它是单独的一样东西，说明和凭据里各有它的一行。

**只染水色的水（washes）**写 `id`、`name`、`areas`（一圈或几圈），类别只能是 `schematic`。

### 地名点（places）

和站点沙盘一样写 `id`、`name`、`at`，加上类别和依据。多一个字段 `stops`：这个地方是哪几站（`figure.json` 里站的 id，按先后）。写了 `stops` 的地名点，它的题签脚上每一站有一方红印，印里是这一站的号码，点了进这一站。杭州去了两次，`stops` 写两站；一站有两个地方的（惠州和昌化军），两个地名点各写这一站。

`figure.json` 里每一站的位置（`place.lngLat`）要和沙盘上这一站的地名点对得上：经度、纬度各差不到 0.02 度（规则 20）。

### 题签（strips）和远处（far）

字段和站点沙盘一样。不一样的：

- `of` 可以指地名点、河、湖、只染水色的水、远处，还可以写 `coast`：指着海（“海”这条题签）。指着河、湖、水和海的是水名，字用靛青。
- 指着河的要写 `at`，离河的线不超过 6 公里（照今天画的河，照取到的线量）；指着湖、只染水色的水的要写 `at`，落在它里面；指着 `coast` 的要写 `at`，落在海里（今天的陆地外面，或者一处抹成海的圈里面）。
- 一条河要在几处立名字（大江在四川、在黄州、在金陵以下），写几条题签，`of` 都是这条河，各节用各的。
- **远处**：题签必须写 `at`，是路出沙盘的那一点，离沙盘的边不超过 5 公里。沙盘旁边那句话的方向和距离从这一点量到那个地方，不从沙盘的原点量（全程沙盘的原点离哪条边都有上千公里）：“定州：往北约 14 公里（今河北定州）”。

### 小像（piece）

全程沙盘上摆着这位人物的一个小像，标出时间轴上的这一天他在哪里。它不是哪个时候沙盘上有的东西，场景文件里只写凭据里印的几句，写在文件的最外面：

```json
"piece": { "name": "苏轼的小像", "basis": "……", "note": "……" }
```

`name` 是凭据里的名字；`basis` 说它照什么摆（比真人大得多；站在地名点上，沿画出来的路走，两个有记载的日子之间匀着走；线上平时没有立名字的地方，站在线上那个地方的位置，旁边立出那一处的名字；沙盘上没有的地方、没有画的路，不出现）；`note` 说它的样子，哪些是示意的（花青的袍子、陶土色的脸、墨色的高帽；长袍、高帽没有照哪一幅画像）。三句都要是摆出来的样子的真话：改了小像的做法、颜色，这里跟着改。它站在哪里不写在这里，照行迹走。有行迹的人物，全程沙盘写这一组；没有的不写（写不写，校验现在不管，只查写了的三个字段齐不齐）。这一组不算进定格图的记号里：改这几句，定格图不用重拍。

凭据里它单立一栏，叫“记号”，排在那四类的后面、“没有画的”前面；全程沙盘的凭据最后另有一段，印行迹的出处（见“行迹”）。

### 路（roads）

```json
"roads": {
  "ways": [
    { "id": "w-canal", "by": "water", "along": "canal-north", "line": [[119.14, 33.51], [119.32, 33.24], [119.43, 32.79]] }
  ],
  "journeys": [
    { "id": "j-1071", "name": "到杭州", "stop": "hangzhou-1", "date": "熙宁四年（1071）秋冬",
      "parts": [
        { "name": "1071 年汴京到润州的水路", "ways": ["w-bian", "w-canal"], "class": "text", "basis": "……", "sourceIds": ["own-1071"] },
        { "name": "1071 年润州到杭州的路", "ways": ["w-south"], "class": "schematic", "basis": "……", "sourceIds": [] }
      ] }
  ]
}
```

**一截路（ways）。** `id`；`by` 是 `water`（水路）、`land`（陆路）或 `sea`（海路）；`line` 是画出来的那条线，在沙盘里面；`along` 可以不写，写的是沿着哪条河、哪个湖走（它的 id），只是交代，线还是 `line` 写的那条。沿河的水路不压在河上，画在河的一边（离河的线 2 到 15 公里）：这些线是 `npm run route:bank` 照画出来的河算的（`tests/tools/route/bankTool.ts`），算好了贴进场景文件；河的线挪了，重跑一遍，它会说哪几条对不上了。同一截路几趟都走的，只写一次、只画一笔。每一截路都要有哪一趟走到。`by` 说的是这条线照哪一种路画的，不是每一趟走它的路怎么走：1080 年去黄州走的是陆路，汴京到陈州那一段借的是 1071 年沿蔡河的那条线（`by` 是 `water`）；1077 年到徐州是水路还是陆路没有查到，借的也是汴河边的线。一趟路是水路还是陆路，看这一截的依据，不看 `by`；现在没有程序把 `by` 印给读者。

**一趟（journeys）。** 到一站去的那一趟：`id`、`name`、`stop`（到的是哪一站）、`date`、`parts`。一站可以有几趟（第一站有两次出川，各是一趟）；每一站至少一趟。

**一趟里的一截一截（parts）。** 按走的先后写。每一截有 `name`（给读者看的名字，说了哪一年、从哪到哪）、`ways`（走哪几截路，按先后；倒着走的在 id 前面加“-”，如 `"-w-canal"`），加上类别和依据。它在说明和凭据里的 id 是“<这一趟的 id>/<第几截>”，从 1 数起（`j-1071/2`）。一趟路要首尾相接：后一截路的头接着前一截路的尾，差不到 1 公里。

**类别定画成什么线。** 一截的类别只能是两种：`text`（他自己的文字写到了途中的地方）画实线；`schematic`（只知道两头，或者照他以前走过的路画）画虚线。不另有“虚线”这个字段。

**哪一节画哪些路。** 头一节（全程）所有的路都画，一样的墨色。后面的每一节：到这一站的那几趟是“刚走的”，用朱色；前面各站的是“走过的”，淡墨；后面各站的不画。一截路只画一笔：有“刚走的”那一趟走它，就照刚走的画，不然照走过的画；在这种颜色里，走它的各截里有一截是 `text`，就画实线。

**线怎么画**（`src/stage/three/routeKit.ts`；线怎么走、排成几笔是 `src/stage/roadLines.ts` 算的）。线的宽度按页面的像素算，镜头远近都一样宽：墨线 1.8 像素，刚走的 2.4，走过的 1.4；墨线和刚走的路，每一笔下面垫一道 4.5 像素的浅色线，压在山上、河上都分得出来。走过的路下面不垫（`haloUnder` 里没有它）：它是一道淡了的墨线，垫了浅色线远看是一条白线。减配的一档没有抗锯齿，各加粗 0.3 像素。虚线一划 7 像素、一空 5.5 像素，镜头拉近拉远都是这么长。拐角抹圆（最多切掉 9 公里）。线比地面抬高一点，不比深浅：山后面的路也画出来，路不会被起伏的地面吃掉半截。这些数在时代样式里（`StageStyle.route.roads`）。

### 小节（sections）

| 字段 | 含义 |
|---|---|
| `heading` | 这一节叫什么（“全程”“到徐州”），不重复，最多七个字 |
| `date` `line` | 和站点沙盘一样；题记不超过 40 个字，题签指到远处的小节连同远处的那句话不超过 50 个字宽 |
| `camera` | 镜头。字段和站点沙盘一样，只是不许写 `targetUpM`；`distanceM` 是沙盘里的米；`mustShow` 可以写地名点、河、湖、只染水色的水、远处、一趟路的 id，或 `frame` |
| `strips` | 这一节摆哪几条题签，一到十二条，要紧的在前 |
| `explain` | 说明先讲哪几样，至少一样。可以写抹成海的地方、河、湖、从湖面里裁掉的那一角、只染水色的水、地名点、远处、一趟路、没有画的东西的 id，或者 `terrain`、`recipe`、`levels`、`coast`。写一趟路的，它各截的 `note` 照先后印（至少一截要有） |
| `stop` | 这一节看的是到哪一站的来路。头一节不写；后面 `figure.json` 里的每一站正好一节，先后和站一样 |

没有 `water` 和 `sky`：全程沙盘只有一个海面，只有白天。

**题记里只说站名，和这一节立了题签的山和水。** 孩子读到一个名字，要能在沙盘上找到它。路上经过的别的城，写在这一趟路的说明和凭据里，不写进题记。（这一条校验查不了，靠审阅的人看。）

每一站都要有一个地名点是它（`stops` 里写着它），而且这个地名点的题签在头一节和这一站自己的那一节里都摆着。

### 全程沙盘上的类别

还是那五类里的四类，不添第六类，没有点缀；小像另算一样记号，见上面“小像（piece）”：

- **真的**：山的位置和形状。
- **今天的位置**：各站的点；照今天的数据画、当时差多少没有查、也没有查到有大变的河、湖和海岸。依据里写“照今天的数据画，当时差多少没有查”。
- **按史料摆的**：他自己的文字写到了途中地方的那几截路。
- **示意的**：照史料连出来的河道、湖和海岸；只知道两头的路；照今天画、但知道当时不一样的地方（依据里写明）。抹成海的地方、只染水色的水、从湖面里裁掉的角只能是这一类。

小像另算一样，不在这四类里，凭据里单立一栏，叫**记号**：不是当时的东西，只是标出位置；比实际大得多。它不写 `class`。

## 行迹（itinerary.json）

苏轼另有一份行迹：从出生到去世，哪一段年月在哪里，一段接一段，不留空、不重叠。全程沙盘下面的时间轴照它画；沙盘上的小像照它站、照它走。机器可读的形式是 `src/domain/itinerary.ts`。每条出处读了什么、没有读什么，写在它的 `read` 里。

**谁要有行迹。** 行迹的每一段都要对着全程沙盘上的点和路，所以有行迹的人物要有全程沙盘（没有全程沙盘的不许有）。反过来——有全程沙盘的人物要有行迹——校验**现在还不查**：等有了第二位人物再添这一句。没有行迹的人物，人物页和首页上没有时间轴，沙盘上没有小像。

苏轼的行迹是照南宋的两种年表（王宗稷《东坡先生年谱》、傅藻《东坡纪年录》）、查慎行《苏诗补注》的题注和他自己的文字排的。**孔凡礼《苏轼年谱》等今人的年谱没有读到**：凡是“通行的说法”而这几种里没有的日子，都写“没有核到原文”，不当成日期用。文件开头的 `about.notRead` 也写着这一句。怎么读的、每一段依据哪一条，另有一份记录：`docs/research/su-shi-itinerary.md`（记录只是记录，以手写的那一份文件为准）。

**它管三件事，都要如实。**

- **不编日子。** 每一个日子照史料的写法抄下来（`text`），另写它知道到哪一步（`precision`）。只查到月份、季节的，不写成哪一天，只写一个范围：最早可能是哪一天，最晚可能是哪一天。
- **时间轴第一行说的“哪一年、在哪”，一定是史料担保得了的。** 程序要把每一段的头尾放到时间轴上的某一天，这一天只用来摆位置，从不显示成日子。怎么放、为什么这样放就担保得了，见下面“头尾放在哪一天”。
- **两行字是人写的。** 第一行的“在哪”（`label`）和第二行的一句话（`says`）每一段各写一句，程序不拼句子。句子里的日子只许照史料的写法删字；说不准的要说出来。

### 文件里有什么

| 字段 | 含义 |
|---|---|
| `about` | 给写数据的人看的说明（各个字段怎么用、哪一天改过什么）。程序不读，里面写什么校验不管；它不进网站 |
| `sources` | 出处。`id`、`basis`、`cite` 和一站的 `sources` 一样；多一个 `read`：读了什么（读了全文、只读了引文，还是没有读到原文）。全程沙盘的凭据最后印它们：一条出处印一次，下面是它的 `read`。这两样是印给读者看的：不写文件的名字、别处的 id，不说“评审”；拉丁字母只在网址里（`tests/content/itineraryRules.test.ts` 守着） |
| `years` | 农历年的表（见下） |
| `stretches` | 一段一段，按先后 |
| `first` `last` | 时间轴最前、最后一个位置上的两行字：各有 `label`、`says`、`saysDates`（句子里没有日子的写 `[]`） |

不认识的字段通不过校验。手写的这一份里，只有 `sources` 这一个字段打进网站的程序（凭据点开才下载的那一块）；别的字段只有校验和工具读。

### 一段（stretches）

每一段都有的：

| 字段 | 含义 |
|---|---|
| `id` | 不重复 |
| `kind` | 这一段是哪一种：`stop`、`road`、`elsewhere`（见下） |
| `stopYearsOf` | 这一段落在哪一站讲的年月里：到这一站去的来路，加上住在这一站的年月。写站的 `id`；不在哪一站里写 `null`。时间轴上“进这一站”的入口、时间轴停下来以后全程沙盘看哪一节，都照它 |
| `start` `end` | 从哪一个日子到哪一个日子（见“一个日子”）。`start` 就是上一段的 `end`，要一字不差 |
| `sourceIds` | 出处，至少一个 |
| `class` | `text`（他在哪里有文字可据）或 `schematic`（在哪里是推出来的） |
| `unsure` | 这一段里说不准的。点开时间轴的“图例”才看得见。头尾有一个不精确到日（或者写了 `earliestIs`、`latestIs`）的一段，这里不能空着；写了字的至少两个汉字 |
| `note` | 可以不写。补充的话 |
| `longRoad` | 在路上、到的日子又不精确到日的一段，在时间轴上超过 93 天的要写：史料怎么讲它走了这么久 |
| `label` | 时间轴第一行的“在哪”。最多十个字；落在一站讲的年月里的最多七个字（那里第一行右边还有进这一站的入口）。不用弯引号 |
| `says` | 时间轴第二行的一句话。最多三十二个字（最窄的沙盘栏上一行放得下），要紧的半句在前 |
| `saysDates` | `says` 里用到的每一个日子：`of` 说是哪一个日子的写法缩短来的（`start`、`end`，或者“`wp:`”加路上一处的名字），`text` 是句子里的写法。照日子的先后列（先 `start`，再路上各处，最后 `end`），句子里也照这个先后说 |
| `waypoints` | 可以不写。路上的各处（见“路上的各处”） |

**三种。**

- **`stop`：住在一站讲的地方，而且在这一站讲的年月里。** 另写 `stop`（站的 `id`，和 `stopYearsOf` 一样）、`place`（全程沙盘上的地名点，它的 `stops` 里要有这一站）。小像站在这个地名点上。一站有两个地方的，各写一段。
- **`road`：在全程沙盘画出来的一趟路上。** 另写 `journey`（`scenes/route.json` 里那一趟的 `id`）、`from`、`to`（从哪到哪，写地名）、`parts`。`parts` 里的每一截照场景里的那一截写：`name`、`class` 一字不差，`ways` 按他走的先后；只走了这一截里连着的一部分，写 `"partial": true`。同一趟路可以拆成几段（中间住下来过），各段接起来要正好是场景里这一趟的每一截路。`stopYearsOf` 是这一趟到的那一站。小像沿着画出来的线走。
- **`elsewhere`：别的。** 另写 `where`（在哪，开头是地名，后面可以用括号交代几个字）、`moving`（是不是在路上）、`tablePoint`（这个地方在全程沙盘上有没有）：

| `tablePoint.type` | 是什么 | 另写 | 小像 |
|---|---|---|---|
| `stop-point` | 是某一站的那个地名点，只是年月不在这一站里（小时候的眉州，几次在汴京） | `place` | 站在那里 |
| `place` | 沙盘上立了名字、不是站的地名点（湖州） | `place` | 站在那里 |
| `way-vertex` | 在画出来的一条线上（或者紧挨着它：颍州离线约十公里），沙盘上平时没有立它的名字（凤翔、泗州、常州、颍州、扬州、虔州） | `way`（那截路的 `id`）、`at`（这个地方的经纬度，离那截路不超过 15 公里）、`name`（当时的名字，就是 `where` 开头的那个地名）；`where` 的括号里写了“今某省某地”的另写 `modern`（今名，去掉省名：“今安徽阜阳”写“阜阳”），没有写的不写——今名不另查；`note` 可以不写 | 站在线上离它最近的地方；他站到那里的时候，旁边立出这一处的名字（读者选了“今名”、这一处又有今名的立今名），他走了就拿掉 |
| `edge-strip` | 在沙盘的框外，框上立着它的题签（定州） | `strip`（那条题签的 `id`）、`at` | 不出现 |
| `on-ways` | 路上的一趟，经过的地方大半在画出来的线上，可这一趟沙盘没有画 | `ways`、`note` | 不出现 |
| `none` | 沙盘上没有这个地方，或者路线没有查到 | | 不出现 |

`way-vertex` 只给沙盘上确实没有立名字的地方用：场景里没有哪一条题签的古名、今名是它，没有哪一条指着地名点的题签的名字套着它、被它套着，它离哪一个立了题签的地名点都超过 15 公里。哪一天全程沙盘上立了这个地方的题签，这一种就不能再用，要改成 `place`：校验会说（不然小像旁边立出来的名字同原来的题签重了，一个地方两个名字）。

**小像只站在沙盘上有的地方。** 地名点上、画出来的线上，他确实在那里，小像就站在那里；沙盘上没有线的地方、没有画的路，小像不出现，第二行头一个半句说“沙盘上没有他”。小像不会站在一个假的地方。

### 一个日子

`start`、`end` 和路上各处的 `date` 是同一种写法：

| 字段 | 含义 |
|---|---|
| `text` | 照史料的写法，年号纪年，开头写全是哪一年：“元丰三年二月一日”“嘉祐二年四月八日以后”“熙宁六年除夜”。不改字 |
| `year` | 公元年（最早那一天所在的年） |
| `precision` | 知道到哪一步：`day` 日、`month` 月、`season` 季、`year` 年、`before` 某一天以前、`after` 某一天以后、`not-found` 没有查到（`text` 里要明说“没有查到”） |
| `month` `day` | 只有 `day` 才写：公元的月、日，**儒略历**（1582 年以前通行的历法） |
| `earliest` `latest` | 不是 `day` 的都要写，两头都写：最早、最晚可能是哪一天，写成“1084-05-08”（儒略历）。它是日历和前后有日子的记载卡出来的最宽的范围，不是估的。`month` 的范围不超过 60 天（一个月，或者“四月或五月”），`season` 的不超过 120 天 |
| `earliestIs` `latestIs` | 可以不写。这一头是怎么定的（“嘉祐二年的最后一天：史料把动身放在嘉祐二年”） |
| `sharesWindow` | 前后两个日子的范围一模一样的（先动身、后到，都只知道在同一个月里），两个都要写：`order` 第几个，`of` 一共几个 |

范围只写一头不行：程序从不拿前后的日子替它补。知道是哪一天的才写 `month`、`day`；别的写了就通不过。

**精度写不写 `day`，看的是史料的写法。** `text` 自己说到了哪一天——年号、第几年、几月、哪一天（“十九日”“初一”“晦日”），或者“某年除夜”“某年元日”，别的什么也不带——精度才能是 `day`，也一定是 `day`。写法里只有月份、季节，或者带着“以前、以后、或、之间、没有查到”的，精度写 `day` 通不过：那一天是编的。写法末一个字是“春、夏、秋、冬”的（只说到季节），精度只能是 `season`、`before`、`after`。精确到日的写法里的月、日，还要和公元的日子对得上（见“农历年的表”）。

### 路上的各处（waypoints）

路上的一段（`road`，和 `elsewhere` 里 `moving` 的）可以写路上的各处，照走的先后：`name`、`sourceIds`、`note`，查到位置的写 `at`，查到日子的写 `date`，说不准的写 `unsure`。

**只有精确到日、又有位置的地方，把一段路切成一程一程。** 那一天小像就在那里；两个这样的地方之间，小像在画出来的线上匀着走——哪一天走到哪里没有记载，所以第二行开头先说“匀着走的：”。**只知道月份、季节的地方不切，也不管小像的步子**：小像照匀着走的步子经过它，经过的那一天可能同史料说的那个月差几天（熙宁四年去杭州的那一趟，小像经过润州比史料说的那个月早五天）。这一条是知道的、留着的：要它不差，就得给一个只知道月份的地方编一个日子。有位置的各处离这一段走的线不超过 25 公里（沿河的水路画在河的一边），先后和走的方向一样。

**路上一处的疑问也要让读者看得到。** 句子里说到的一处、把路切成一程一程的一处，它的 `note` 里写着另一种说法、对不上、是推出来的（“一本作、引作、录作、别本、又作、或作、一说、异文、对不上、推出来、也可能、差一天、两说”这些字眼），这一处要写 `unsure`，而且是 `note` 里连着的一截（只删字）。工具把它接在这一段的 `unsure` 后面，前面带上这一处的名字（“江陵：查慎行的《苏诗补注》引作十八日”）。

### 两行字

时间轴第一行是“哪一年、几岁、在哪”，如“元丰五年（1082）　虚岁四十七　在黄州”：年份和虚岁是程序照 `years` 表写的，“在哪”是这一段的 `label`。第二行是这一段的 `says`。第一行说的是当时的名字，读者选了“今名”也不换（“今名”只换题签上的名字）。

**括号里的公历年份。** 平常写这个农历年大半落在的那一年：“元丰五年（1082）”。一个农历年的最后几十天落在公历的下一年里（年底常常已经是下一年的一月、二月，有的年份十一月下半月就是了）：那些天括号里写那一天公历的年和月——“景祐三年（1037年1月）”——不然读的人看到的是“1036”，而他生在 1037 年 1 月。写了月份，“某年某月、在某地”也要是史料担保得了的：这一段在那个月里是不是已经开始、是不是还没结束，史料担保不了的，那些天不写月份，照平常只写年份。苏轼的行迹里有两处这样：回汴京的路上，治平元年末写“治平元年（1064）”；在密州，熙宁九年末写“熙宁九年（1076）”。哪几处，工具算出来写在时间轴用的那一份里（`plainMonths`）。

- `label` 里要有数据里这个地方的名字：住在一站的、站在有名字的地方的，是那个地名点的名字；站在线上没有立名字的地方的，是 `where` 开头的地名；路上的，是 `to`。
- `says` 开头的半句照这一段是哪一种写：

| 这一段 | 开头 | 例子 |
|---|---|---|
| 路上（`road`） | 匀着走的： | 匀着走的：正月初一出汴京，十八日在蔡州道上，二月一日到黄州 |
| 沙盘上没有他（`edge-strip`、`on-ways`、`none`） | 头一个半句里说“沙盘上没有他” | 这一趟没有画，沙盘上没有他。六月二十日过海，七月初到廉州 |
| 别的（`stop`、`stop-point`、`place`、`way-vertex`） | 不用开头 | 元丰三年二月一日到，元丰七年四月离开 |

  小像站在沙盘上的一段，句子里不能说“没有他”“没有标出”。地方说“没有标出”，路说“没有画”。站在线上没有立名字的地方的一段（`way-vertex`），句子里不许再说“沙盘上没有立某地的名字”：他站到那里的时候，旁边立着那一处的名字。
- `label` 里不写日子（第一行的年份是程序照 `years` 表写的）。
- **句子里的日子只许删，不许添。** `says` 里的每一个日子都列在 `saysDates` 里，照日子的先后列，句子里也照这个先后说。校验查这几样：
  1. **只许整截地删。** 史料的写法拆开来是一截一截的：年号、第几年、几月、哪一天、季，数字连着它的单位是一截。句子里的写法要是那个日子的 `text` 删掉几截来的，不添、不换，先后不变：“元丰二年七月二十八日”可以说成“七月二十八日”，不能说成“七月八日”；“十二月”不能说成“二月”。留着年号的，它后面的“第几年”也要留着。
  2. **“以前、以后、或、之间、初”不许删**（删了，说出来的就比史料知道的还细）。史料的写法用逗号分成两个半句的，只用到前一个半句，后一个半句里的词不用带。留着“以前”“以后”的，史料的写法里它前面紧挨着的那一截日子也要留着：“六月十七日以前”删成“元符三年以前”，“以前”就挂到年份上去了，说的是另一个日子。
  3. **删掉的年份、月份，读的人是拿前面的来补的，补出来的要正是史料写的那个日子。** 句子里一个日子删掉了年份的，它的年名要和句子里前一个日子的（史料写的）一样；头一个日子删掉了年份的，要和这一段开始摆出来的那个农历年一样（第一行印着的那一年），而且这一段在时间轴上不能跨着正月初一（第一行先后印着两个年名，读的人会拿后一年去补）。只删了年号、留着第几年的，年号要一样；删掉了月份还说着哪一天的，年名、月份都要和前一个日子的一样。
  4. **日子旁边不添字。** 日子后面紧挨着的只能是“到、离、出、在、过、回、被、坐、快、动”里的一个字，或者逗号、分号（单子上没有“因”：句子说他做了什么，不说为什么）；前面紧挨着的只能是句子的开头、“在”，或者冒号、逗号、分号、句号。“四月初离开”“四月底”“二月一日前后”“四月（1084）”都通不过。这两张单子（`tests/content/itineraryRules.ts` 的 `AFTER_DATE`、`BEFORE_DATE`）是照现有的句子定的；句子确实要用别的字接在日子后面，先看接上去以后说的还是不是那个日子，再往单子里添。
  5. **没有列的日子不许有。** 列过的去掉以后，句子里不能再有像日子的字眼：“三月”“八日”“七年”、阿拉伯数字、“初八”“上旬”、节令和二十四节气、“春夏秋冬”；岁数；多久（“三个月”“六十天”“半年”“数月”“三载”）；靠着别的日子说的（“次年、明年、去年、前后、翌日、是年、当天、同年、年底、月初”这一类）；干支记的日子；年号后面紧跟着“初、末、中、间”的（“绍圣初”）。“三天竺”（杭州的地名）和“度岁”指名放过。**这张单子是一张网，不是证明**：网眼里漏得过去的说法总还有。
- `first`、`last`：时间轴拖到最前、最后时的两行字。`label` 里要有头一段、最后一段的那个地方；句子里的日子同样列在 `saysDates` 里，`first` 的只能指头一段的 `start`，`last` 的只能指最后一段的 `end`；`last` 的句子里写了“虚岁多少”的，要是 `years` 表最后一年的岁数。只放图片的设备上，最前一个位置的第二行后面多半句“；图片上没有他的小像”（时间轴自己添的，不在数据里）。
- **句子里的地方、做了什么事、住了多久，校验管不到，靠读。** 规则查的是日子。把“到”和“离开”说反了（日子的先后没有错）、把一个地方的经纬度写到了别处、句子里说他在那里做了什么，规则看不出来；改了句子、改了位置，都要有人对着出处读一遍。路上各处的位置、哪里算说得准，也是这样。两行字也不说他为什么做一件事（只说做了什么）：苏轼的那一份另有一条测试守着，`label`、`says` 里没有“因”“为了”“以便”“等……”这样的字；月日没有查到的日子，`text` 只写到年，年份后面不添“初”“末”；读者在时间轴上看得见的每一段话（第二行，“图例”里说不准的）里，说到“查注”以前先写出书名（查慎行的《苏诗补注》），一段话里再说到才叫“查注”。

### 农历年的表（years）

一行是一个农历年：`year`（公元年：这个农历年大半落在的那一年，时间轴第一行括号里平常印的就是它）、`name`（年名，如“元丰三年”）、`newYear`（这一年的正月初一是公元哪一天，儒略历）、`age`（这一年他虚岁几岁）。头一行是他出生的那一年，`newYear` 写 `null`，虚岁一岁；后面一年接一年，一直到他去世的那一年。年中改了年号的年份，整年用后来的年号。

校验查这张表自己说不说得通（一年只能是 353、354、355 天，或者有闰月的 383、384、385 天；年名接得上；虚岁每年加一），再拿行迹里的每一个日子来对：`text` 开头写的年号纪年，要和照它的公元日子在表里查到的年名一样；精确到日的写法里的月、日，要和它的公元日子离那一年正月初一的天数对得上——“正月初一”“元日”就是表里的正月初一，正月某日是它后面的第几天，“除夜”是下一个正月初一的前一天，别的月份落在“一个月 29 到 30 天、前面至多一个闰月”算出来的范围里。

苏轼的表是照中央研究院《两千年中西历转换》换算的（出处 `cal`）。**校验只能查到上面这些**：表里没有日子落进去的年份（六十六年里有三十七年），正月初一整整错一个月，规则是看不出来的；差一天也看不出来。所以这张表和每一个公元的月日，改过以后要对着历表读一遍：**由负责人在发布以前对**（制作的人不向外面的网站发请求）。上一回是 2026-11-24：六十五个正月初一、五十四个精确到日的日子，和查历表时存下来的页面一个不差；范围的两头没有对过，也没有另找一份历表对。`npm run validate` 里有一项记着那一回以后这些日子和这张表的一个记号：谁动了一个字、一个数，它就通不过，话里说“先对着历表核一遍，再把这里记的数换掉”。

### 头尾放在哪一天

每一段的头尾要放到时间轴上的某一天（`tests/support/itineraryTool.ts` 的 `boundaryNumbers`）。这一天从不显示成日子：

1. 精确到日的，就是那一天；
2. 前后两个日子范围一模一样的，照 `sharesWindow` 匀着排在范围里（两个的话，三分之一处、三分之二处）；
3. 范围里有一个正月初一的，放在那个正月初一上；
4. 别的放在范围的正中间。

一个范围里最多一个正月初一，共用的范围里不能有。这样，一段在时间轴上碰到的每一个农历年里，它一定已经开始了、也一定还没有结束：第一行印出来的“某年、在某地”，都是史料担保得了的。校验把这一句对着每一段再查一遍（规则 22 第六句）；括号里写了公历月份的那些天，照同样的办法一个月一个月地比，担保不了的月份不写（见“两行字”）。

### 时间轴用的那一份（itinerary.bar.json）

工具照手写的那一份做的（`npm run itinerary`），**不手改**；手写的那一份改了，重做一遍，两份一起提交。校验会拿它和现做的比，差一个字就通不过。一行，不缩进。它跟着时间轴的那一段程序走（栏里摆上全程沙盘才下载），不在页面一打开就下载的程序里。

| 字段 | 含义 |
|---|---|
| `day0` | 第 0 天：他出生的那一天（公元，儒略历）。下面的“第几天”都从它数起 |
| `name` | 这位人物的名字，照 `figure.json` 的 `name` 抄（时间轴给读屏念的名字、首页第一行开头的名字、“图例”里说小像是谁的那一句） |
| `years` | 农历年，每一行四样：公元年、年名、正月初一是第几天（头一行是 `null`）、虚岁 |
| `first` `last` | `label`、`says` 原样抄来（`saysDates` 只是校验用的，不抄） |
| `stretches` | 每一段（见下） |

每一段：`id`、`label`、`says` 原样抄来；`unsure` 是这一段的，后面接着路上那几处的（各带着那一处的名字），空的不写；`group` 就是 `stopYearsOf`（没有的不写）；`until` 是这一段到第几天为止（可以带小数）；另有：

| 字段 | 含义 |
|---|---|
| `look` | 时间轴上这一段画成什么：`stop` 住在一站讲的地方；`road` 在画出来的路上；`quiet` 沙盘上有这个地方、不在哪一站住下来的年月里；`off` 沙盘上没有他 |
| `plainMonths` | 第一行括号里只写年份的公历月份，一项是 `[年, 月]`（见“两行字”）。没有的不写 |
| `place` | 小像站在哪个地名点上（`stop`，和站在有名字的地方的 `quiet`） |
| `spot` | 小像站在一条线上没有立名字的一处（另一种 `quiet`）：那截路的 `id`，这个地方的经纬度，它的名字，有今名的再加今名 |
| `ways` `dashed` | 这一段走的路，照先后，倒着走的前面一个减号；各截是不是示意的（`road`） |
| `legs` | 路上精确到日、又有位置的各处：经纬度，和那一天是第几天 |

`off` 的一段三样位置都没有；别的各段正好有一样。圆点旁边不写各站的年份（文字栏的目录里每一站都写着），这一份里也没有那几个年份。

## 制作时做好的两样：先画好的地面，每一小节的定格图

这两样都是工具照着场景文件和沙盘程序做出来的，做好以后放进仓库，随网站一起发；发布的流程不重新做。**清单和图片都不手改**：要改，改场景文件或者程序，再重新做。

两条命令，先后不能反，都会打开一个浏览器（同一时刻只能开一个，所以不要和 `npm run test:e2e` 同时跑）：

1. `npm run bake`：给每座沙盘的地面上色，存成两张图，放进 `baked/`。一座沙盘十几秒。地面没有变时什么也不写，再跑一遍文件一个字节也不变。
2. `STILLS_OUT=content/figures npm run stills`：把每座沙盘的每一小节拍成定格图，放进 `stills/`，用的是完整的画质，地面用的是第 1 条做好的那一份。一座沙盘半分钟上下。画面没有变的图片不重写：在同一台机器上连拍两遍，第二遍一张也不动。不带 `STILLS_OUT` 的 `npm run stills` 只是试拍，图放在 `tests/shots/stills-trial/`（不进仓库），不动 `content/`。每次拍完在 `tests/shots/stills/` 里留下一页给人看的（`<人物>-<站>.html`，不进仓库），画面变了的那几张有标记，人只看变了的。（`STILLS_OUT=…` 放在命令前面是 bash 的写法；PowerShell 里先写 `$env:STILLS_OUT = 'content/figures'`。）

**正在做的沙盘。** 一座新沙盘是分几步接进来的：场景文件先进 `content/`，沙盘程序画得出它以后才做得了这两样。中间这一段，把它的名字（“人物/场景文件的名字”，如 `su-shi/route`）写进 `tests/support/pendingTables.ts` 的 `MADE_FILES_PENDING`：校验不要求它有这两样（已经有的照规则查），上面两条命令跳过它。要给表里的沙盘做这两样，带着 `INCLUDE_PENDING=1` 跑（`INCLUDE_PENDING=1 npm run bake`，`INCLUDE_PENDING=1 STILLS_OUT=content/figures npm run stills`）。两样都放进 `content/` 以后把名字拿掉；这张表平时是空的。名字忘了拿掉的话，“定格图旧不旧”那一项不再查这座沙盘，两条命令也跳过它，所以另有一条检查守着：表里的沙盘，两份清单要是都已经在 `content/` 里了，`npm run validate` 通不过，说把名字拿掉（`tests/content/routeRules.test.ts`）。

**什么时候要重做。** 改了场景文件里管地面的部分（范围、地形、水、摆件、点缀）、地形文件、地面上色的程序或样式里地面的颜色：两条都重做。改了镜头、题签指的点、沙盘程序里别的地方、样式里的光或模型的大小：只重做第 2 条。只改了依据、说明、题记、题签上的字：都不用重做。

**忘了重做会怎样。** `npm test`（不是 `npm run validate`）里有两项检查，发现存着的图比做它的东西旧，就不通过，并且说出是哪一样变了、该跑哪条命令：

- “徐州先画好的地面是旧的：照现在的场景和程序重画，颜色和存着的不一样。运行 npm run bake，再提交。”
- “徐州的定格图是旧的：沙盘程序改过了（……）。运行 STILLS_OUT=content/figures npm run stills（见 README），再提交。”

照着做的时候：地面旧了，先跑 `npm run bake`，再跑 `STILLS_OUT=content/figures npm run stills`（定格图是在地面上拍的，地面变了它也算旧的）；只是定格图旧了，跑后一条。不带 `STILLS_OUT` 的 `npm run stills` 只是试拍，检查还是通不过。重做以后，`baked/`、`stills/` 里变了的文件同改动一起提交。

页面自己也防一手：先画好的地面和手里的场景、地形文件对不上时，打开时现画（开发机上慢一秒上下），不用旧图，并且在控制台里说一句“先画好的地面用不上”。

### 先画好的地面（`baked/`）

| 文件 | 是什么 |
|---|---|
| `<站>.colour.jpg` | 地面的颜色。JPEG；每 10 米一个点，第 0 行最北，第 0 列最西 |
| `<站>.fields.png` | 哪里是田、田有多重。8 位灰度的 PNG，和颜色一样大。田垄是页面上画的，这张图只说哪里画 |
| `<站>.json` | 清单 |

山的明暗不存成图：页面打开时照地面现算，只要十几毫秒，光换了也不用重做。

**全程沙盘的这两张图**文件名一样（`route.colour.jpg`、`route.fields.png`、`route.json`），有三处不同。一、地面的一格画三个点（站点沙盘两个）：它的一格是地上的三公里多，海岸、河都是画在这张图上的，两个点画不出来；苏轼的全程沙盘网格是 586 × 662，图是 1756 × 1984。二、第二张图记的不是田，是水面上哪里画水纹、多重；名字还叫 `fields`。三、页面打开时不现画：上色的程序是一个工具（`tests/tools/route/paint.ts`），不随网站发；图是照旧的场景或者旧的地形文件画的时候也照样用，在控制台里说一句；图没有、取不到、大小不对，这座沙盘就摆不出来（页面放图片或者一句话）。“今天的海岸、湖、河”那个文件也是上色用的，它没有记号，改了它要靠 `npm test` 里重画一遍才看得出来。

苏轼的全程沙盘量到的数（2026-11-20，浏览器压的；留白的边打散、河口和水纹改过以后）：颜色压成 JPEG 的质量是 0.90，560,935 字节，清晰度 37.21 分贝；水纹的标记 75,228 字节；地形文件 592,800 字节；三个文件合计 1,228,963 字节，是上限的 78%。（改以前是 570,510 字节、37.05 分贝、60,834 字节，合计 1,224,144 字节。）质量 0.95 时颜色是 839,584 字节（38.67 分贝），三个文件合计到上限的 95%，所以不用。清晰度的下限另定一个数，36 分贝：比浏览器在这个质量上压出来的低一分贝（站点沙盘的 40 分贝，这张图要 1.5 MB 上下才到得了）。山上那些两个点宽的细纹压过以后淡一些，哪一档质量都一样，和徐州的情形相同。

颜色那张图的质量是 0.95（`tests/tools/bake-ground.test.ts` 里的 `JPEG_QUALITY`），是对着图片定的：贴近了看的“水退以后”一节，用先画好的地面和现画的地面各拍一张，一个点最多差 7 级（一共 255 级），看不出来。徐州现在的大小：颜色 279,735 字节（清晰度 41.36 分贝），田的标记 254,181 字节，连同地形文件 277,220 字节，合计 811,136 字节，上限 1,572,864。JPEG 存颜色只用一半的分辨率，所以山坡上很细的赭色笔触比现画的淡一点；质量调到 0.97（394,725 字节）、0.99（586,307 字节）也是这样，所以没有调高。

清单的字段：

| 字段 | 含义 |
|---|---|
| `tool` | 清单格式的版本，现在是 1 |
| `inputs.ground` | 场景文件里管地面的那一部分（样式、范围、地形、水、摆件、点缀）的记号（其中的依据、出处、说明这些字不算） |
| `inputs.terrain` | 地形文件的记号 |
| `pixels.colour` `pixels.fields` | 画出来的颜色、田的标记（压缩以前）的记号。检查“旧不旧”时照现在的场景和程序重画一遍，和它比 |
| `colour` | 颜色那张图：`file` 文件名，`width` `height` 宽高，`bytes` 字节数，`key` 文件的记号，`quality` 压缩的质量（0 到 1），`psnr` 压完以后和原来比的清晰度（分贝，越大越接近） |
| `fields` | 田的标记那张图：`file`、`width`、`height`、`bytes`、`key` |

“记号”是照内容算出来的 16 个字符（0 到 9、a 到 f）：内容变了，记号就变。

### 每一小节的定格图（`stills/`）

每一小节两张，都是 JPEG：

| 形状 | 文件名 | 图片大小（像素） | 照哪种画面拍的 |
|---|---|---|---|
| 宽的 | `<站>-<第几节>-wide.jpg` | 1800 × 1350 | 1440 × 900 的电脑窗口：沙盘栏 940 × 900（左边有一像素的边线，放画面的那一块是 939 × 900），左右各多拍 130.5 |
| 窄的 | `<站>-<第几节>-narrow.jpg` | 1920 × 1144 | 竖着拿的 768 × 1024 平板：沙盘栏 768 × 573（屏幕高度的 56%；下边有一像素的边线，放画面的那一块是 768 × 572），左右各多拍 96 |

“第几节”从 1 数起，和场景文件里小节的先后一样。文件名里不用汉字，也不带文件夹。

竖着拿的大平板（1024 × 1366，沙盘栏 1024 × 765）也是上下排的版面，放的是窄的那一张，照栏的高放大到 1.34 倍（写了 `closest` 的小节更大一些），左右铺得满；这时一个页面像素合 1.4 到 1.5 个图片像素。

用在三处：立体的沙盘还没摆好时先显出来；浏览器画不了、设备太慢或画面中途断了时代替立体的沙盘；每座沙盘拼成一页给负责人看。**图上没有字**：题签还是页面上的字，照清单里记下的位置摆，所以定格图上古名、今名照样能换，题签照样互相避让。

清单（`stills/<站>.json`）的字段：

| 字段 | 含义 |
|---|---|
| `tool` | 清单格式的版本，现在是 1 |
| `made` | 拍的时候的情形：`tier` 画质（`full`），`three` 画图用的库的版本，`background` 沙盘栏的底色，`fitMarginPx`、`maxFit` 镜头用的两个数 |
| `madeFrom` | 照什么拍的，四个记号：`scene` 场景文件里决定画面的部分（依据、说明、题记、名字、题签上的字、远处照当时人的话写的那一句 `inHisWords` 不算），`terrain` 地形文件，`ground` 先画好的地面，`program` 沙盘程序和拍照的工具 |
| `shapes` | 两种形状各是照什么画面拍的：`window` 窗口，`pane` 沙盘栏，`insets` 四边留的空（上、右、下、左），`extra` 左右各多拍多少，`pixelRatio` 像素比 |
| `stills` | 每张图一项（见下） |

每张图：

| 字段 | 含义 |
|---|---|
| `section` | 小节标题 |
| `shape` | `wide` 或 `narrow` |
| `file` `width` `height` `bytes` `key` | 文件名、宽高、字节数、文件的记号 |
| `quality` | JPEG 的质量（0 到 100）。工具从高往低试，取第一个不超过 300 KB 的：宽的依次试 82、78、74、70、66，窄的依次试 86、82、78、74、70，最后一个还超就停下来不写。徐州的十四张都用的是头一个数，每张 112,123 到 248,036 字节，合计 2,806,117 字节 |
| `raw` | 压成 JPEG 以前那张截图的记号。重拍时这个记号没变，图片文件就不动 |
| `pose` | 镜头真的在哪：`target`、`position`（沙盘里的米）、`fov` |
| `fit` | 镜头离对准的那一点，是场景里写的距离的几倍 |
| `reach` | 这一节一定要看得见的点，离画面留出来的那一块的中心最远多少像素：横、竖 |
| `northDeg` `pxPerMetre` | 指北针转多少度；画面中心一米是多少像素。指北和比例尺照它们画 |
| `anchors` | 这一节每条题签指着的那一点，按题签的先后：`id`；`x`、`y` 是那一点在整张图的哪里（从左上角量，占宽、高的几成）；`visible` 看不看得见；远处的题签另有 `out`（朝外的方向）；抬高了的另有 `foot`（它脚下的地面在图的哪里） |

别的窗口大小用的也是这两张图：页面照立体沙盘摆镜头的办法把图放大、缩小、挪位置，题签的位置跟着算。

**黄州的两样**（2026-11-23，这座沙盘做完、检查以后改过时）。先画好的地面：颜色 901 × 901，176,618 字节，质量 0.95，清晰度 42.41 分贝；田的标记 64,422 字节；连地形文件（193 列 × 195 行，75,270 字节）合计 316,310 字节。定格图：九节，宽、窄各一张，一共十八张，`huangzhou-1-wide.jpg` 到 `huangzhou-9-narrow.jpg`，合计 3,007,305 字节，每张 120,111 到 227,555 字节，都是头一个质量（宽的 82，窄的 86）。夜里的三节（第 6、7、8 节）六张 126,315 到 152,805 字节。

**全程沙盘的定格图**（苏轼，2026-11-20）：九节，宽、窄各一张，一共十八张，`route-1-wide.jpg` 到 `route-9-narrow.jpg`，清单是 `stills/route.json`。拍的时候工具打开的是人物页（站点沙盘打开的是那一站），量到的沙盘栏和徐州的一样（宽的 939 × 900，上、下留 62、130；窄的 768 × 572，留 54、131）。图上有路，没有题签和印（题签和印是页面上的字，照清单里记的位置摆，所以放着图片的时候印照样按得动）。合计 4,347,584 字节，每张 162,121 到 298,402 字节。十五张用的是头一个质量（宽的 82，窄的 86）；山多、路多的三张降了级：“出川”宽的 298,402 字节（质量 78，第二级），窄的 275,379 字节（质量 78，第三级），“到黄州”窄的 265,495 字节（质量 82，第二级）。“出川”宽的那一张离 300 KB 的上限只有 8,798 字节：再动那一节的镜头或者路，它可能要降到 74。看路的图片比徐州的压得重一些（徐州十四张都在头一级），并排看会软一点。“全程”那一节是 224,884 和 162,121 字节。

立体的沙盘接替图片的那一下，题签挪不挪（2026-11-20 量的，人物页、出川、到黄州三处）：电脑（1440 × 900）和竖着拿的平板（768 × 1024）上不挪，一个像素也不差——栏和拍图时一样大；横着拿的平板（1024 × 768）上“全程”那一节最多挪 7.1 像素、“出川”4.1 像素；竖着拿的大平板上“全程”最多 3.2 像素。和上面徐州的情形是一回事：宽的那张图是照 939 × 900 的栏拍的，缩放了摆进别的栏，取景差几个像素。首页宽屏上的栏（800 × 900、553 × 768）用的也是宽的那一张，同样是缩放了摆上去的，接替的那一下差多少没有量。

**水纹照页面上的像素算。** 水面上的白色水纹和急滩的白浪，疏密、粗细都照页面上的像素算，不照画布的像素（`src/stage/three/water.ts` 的 `setPixelRatio`；画布这一帧用的像素比由 `view.ts` 每一帧告诉它）。定格图宽的照像素比 1.5 拍、窄的照 2 拍，读者的屏幕可能是 1、1.5、2：照画布的像素算的话，像素比不一样，水纹就落在不一样的地方，立体的沙盘接替定格图的那一下，白线会跳。量过（徐州“住在城墙上”，图片和接替它的沙盘比，颜色差 17 级以上的点占多少）：电脑上像素比 1、1.5、2 是 1.9%、1.8%、2.0%，竖着拿的平板像素比 2 是 1.1%；改以前是 5.1%、2.1%、7.0% 和 1.1%。像素比是 1 的屏幕上，立体的沙盘和改以前一个像素不差。这几个数是在定格图自己那么高的栏上量的（电脑 1440 × 900 的窗口，竖着拿的平板 768 × 1024）：栏是别的高矮的时候，定格图是缩放了才摆上去的（宽的那张照栏高 ÷ 900，窄的照栏高 ÷ 572），图上的水纹跟着缩放，立体的沙盘的水纹不缩放，接替的那一下白线还是会有一部分换地方。横着拿的平板也量了（1024 × 768 的窗口，像素比 2，栏 584 × 768，题记以上的那一块）：“住在城墙上”改以前 6.6%，现在 5.1%；“到徐州”14.5%、“云龙山和百步洪”20% 上下，改前改后一样。那里差的主要不是水纹：宽的那张定格图是照 939 × 900 的栏拍的，缩放了摆进 584 × 768 的栏，和立体的沙盘的取景差几个像素，整幅画面在接替的那一下会轻轻挪一下——电脑和竖着拿的平板上没有这回事（栏和拍图时一样大）。这是做定格图那一步留下的，这里没有动；横着拿的平板是头一个要在真机上看的地方。1366 × 768 的笔记本没有量，照算法推水纹比改以前好一半左右。要把水纹也治到底，得让定格图摆上去的缩放进到水纹的疏密里，那会改水纹的样子，没有做。地面上田块的细线（`terrainMesh.ts`）还是照画布的像素淡出的，接替的那一下也会有淡淡的出入，没有动。着色器里新添量像素的地方（`fwidth`），也要乘上这个像素比（`tests/stage/scene-budgets.test.ts` 数着）。

## 随站的字体

网站自己带着三套字体：黑体是 Noto Sans SC 的 Medium（思源黑体的谷歌发行版，粗细 500），宋体是 Noto Serif SC（思源宋体的谷歌发行版），楷体是霞鹜文楷 GB。打开网页时不向别的网站要字体。三套都只带网站用到的字，由工具做好放进仓库（`src/fonts/`），随网站一起发；发布的流程不重做。**这些文件都不手改。**

黑体的文件是 2026-11-24 添的（第 51 条）：框架换成了中性的样子，标题、标签、按钮、年份用黑体，成句的话还是宋体。楷体从那一天起只有沙盘上的题签和题签脚上的印在用：它是苏轼这位人物自己的，不是框架的。

| 文件 | 是什么 |
|---|---|
| `yanlu-sans.woff2` | 黑体里网站用到的字（粗细 500） |
| `yanlu-song.woff2` | 宋体里不用点开就看得见的字 |
| `yanlu-kai.woff2` | 楷体里网站用到的字 |
| `yanlu-song-more.woff2` | 宋体里点开才看得见的字。页面上用到其中的字时，浏览器才下载它 |
| `fonts.css` | 四条 `@font-face`，粗细写的是那套字体自己的那一种（黑体 500，别的 400）。点开才要的那个宋体文件带一条 `unicode-range`，逐个列着它里面的字，浏览器靠它知道什么时候该下载 |
| `fonts.json` | 记录：每个文件里有哪些字、多大、是照哪个原字体做的（字段见下） |
| `shipped.ts` | 给“来源”页用的一张表：三套字体的名字、版本、网址、许可文件叫什么。`src/` 里只有“来源”页的那一块程序引它，这张表就跟着那一块走，不在页面一打开就下载的程序里（`npm test` 和 `npm run check:size` 守着；第 52 条） |
| `probe.ts` | 页面一打开就下载的程序用的几样：宋体和楷体写在字体文件里的名称（页面叫浏览器先去取字体的时候要说名称；页面的程序里不另写一遍），和点开才要的那个宋体文件里的一个字 |

下面说“第三个文件”的地方，指的都是点开才要的那个宋体文件（`yanlu-song-more.woff2`）；“头两个文件”是 `index.html` 里预先声明的两个：黑体和头一个宋体文件。

文件里的字体名称是“Yanlu Sans”“Yanlu Song”“Yanlu Kai”，不是原字体的名字：裁剪过的字体不是完整的字体，霞鹜文楷的许可也要求改过的版本不用它保留的名字（“Noto”是 Google 的商标，也不写进名称里）。黑体的 PostScript 名称是 `YanluSans-Medium`，文件里写的粗细是 500。原字体的版权声明原样留在文件里。三份许可的全文在 `public/licences/`（`noto-sans-cjk-OFL.txt`、`noto-serif-cjk-OFL.txt`、`lxgw-wenkai-gb-OFL.txt`；黑体和宋体的两份是同样的字，各放一份，各用各的名字），同一个文件夹里还有页面用到的两个程序库的许可全文（`react-LICENSE.txt`、`three-LICENSE.txt`），都是工具照原样抄来的：一共五份。

### 哪些字归哪个文件

不靠人列字表。工具照页面自己的程序去数（`tests/support/fontTool.ts`）：正文用页面解析正文的那段程序读，沙盘旁边的字、题签、“沙盘上的东西”一栏用页面生成它们的那几个函数算。分四组：

| 组 | 放进 | 有什么 |
|---|---|---|
| 用黑体排的 | `yanlu-sans` | 界面上用黑体排的固定的字（`src/ui/text.ts` 的 `SANS_LABELS`：标题、按钮、小标签、“第 站 · 共”、“关闭”、加号和减号、“上一站”“下一站”、比例尺上的数和单位……）；沙盘上东西的五个类别名；人物的名字、朝代和年份；各站的标题和短标题，每一站的年份、地点和年纪；小节标题（正文里的、沙盘旁边的、凭据里的）；小注的标题；沙盘旁边每一小节的时间；空格；省略号（工具自己添的：一行黑体的字被截掉时行尾要用）。没有英文字母：框架里用黑体排的字，程序现拼的只有数字和单位，名字、标题、时间都是内容里来的；时间轴第一行的字——人物的名字、行迹里农历年的年名、每一段的 `label`（连 `first`、`last` 的）；时间轴上固定的字（`src/timebar/barText.ts`，经 `SANS_LABELS`：播放、暂停、上一段、下一段、图例、“进第 站”、虚岁、岁、全角的括号、“年”“月”……）；凭据里“记号”这个栏名 |
| 沙盘上用楷体写的 | `yanlu-kai` | 题签上的字（古名、今名两种叫法都算，照页面拼题签的函数数）；全程沙盘上站名的题签脚上写着第几站的印上的字（照页面拼印的函数数）；空格。别的都不在：界面上没有哪个字是楷体的。现在这一组里没有标点，也没有省略号（题签不截）；小像站在线上、沙盘平时没有立名字的一处的时候旁边立出的名字（行迹里那几处的 `name`、`modern`） |
| 不用点开就看得见的 | `yanlu-song` | `src/` 里的程序写着的每一个字，和 `index.html` 里的字（注释不算）；首页的人物卡片；人物页上的字（人物资料、各站的抬头）；每一站的正文；原文的标题；图片的题记、作者和许可；沙盘旁边每一小节的小节名、时间、题记、远处的那句话、那一句说明的两种写法；英文字母、数字和半角的符号，一个不落。另外，楷体那一组的每一个字这里也放一份（楷体的文件还在路上时题签先用宋体显示，不能为这个去下载第三个文件）；黑体那一组的每一个字这里也记一份：黑体的字不管点没点开都归这一组（小注的标题点开才看得见，也在这里）。现在的内容里这些字本来就都在这一组，文件没有因此多一个字；行迹里每一段的 `says`（连 `first`、`last` 的） |
| 点开才看得见的 | `yanlu-song-more` | 小注（标题、正文、出处）；原文的时间、原文和白话；凭据的每一条和它的出处；“沙盘上的东西”一栏；点“说明”展开的那几句；讲解员面板里的示例问题；图片的 `alt`。“来源”页上的话（`src/ui/sourcesText.ts`：读者从链接点进那一页才看得见；哪几个程序文件这样算，列在 `tests/support/fontTool.ts` 的 `PRESSED_SOURCES` 里）。上一组里已经有的字不再放；行迹里每一段的 `unsure`；时间轴的“图例”里固定的几句（`src/timebar/barNoteText.ts`，也列在 `PRESSED_SOURCES` 里）；凭据里小像的那一栏（场景文件的 `piece`）；凭据里印出来的行迹的出处（手写的那一份的 `sources`：`cite` 和 `read`） |

“`src/` 里的程序”不算这三个文件夹：`src/ui/dev/`、`src/stage/dev/`（测试用的替身和开发时单看沙盘的页面，上面的字不是给读者看的），`src/fonts/`（工具做的）。

行迹的字，工具读的是做好的那一份（`itinerary.bar.json`）和手写的那一份的 `sources`。时间轴第一行的几截之间的空是样式留的，不是一个全角空格的字（字体文件里没有它）。

工具分不清程序里的一句话是不是给读者看的，所以宁可多带：只印在浏览器控制台里的话、出错时的话都算了进来。只有一样不算：着色器的程序是写在字符串里的（`src/stage/three/` 和 `src/stage/ground/` 两个文件夹里的模板字符串），它里面“//”到行尾是着色器自己的注释，谁也看不到，工具认得这两个文件夹，数字的时候把这些注释去掉（`tests/support/fontTool.ts` 的 `SHADER_DIRS`；这两个文件夹里出错时的话、印在控制台里的话照旧算）。只在程序里写着、内容里没有的字记在记录的 `onlyFromSrc` 里（头一个宋体文件现在记着 17 个：× − 丢 备 展 帧 扮 暂 机 栏 毫 浏 疑 秒 配 闭 降；黑体的文件记着 4 个：− 展 暂 闭）；其中有读者看不到的，只在出错时的话和印在控制台里的话里。代价除了这点大小，还有一条：在控制台的话里添一个字体里没有的字，`npm test` 也会通不过，要重做字体才行；在着色器的注释里添字不会。原来着色器的注释也算，头一个宋体文件因此多带过 15 个字（垄 埂 屏 幕 总 纹 绿 藤 赭 九个哪里也用不到；主 壕 急 略 组 续 六个点开才看得见，现在在第三个文件里）。

几条规矩，都由 `npm test` 查：

- **界面上的字要原样写在程序里。** `src/` 和 `index.html` 里不用 `\u` 一类的转义、HTML 实体（`&nbsp;` 这样的写法）、`String.fromCharCode`、`String.fromCodePoint`，也不用 `Intl` 和 `toLocale` 打头的那些函数（它们会现造出程序里没写着的字）。工具只认得原样写着的字。
- **样式表的 `content:` 里不写字。** 工具不看样式表。要画一个记号，要么用边框和底色画（小节标题上面的短线、位置那一行中间的一小段线、抬头里的一排小圆圈），要么把它写成页面上真的字：“读原文”“凭据”那一行前面的加号、减号就是页面上的两个字（`src/ui/StopText.tsx` 的 `FoldSummary`），样式表只管折着显加号、点开显减号。减号（−，U+2212）因此在头一个宋体文件里。
- **题签上的字里不能有弯引号**（“ ” ‘ ’）：这套楷体里它们只有三分之一个字宽，和别的字对不齐。题签里要用引号，换个说法，或者先问一声。（标题、小节名现在是黑体，不归这一条管。）
- **原字体里没有的字**：工具停下来，把它列出来。改掉这个字；实在要用，把它连同理由记进 `tests/support/fontTool.ts` 的 `FALLBACK_OK`，它就用设备自带的字显示。现在一个也没有。

题签上的字在“沙盘上用楷体写的”那一组里，所以“题签用到的字都在随站的字体里”这一条也就查到了。

### 页面怎么用这三套字体

- **两套记号，三个字体的记号。** `tokens.css` 里的记号分两套：框架的一套写在 `:root` 上，人物自己的一套（沙盘栏的底色，题签的纸条、字、印、引线的颜色，题签的字体 `--figure-font`）写在文件末尾的 `.stage-pane` 上；框架的样式不读人物的那一套，题签的样式只读人物的那一套（`npm test` 扫样式表守着）。框架的字体是两个记号：`--font-song` 排正文和每一句成句的话，`--font-sans` 排标题、名字、标签、按钮和单独摆着的日期、数字（“时间”“地点”“年纪”这些也是）；题签和印用人物自己的 `--figure-font`，苏轼的是楷体。记号里排在随站的字体后面的是设备自带的字体，只在文件还没到、没取到的时候顶一下：黑体后面是设备上的黑体，宋体后面是设备上的宋体；题签的楷体后面先是设备上的楷体，再是随站的宋体（平板上大多没有楷体，那里先用随站的宋体）。设备自带的黑体的名字只许写在 `:root` 上 `--font-sans` 这一个记号的值里。同一份扫描还守着这几条：题签不和别的东西写在同一条规则里；人物的那一块里不写框架的记号（沙盘栏上挂着状态类名的规则，像 `.stage-pane.is-wide`，也算这一块；说明那一块底边的影子用的 `--fade-…`、`--shade-…` 也是框架的记号）；`--font-song`、`--font-sans`、`--weight-sans` 只在 `:root` 上写；三个字体记号的值各是随站的那一套打头；黑体的粗细（`var(--weight-sans)`）只写在设黑体的规则里（一条规则里写了几次字体、几次粗细，都算最后写的那一次）；沙盘栏、画布、放题签的两层和题签自己的那一层（`.strips`）上不写粗细、排版功能和字距，紧挨在这几层下面的 `*` 上也不写（题签会接过去）。`src/main.tsx` 头一个引入的就是 `src/fonts/fonts.css`。
- **每套字体一种粗细。** 黑体只带了 500 这一种，宋体和楷体只带了 400。样式表里不加粗、不用斜体，也不许浏览器自己把字描粗（`font-synthesis: none`）。设黑体的每一条规则都在同一条里写上粗细（`font-weight: var(--weight-sans)`，这个记号是 500）；黑体的元素里面夹着一块宋体的时候，那一块自己写 `font-weight: 400`。漏写了粗细，字照样画得出来（只有 500 的那一个字形可用），可是浏览器算出来的粗细是 400：`npm test` 扫样式表查得到，浏览器测试也查。要显眼，靠黑体和宋体的分别、字的大小。
- **用黑体排的一段字里，只能有黑体文件里的字**（上面那张表第一行列的那些）。把别的字排成黑体，它会掉到设备自带的黑体上，一行里就有了两种字。所以一个元素要么整个是黑体，要么整个是宋体；一句宋体的话里不夹黑体的词。楷体只在题签上（`.strip`，连题签脚上的印）：框架的哪一处写成了楷体，浏览器测试通不过。界面上新添一个黑体的固定的词，要把它列进 `src/ui/text.ts` 的 `SANS_LABELS`，再运行 `npm run fonts`。
- **标点。** 全角的标点个个占满一个字宽，两个挨着也不挤紧——只有标题例外（见下）。Chrome 平常会把挨着的两个标点挤紧，iPad 上的 Safari 不会：不这样，同一段话在两边会断在不同的地方。靠的是两样。一、宋体和楷体的文件里没有带把标点挤窄的那几项排版功能（`halt`、`vhal`、`chws`、`vchw`、`palt`、`vpal`）：浏览器没有它们可用，想挤也挤不了。这一样在哪种浏览器里都管用，由 `npm test` 守着（文件里没有，说好留的名单里也不许有）。黑体的文件例外：它留着 `halt` 这一种（别的五种没有）；要是做出来的黑体文件里没有 `halt`，工具不肯写。二、样式表里的 `text-spacing-trim: space-all`：它管的是随站的字体还没到、设备自带的字体顶着的那一会儿（设备自带的字体里常有那几项功能），和所有黑体的字（文件里有 `halt`）——所以这一句不能当成没用的删掉。代价是两个标点挨着的地方看着松一点。**标题的例外**：一页的大标题和目录里各站的标题（`.page-title`、`.stop-title`）写着 `font-feature-settings: 'halt'`，标题里全角的冒号、顿号和间隔号只占半个字宽（“徐州：大水围城”冒号后面不空出一大块）；别的黑体的字都不开。在 Chromium 里量过（`tests/e2e/fonts.spec.ts`，字号 100 像素）：宋体的句号和后引号挨着是 200 像素，样式表里那一句写不写都一样；黑体的冒号和前括号挨着，照页面的写法是 200，去掉 `text-spacing-trim` 那一句是 150；开着 `halt`，“州：大”是 250，冒号和前括号挨着是 100；不开，“州：大”是 300；照字体的名字量和照 `--font-sans` 这个记号量是同样的数。楷体不量：题签上的字里没有标点（同一份测试照记录查，楷体的文件里一个全角的标点也没有；哪天题签上写进了标点，那一句通不过，那时再量）。宋体里的间隔号（·）和连接号（–）本来就不是一个字宽；黑体里的间隔号是一个字宽，标题上开着 `halt` 时是半个。
- **什么时候取。** 黑体和头一个宋体文件在 `index.html` 里预先声明，一打开网站就取。楷体的文件不预先声明：页面一知道沙盘栏要摆沙盘（沙盘的数据读出来了），就叫浏览器去取，不等图片和沙盘程序（`src/ui/StagePane.tsx`；2026-11-24 添的，第 51 条——原来要等题签摆出来浏览器才取，没有自带楷体的平板上，头一次打开时题签先是宋体、过半秒才换成楷体）。首页上就有全程沙盘，所以头一次打开首页时它比页面晚到一步；没有沙盘可摆的栏不取，“来源”页上没有沙盘栏，那一页不取它。浏览器测试把图片和沙盘程序压住来查：栏上还没有画面，楷体的文件已经来要了；前后只要一次（`tests/e2e/fonts.spec.ts`）。什么时候去取，不开浏览器也查（`tests/unit/page/pane-behaviour.test.tsx`，第 52 条）：沙盘的数据还在读的时候不取，没有沙盘可摆的栏不取，知道要摆哪一座了取一次；浏览器说没取成、或者取的时候当场出错，沙盘栏照旧摆出来。页面去取的时候要说字体的名称：楷体和宋体的名称、点开才要的那个文件里的一个字，都从 `src/fonts/probe.ts` 读（做字体的工具照记录写的），页面的程序里不另写一遍。第三个文件平常是页面上出现了它里面的字才取；写好了正文的站点页另外会在正文出来、头两个文件到了、又过两秒以后先把它取来（`src/ui/StopPage.tsx`），免得网慢的时候刚点开的小注里夹着几个设备自带的字。首页、人物页和还没写的站不取它：那里没有要点开的东西。
- **文件来得晚。** 四条 `@font-face` 都是 `font-display: swap`：文件还没到，字先用记号里后面的字体显示，到了再换过来，不空着。按钮上、标题上任何时候都有字（黑体没到时是设备上的黑体）。题签也一样：楷体的文件到之前，题签上的字先用设备上的楷体（没有就用随站的宋体）画，到了换成随站的楷体；换的前后每一条题签还在原处、还是那么大（差不过半个像素），由浏览器测试守着（`tests/e2e/fonts.spec.ts`，把楷体的文件压住再放行）。

- **正文那一栏里哪些是黑体。** 一页的标题、标题后面用键盘走到才显出来的“到沙盘”、小节标题、位置那一行、“第 4 站 · 共 8 站”、人物页抬头里的朝代和年份、“时间”“地点”“年纪”、“读原文”“凭据”和它们前面的加号减号、小注的标题和“关闭”、每一种小标签（还没写、正在看、历史、地理、他本人的话……）、“白话”、凭据里每一小节的名字、“沙盘上的东西”和它下面五个类别的名字、目录里各站的标题、圆点里的数字（一、二、三……）和标题下面时间地点年纪的那一行、“沙盘上看的几处”和那张单子里各处的名字和年份（正文还没写、有自己的沙盘的一站）、正文末尾的“回到各站目录”“来源”、贴着底边那一条里的“上一站”“下一站”和站名、“问讲解员”、讲解员面板的标题、“关闭”、里面的小标题、“你的问题”和“发送”。别的都是宋体，凡是成句的话：正文、引文、抬头里时间地点年纪后面的那几个字、标题下面的两句说明、目录里各站的摘要、“沙盘上看的几处”那张单子里各处的题记、小注的正文、原文、白话的正文、凭据的每一条和它的出处、沙盘上每样东西的名字和依据、讲解员面板里的话和示例问题。一行里两样都有的地方（时间地点、小注的抬头、“读原文”那一行、目录里的一站、讲解员面板的抬头），黑体的和宋体的各是并排的一块，不排在同一行字里；贴着底边那一条的两头，小字在上、站名在下，各占一行。
- **一页的大标题。** 黑体，竖着拿的平板上 36 像素；横排的版面上 34 像素，窗口 1400 像素宽起 40 像素（文字栏到 1389 像素宽才长到头）。标题里的全角标点只占半个字宽（上面“标点”那一条）。标题在标点后面折行；折了行的标题，最后一行不能只剩一个字。在浏览器里量（`tests/e2e/titles.spec.ts`）：每一站都打开，窗口从 960 到 1920 像素宽（横排）、从 600 到 1100 像素宽（沙盘在上）每 20 像素一档拉过去，看每个字落在哪一行；四种标准的窗口上字号是 40、34、36、36。2026-11-24 量到的：八站一共量 600 次，折了行的 43 次，最后一行只剩一个字的没有。
- **正文一行多少个字。** 一行最多 30 个字（`--measure`）：竖着拿的平板上就是 30 个；横排的版面上是文字栏的宽度减去两边的空，1024 像素宽的窗口 20 个字，1389 像素起 23 个字。段首空两个字，两端对齐。在浏览器里量（`tests/e2e/leaf.spec.ts`）：横排 18 到 24 个，竖着拿的平板 28 到 32 个，算出来的和一行一行数出来的一样。同一份测试还查：可以点开的词下面有一道强调色的虚线，点开的小注里类别的小标签和小注的底比不低于 4.5 比 1；正文那一栏里能点的东西都不小于 44 像素见方（正文里的词有一行那么高）；“读原文”“凭据”折着显加号、点开显减号；位置那一行的两个链接下面各有一道细细的灰线（平板上没有“鼠标移上去”，靠它看得出点得动）；宽屏上文字栏一直到屏幕的底边，是平的一种颜色。
- **站点页贴着底边的那一条，和讲解员面板。** 那一条是文字栏的下边：页面的颜色，平的，上边一道细线，64 像素高（横排的版面 68，`--bar-h`）；横排的版面上和文字栏一样宽，别的窗口上和窗口一样宽。里面并排三格，和正文那一栏的左右边对齐：左边上一站，中间“问讲解员”，右边下一站（链接带着 `rel="prev"`、`rel="next"`；“上一站”“下一站”是黑体的小字，站名是黑体、大一些，站名下面一道细细的灰线，和页面顶上“位置”那一行的链接一样——往下一站去只有这一处，要看得出点得动）；这一站在头或在尾，那一头的格子空着；这一站还没写，中间空着。“问讲解员”平常是一块白底的板——一圈墨蓝的细线、墨蓝的字，只有按着或者鼠标移上去的那一下才铺墨蓝的底、字变白：墨蓝在这个网站上只做记号。正文末尾是并排的两个链接：“回到各站目录”和“来源”。点开“问讲解员”，面板是一块盖在页面上的白底的板（上边一道细线，线上面压着一道影子）：横排的版面上和文字栏一样宽、一直到窗口的底边，不挡沙盘；别的窗口上从底部升起，最高到窗口的四分之三，里面的字和正文那一栏一样宽、对齐。在浏览器里量（`tests/e2e/leaf.spec.ts`）：四种标准的窗口上各量一遍，头一站、最后一站各看一遍，再把各站里最长的两个短名字（现在是五个字的）换到两头，看三格还放不放得下。
- **点开才下载的三段程序。** “凭据”点开以后里面的东西（连同“沙盘上的东西”一栏）、讲解员面板里面的东西、“来源”页里面的东西（下一条），各是单独的一小块程序，读者点开了才下载，不占“页面一打开就下载的程序”的份（见技术方案第七节）。一点就开：凭据那一行马上展开，面板马上出来（标题和“关闭”都在），里面先是一句“加载中…”，取到了换成内容；没取到，那里说“没能读出来。关上再点开，可以再试一次；还不行，就刷新一下网页。”，关上再点开就重取一遍（网站发了新的一版以后，旧的那一段程序已经不在了，重取也取不到，要刷新才行，所以有后半句；“来源”页没取到时说的是“这一页没能读出来。刷新一下网页再试。”）。等着的和没取到的这一句都带着 `role="status"`，读屏软件会念出来。点开才用得到的几句固定的话（各条依据的名字、“沙盘上的东西”一栏的几句）跟着那一段程序走，写在 `src/ui/foldText.ts`，不写在 `text.ts`。要打开这两样再看、再量、再拍的测试，先等里面的东西到了（`tests/e2e/helpers.ts` 的 `foldBodiesReady`）。在 Node 里测（`tests/unit/page/page-behaviour.test.tsx`）：折着只有等着的那一句，点开换成内容；没取到的再叫一次重取，取到了不再取。在浏览器里测（`tests/e2e/main-flow.spec.ts`）：把这两段程序的请求头一次断掉、第二次压住，看那两句话和重取。
  这样的一块程序里引入什么有讲究：不要引入页面那一块里自己又用到 react 的程序（`src/app/router.ts`、`useLoaded.ts`，`PageTitle.tsx`，别的组件）。打包的工具（rolldown 1.2）碰到这种引法，会把 React 的核心从页面那一块里单拆成一个文件，页面一打开就下载的程序凭空多出约 600 字节，还多一次请求（2026 年 11 月量过：引入 `src/domain`、`src/fonts/shipped.ts`、不用 react 的文字模块没有事；钩子要直接从 `react` 引）。所以“来源”页分成两个文件：架子（位置那一行、标题）在页面那一块里，里面的东西在点开才下载的那一块里。`npm run check:size` 守着（`tests/build/dist-size.test.ts`）：这三块各是单独的一块，页面一打开就下载的程序只有一个文件。
- **“来源”页。** 地址是 `#/sources`（所以没有哪位人物的 `id` 可以叫 `sources`：规则 0）。一栏字立在页面正中（最宽 640 像素，`--home-width`），没有沙盘栏，页面的底是平的一种颜色；标题和四个小标题是黑体，别的是宋体，链接是墨蓝的字、下面一道墨蓝的线；从首页的卡片后面、人物页的目录后面、每一站正文的末尾都有链接通到它。四栏，每一行从哪里来，页面自己不另记一份：字体——三套字体（照黑体、宋体、楷体的先后）的名字、哪一版、网站、许可全文的地址读的是 `src/fonts/shipped.ts`（做字体的工具写的）；地形和水——内容里的原话，每位可以点进去的人物的全程沙盘的 `credits`（排在最前面，只印头一个分号前面署名的半句）、他每一站的沙盘的 `credits`，说过的不再印：一模一样的一行只印一遍；一行里头一个分号前面的半句，前面印过的哪一行就是这样开头的，这一行也不再印（同一份地形，全程的图片署过一遍，沙盘的凭据里又署一遍，后面带的半句“裁剪和修整见上面的说明”是说给凭据里的读者听的，这一页上没有那段说明）。所以一行出处要署的名都写在头一个分号前面，分号后面只写补充的话；图片——每一站正文里的每一张图片：先说是哪一站的（那一站的短名字），后面是它的题记，再是作者、许可和出处的地址；程序——React 和 three.js 的许可全文。五份许可全文是网站自己带着的文本文件（`public/licences/`，都是英文的原文，链接上写着“（英文）”），链接直接打开它们；三套字体各自的“许可全文”“字体的网站”写的字一样，给读屏软件的名字里另带着字体的名字；“字体的网站”“图片出处”是通到别的网站的平常链接，读者点了才去，页面自己不取。页面上的话写在 `src/ui/sourcesText.ts`，跟着里面的那一段程序走；它们独有的字在点开才要的那个字体文件里，那一页打开的时候浏览器才去取。在 Node 里测（`tests/unit/page/home-sources.test.tsx`）、在浏览器里测（`tests/e2e/home-sources.spec.ts`）：每一条都对着上面那几个文件查，五份许可全文答的是 200、和 `public/licences/` 里的文件一个字不差，里面的那一段程序点进去才下载、只取一次。
- **首页。** 版面就是人物页的那一种：文字栏，旁边是沙盘栏。文字栏里是网站的名字（黑体，一行，上面一道墨蓝的短线）、一句话、内容里的每一张人物卡片（一张在一张下面）、通到“来源”页的链接。一张卡片从上到下：抬头一行——名字（黑体，横着写）、朝代和年份（黑体的小字；年份不拆开，窗口窄得一行放不下时在年份的前面换行），还没写的在这一行的右头标着“还没写”；一句话介绍（宋体）；可以点进去的最后一行是“从第一站读起”（墨蓝）。可以点进去的卡片是链接，是一块白底的板（一圈细边，圆角，底下一点很淡的影子）；还没写的不是链接，只是单子上的一行（上面一道细线，不铺底，字淡一点，名字小一号）。卡片上只有这几样，不记读者读过什么、读到哪。沙盘栏就是人物页用的那一栏（`StagePane`），摆的是第一位可以点进去的人物的全程沙盘，看的是头一节（全程），按钮、题记、“说明”和人物页上是同一套，按一方印就到那一站（2026-11-20 起；原来放的是那张全程图片）。左右排的版面上文字栏宽是窗口的 46%（最窄 464、最宽 640 像素），沙盘栏和屏幕一样高，比人物页的栏窄；上下排的版面上沙盘栏在上，钉在顶上，高是屏幕的 56%，和人物页一样。栏多大、题签在上面摆不摆得下，见“题签摆在哪”末尾和“人物页和没有自己的沙盘的站摆什么”。在浏览器里量（`tests/e2e/home-sources.spec.ts`、`pane-boxes.spec.ts`）：四种标准的窗口上两块的位置和大小、卡片（朝代和年份都只占一行）、沙盘栏里的东西都对；窗口再窄、放不下的时候（左右排里最窄的 960 像素宽的窗口上，“达尔文”那一行就是），那一行折在年份的前面，年份不拆开。
- **沙盘栏里的字。** 沙盘栏的底色是人物自己的（`tokens.css` 末尾那一块的 `--color-paper-sunk`，苏轼的是 `#c5b189`）。框架的字不直接落在这块底色上：都垫着带子或者板，沙盘栏的底是深是浅，它们一样看得清。**带子**有两条——按钮下面的那一行话，和题记那一条——底是页面的颜色，不透明（沙盘不从字底下透上来），挨着沙盘的那一边一道细线；带子上的字是深灰（和带子比 15.2 比 1）和说明性的灰（6.6 比 1）。**板**是白底、一圈半透明深灰的细边、圆角、一点影子：按钮、“说明”“换回图片”两个小按钮（看着 20、22 像素高，能点的地方有 44 像素高）、展开的说明、“沙盘正在摆出来”和没能摆出来时的那几句话；板上的字是深灰（15.9 比 1）、灰（6.9 比 1）或者墨蓝（9.2 比 1）。还用不了的按钮（刚摆好、还没转动过的“回到这一节”）是平的一块板，边和字都淡下去，没有影子。墨蓝只做记号：小节名上面的一道短线、古名今名选中的那一个（墨蓝的字、实心的圆点、垫一块淡蓝）、“说明”“换回图片”上的字、指北针朝北的那一头。指北针只有一个头：朝北的一头是实心的箭头，另一头是一根直线（2026-11-24 改的，第 51 条：原来两头都画成箭头，一头实心一头空心，二十来个像素大的时候分不出哪一头是北）。焦点框在沙盘栏里是两道：外面一圈深灰，里面贴着一圈白，栏的底是深是浅总有一道看得见；页面上别处的焦点框是墨蓝的一圈。黑体的是：按钮、小节的名字、时间、比例尺上的数、“北”、展开的说明的标题、标题后面小节的名字和“关闭”；成句的话都是宋体：题记、那一句说明、远处的那句话、按钮下面的那一行话、展开的说明、等着和出了错时的那几句。题签是人物自己的，不归框架管：纸条、楷体，脚上有印，水名是靛青（样子在 `stage.css` 的“题签”一节，只读人物的那一套记号）。平板和电脑上，沙盘栏里给读者看的字没有小于 14 像素的（全程沙盘上站号的印除外：印里的数字在宽的栏上 13 像素、窄的栏上 11 像素，它是人物自己的记号；浏览器里的这一项只在站点沙盘上查，那上面没有印。只有手机那么窄的栏上，题记下面那一行说明还会缩，最小 11 像素；地址里带 `?debug=1` 才有的那一行读数不是给读者看的）。竖着拿的平板上，展开的说明比它那一块高的时候在那一块里滚，底边有一道影子，一行字那么高，越靠底边越深（最深处是四分之一深的影子，和别的影子同一种颜色）：看得出下面还有字——底边正好停在一段话的末尾、没有哪一行被切掉的时候也看得出；滚到底影子就没有了；下面藏着的不到 40 像素（一行半）的时候，白已经盖上来，影子很淡，贴着底边的地方看不出来（2026-11-24 添的，第 51 条；`tests/e2e/main-flow.spec.ts`）。在浏览器里量（`tests/e2e/pane-look.spec.ts`）：每一段字垫在什么底上、颜色和对比；四种标准的窗口上各样字的大小、字体和粗细；按钮、题记那一条、题签的样子。
- **时间轴**（2026-11-25，第 53 条）。人物页和首页的沙盘栏里，题记上面多一条（`.stage-bar`），栏上写着 `data-stage-bar`；每一站的页面上没有。里面的东西是另一段程序（`src/timebar/`），栏里摆上全程沙盘才下载；没取到，这一条里说一句“时间轴没能读出来，刷新一下网页再试。”，别的照常。
  - **多高，什么时候不摆。** 96 像素（`tokens.css` 的 `--stage-bar-h`），栏宽栏窄都一样：上垫 4，第一行 24，第二行 18，轴 48，下垫 2。那一段程序到没到，这一条都这么高，沙盘四边留的空不变。左右排的版面上沙盘栏还是窗口那么高，下面多留这一条；沙盘在上的排法里，摆着时间轴的栏比屏幕的 56% 再高出一条（`--stage-bar-rise`），沙盘和原来一样大——给整页留空的那几条 `:has()` 因此多了一条，一共七条，都在 `layout.css` 里。沙盘在上的排法里窗口不到 768 像素高的不摆（`--stage-bar-h` 是 0），沙盘上也没有小像。栏收起来的时候跟着收起。
  - **第一行的三种样子。** 栏里面 640 像素起宽（`.bar` 上挂 `is-roomy`）：17 像素的字；首页上前面带着人物的名字；进一站的入口写全（“进第六站”）。不到 640：16 像素，没有名字，入口只是那一站的圆点和一个箭头（能点的地方不小于 44 像素）；栏不到 584 像素宽的再小一号（15 像素）。不到 540 连岁数也不写——那已经不是平板和电脑的栏。平板和电脑的六种栏上，每一段碰到的每一个农历年的两行字都放得下、不截（`tests/e2e/time-bar.spec.ts`；只放图片的栏上也查）。
  - **轴不是匀的。** 路上的一段 5 个单位；住在一站的年月 max(3, 2·√年数) 个单位；别的 max(1, 1.5·√年数) 个。所以路上的几个月画得宽，住下来的几年画得窄：住下来的格子上有两道斜线说这一格是压窄了画的（格子够 10 像素宽才画——再窄，斜线就顶着格子的边）。轴下面每十年一道刻度，隔得够 40 像素的写年份；圆点是八站，数字同题签上的印一样；圆点旁边不写各站的年份。
  - **拖、按、按键。** 拖圆钮、按在轴上、左右键（一下走这一段的八分之一）、翻页键（往后到下一段的起头；往前先到这一段的起头，再按才到上一段的起头）、Home、End。圆钮只跟着按下去的那一根手指。给读屏念的是 `aria-valuetext`：哪一年、在哪，加上那一句。
  - **播放。** 圆钮每秒走 1.25 个单位，照钟走：设备慢只是画得少，不是走得久。只有一样例外：两帧之间隔得比 799 毫秒还久的（设备画得慢，画面停住了一阵），这一帧只算 799 毫秒，多出来的不补（`src/timebar/barState.ts` 的 `PLAY_GAP_MAX_MS`）。轴上最窄的一段是 1 个单位，正好走 800 毫秒；一帧最多走 799 毫秒的路，哪一段都跨不过去，每一段的两行字至少有一帧显示出来（`tests/unit/bar-state.test.ts` 拿真的行迹从头播到尾，两帧之间隔 16 毫秒到 5 秒；正好 800 不行，那样的一帧落在两段的交界上）。两帧之间隔到 0.8 秒以上的设备上，播放因此比钟慢。页面打开的时候什么都不自己动，按了“播放”才走。走到要换一节的地方先叫沙盘换，停下来等它摆好，最多等 3 秒。读者一碰就停，停了不自己再播：按在沙盘上、滚轮、栏里的点击和按键（Tab 和单按的修饰键不算；“播放”自己和轴另管），栏收起来，窗口变矮没了地方，页面切到后台，点了进一站的入口。播着的时候题签不让开他（停下来才让）。系统设了“减少动态效果”的没有“播放”，轴的两头是“上一段”“下一段”。
  - **镜头。** 时间轴从不直接同沙盘说话，只向沙盘栏报“该看哪一节”：停在哪一站讲的年月里，就看全程沙盘上那一站的那一节；不在哪一站里的看全程。拖着（按着键）的时候，一出摆着的那一节讲的年月，先退回全程（那一节只画到这一站为止的路），放了手（最后一下按键以后 350 毫秒）才换到停下的那一节。没动过时间轴的不报：页面打开的时候同原来一模一样。
  - **小像和题签。** 小像停着的时候——站在一处，或者时间轴停在路上的一天——题签让开他：只挪碰着他的那几条；让开以后引线超过 70 像素的那一回整个重摆。他站在线上、沙盘平时没有立名字的一处的时候，旁边立出那一处的名字：同别的地名一样的题签，没有印，离他不超过 40 像素，不挨着别的地名点（它占的那一块离他，不比离别的题签指的哪一点远；他近处没有这样的空位的几处，照原样立着，`tests/stage/piece.test.ts` 把它们连数印出来）。这一条的引线画得比别的引线重：不透，粗 1.5 像素（别的引线 1 像素，透明度 0.72）——它短，多半是斜的，旁边又常有别的地名点，要靠它认出这个名字是他脚下那一处的。题签层给每一条引线写上它那条题签的 id（`data-strip-leader`），样式表里只有他这一条（`piece-name`）的一条规则（`stage.css`）；别的引线、摆题签的程序都没有动。读者点了“试试立体的沙盘”、按钮下面那一行话留着的时候，那一行话下面多留 36 像素，小像整个在它下面。只放图片的时候图片上没有小像，时间轴的字照样说他在哪里，最前一个位置的第二行多半句“；图片上没有他的小像”。
  - **图例。** 第一行右头的“图例”点开一块，盖在沙盘的下边、不盖时间轴，地方不够就在自己里面滚；同题记的“说明”一次只开一个。里面先是这一段的两行字和“说不准的：”，下面是固定的几句（`src/timebar/barNoteText.ts`；只放图片的时候头一句换一句，说那几处名字的一句不说）。最后一句讲轴上的圆圈：数字是第几站，实心的是正文已经写好的站（同题签上的印一样，照 `stopMarks` 的 `written` 画）。
  - **开关**（拍照的工具和测试用，读者拖到哪一天从不写进地址）：`?bar=整数` 从那一天起（0 是出生的那一天），只在读者还没动过时间轴的时候算数；`?bar=none` 不摆；沙盘的替身上（`?stage=fake`……）不写就不摆。替身不画小像，把叫它摆在哪记在 `data-fake-piece` 上，说没说“停着”记在 `data-fake-piece-rest` 上。

16 像素，是 16 到 32 像素上下；这一截里的每一回，浏览器测试和别处的一样查，只有一回只记下来、不拿它判对错：徐州在 1366 × 1024 转回 1024 × 1366、刚读到“石炭”的那一回，转完以后页面没有动，后面那一节的标题离阅读线只有 0.2 像素，换一台机器排出来的字差几个像素，它落在哪一边就说不准）。这些是在 Chromium 里量的；平板转方向的时候 Safari - **老平板。** iPadOS 15 的 Safari 跑不了测试，靠两样守着：样式表里不许有它不认的写法（`npm test` 扫源文件，`npm run check:size` 扫构建出来的样式表；`@container`、`cqw` 一处也不许有）；浏览器测试里有一个“老平板”的替身（`tests/support/oldIpadSheet.ts`）：把构建出来的样式表照它的读法改一遍（`@container` 的块去掉，用了 `cqw` 的声明作废）再给页面，三种平板的窗口上（竖着的、横着的、竖着的大平板）沙盘栏的大小、四边留的空、题记的排法、字的大小都要和平常一样。现在改完一个字不差——老平板读到的就是同一份样式表；这只是照规矩推出来的替身，不是 Safari，真机上还要看。
- **定格图有一张取不到。** 只放图片的时候（设备带不动立体的沙盘，或者它摆不了），哪一小节的图片取不到（网断了一下），沙盘栏先照“没有图片”的样子办：一句话，不钉着。这不是从此不放图片：读者读到另一小节的时候，或者浏览器说网又通了，再放一次；还是取不到，照旧收起来等下一回；浏览器明说断着网的时候不试（`src/ui/StagePane.tsx`；`tests/unit/page/pane-stills.test.tsx`）。

由谁查：`npm run check:size` 查构建出来的网站里正好是记录里的这几个文件，`index.html` 预先声明的正好是记录里说要预先声明的那两个、和样式表里写的是同一个文件；`npm run test:e2e`（`tests/e2e/fonts.spec.ts`）在浏览器里走一遍网站，问浏览器每一段字是哪个字体画的：都得是随站的字体，样式是黑体的只用了黑体、粗细是 500，样式是楷体的只用了楷体、而且只在题签上，别的只用了宋体、粗细是 400；没有一个请求出了网站自己的地址，第三个文件只在该取的时候取、只取一次，楷体的文件在“来源”页上不取；把字体文件压住不给的时候按钮、标题和题签上照样有字。走到的地方：电脑的窗口里每一页（“来源”页在内）、每一站（小注、原文、凭据、讲解员面板都打开）、每一小节的题记和题签、沙盘栏平常看不到的几种样子（画不了、太慢、画面断了、没摆出来）；竖着拿的平板（沙盘收起、展开）、横着拿的平板、一个手机那么窄的窗口；页面的程序起不来时的那两句话。没有走到的是“加载中…”和“没能读出来”那几句。这些只在 Chromium 里查得到；iPad 上的 Safari 要到真机上看。

### 怎么做，什么时候要重做

`npm run fonts`。它先数出四组字；和记录里的一样，原字体的说明（`tests/support/fontTool.ts` 的 `FONT_SOURCES`，连同留哪些排版功能）和做法也没变，仓库里的字体文件又和记录对得上、读出来合现在的做法（名称、留没留提示信息），就不重做。这时它再看照记录写的另外几样——`fonts.css`、`shipped.ts`、`probe.ts`、三份字体的许可全文：都对，说一声“已经是新的”，什么也不写；哪一样不在、被改过，照记录把它重写（许可全文照 `.cache/fonts/` 里的那一份重抄），说写了哪几样。所以查字体的测试说“运行 npm run fonts”的地方，跑这一条命令都修得好。要重做的时候才用到原字体：三个原字体文件和三份许可放在 `.cache/fonts/` 里（这个文件夹不进仓库；文件叫什么、从哪里取、记号是多少，见 README），工具先核对记号，对不上就停；工具自己不下载。四个文件做一遍几秒钟，不开浏览器。做好了读回来查：里面的字正好是要的那些，名称对，粗细是原字体的那一种，黑体的文件里留着 `halt`、别的“挤标点”的功能哪个文件里都没有；不对就停，什么也不写。同样的字做两遍，做出来的文件一个字节不差（在同一台机器上试过；换一台机器、换一种系统还没有试过）。

**什么时候要重做。** 正文、小注、场景文件、界面上的字里出现了字体文件里还没有的字；或者一个字从点开才看得见的地方挪到了一打开就看得见的地方；或者改了 `FONT_SOURCES` 里的哪一项、改了做法、裁剪用的库换了版本；或者哪个文件要不要预先声明变了（字体文件不变，记录要重写）。只是删了字、改了已有的字的先后，不用重做（文件里多带了四十个以上已经不用的字时，测试会提醒一句，不算不通过）。

**忘了重做会怎样。** `npm test` 通不过，说出是哪个字、在哪里用的：

- “䃜”（U+40DC，徐州的原文里）不在随站的字体里：运行 npm run fonts，再提交。

重做以后，把 `src/fonts/` 里变了的文件同改动一起提交。想先看看做出来什么样、不动仓库里的文件，用 `FONTS_OUT=<文件夹> npm run fonts` 试做（见 README）。

### 记录（`fonts.json`）

| 字段 | 含义 |
|---|---|
| `tool` | 记录格式的版本，现在是 3（1 里没有 `keepFeatures`、`first`、`stop`，`hinting` 也不是从文件里读的；2 里只有两个原字体，没有 `weight`、`preload`） |
| `recipe` | 做法的编号，现在是 1。名称表里“说明”那一条后半截怎么写、裁剪时另外交给库的选项，改了就加一。别的不靠这个数：原字体的说明和留哪些排版功能记在 `sources` 里逐项比；名称、说明的头一句、留没留提示信息，是读了文件对着做法查的 |
| `made` | 做的时候裁剪工具和它底下几个库的版本 |
| `sources` | 三个原字体各一项（`sans`、`song`、`kai`）：`name` 名字，`version` 版本，`file` 文件名，`from` 从哪里取的，`site` 它的网站，`bytes` 字节数，`sha256` 记号，`copyright` 原字体里的版权声明，`licence` 许可文件叫什么和它的记号，`weight` 这套字体的粗细（黑体 500，另两套 400），`keepFeatures` 说好留哪几种排版功能（原字体里有的才留得下） |
| `files` | 每个字体文件一项（见下） |

每个字体文件：

| 字段 | 含义 |
|---|---|
| `file` | 文件名 |
| `family` `postscript` | 写进文件里的两个名称 |
| `source` | 照哪个原字体做的：`sans`、`song` 或 `kai` |
| `group` | 它装的是哪一组字 |
| `range` | 样式表里有没有给它写 `unicode-range`（黑体、头一个宋体文件和楷体没有） |
| `first` | 装的是不是不用点开就看得见的字（黑体、楷体也算）。算“首次打开要下载多少”时用 |
| `preload` | 要不要在 `index.html` 里预先声明（`tests/support/fontTool.ts` 的 `PRELOAD_GROUPS`）。是黑体和头一个宋体文件；楷体只有沙盘上的题签在用，不声明：页面知道要摆沙盘了，才叫浏览器去取。`npm run check:size` 对着构建出来的 `index.html` 查：声明的正好是这里标着的那几个 |
| `weight` | 粗细：从做出来的文件里读的（OS/2 表里的数），要和原字体那一项里写的一样；样式表里这个文件的 `@font-face` 照它写 |
| `stop` | 只归哪一站（宋体按站拆开以后才有）；大家共用的是 `null`。现在都是 `null` |
| `bytes` `sha256` | 字节数和记号 |
| `count` `glyphs` | 有多少个字；有多少个字形（竖排用的标点另有字形，所以比字多） |
| `characters` | 文件里的每一个字，按编码的先后连成一串 |
| `onlyFromSrc` | 其中只在 `src/` 的程序里出现、`content/` 里哪儿也没有的字（英文字母、数字、半角符号不列）。注释里的字要是漏了进来，会出现在这里 |
| `features` | 文件里留下的排版功能。“挤标点”的六种里，黑体的文件有 `halt`、而且一定要有，别的五种没有；宋体和楷体的文件六种都没有 |
| `hinting` | 文件里留没留着提示信息（让小字在普通屏幕上清楚一些的那些数）：`kept` 或 `none`。是从做出来的文件里读的；测试再读一遍文件来对，并且对着做法查（宋体和黑体留着；霞鹜文楷本来就没有，所以是 `none`） |

“记号”在这里是文件的 SHA-256（64 个字符），和定格图清单里那种 16 个字符的记号不是一回事。

### 大小

上限写在 `tests/content/budgetRules.ts`（`technical-plan.md` 第七节）：首次打开要下载的三个文件（`yanlu-sans`、`yanlu-song` 和 `yanlu-kai`；楷体的不预先声明，可是首页上就有题签，一打开也要下载，所以也算在里面）合计不超过 450 KB；任何一个文件不超过 300 KB，过了 280 KB 提醒。哪个文件到了提醒的线，就把宋体按站拆开，规矩是：一个字只放在一个文件里；界面、首页、人物页用到的字，和两站以上用到的字，放在大家共用的文件里；只有一站用到的字放进这一站自己的文件（`yanlu-song-<站>.woff2`、`yanlu-song-<站>-more.woff2`）。拆开以后，首次打开要下载的合计按站分开算：大家共用的三个，加上这一站自己的那一个，取最大的一站。“该把宋体按站拆开了”这句提醒只对宋体的文件说。

按站拆开现在关着（`tests/support/fontTool.ts` 的 `SPLIT_SONG_BY_STOP`），**还不能直接打开**。已经写好、有测试的是工具这一头：哪个字归哪个文件，样式表里各个文件的 `unicode-range`，“字都在不在”认哪几个文件，大小按站分开算，构建以后查的是记录里的那几个文件。页面那一头还有三件事没有做：一、`probe.ts` 只带着大家共用的那个“点开才要”的文件里的一个字，页面空下来时只会先取那一个文件，一站自己的“点开才要”的文件要各带一个字、按站去取；二、一站自己的头一个文件没法在 `index.html` 里预先声明，这一站刚打开时它比头两个文件晚到一步，要先看一看那一会儿的样子；三、浏览器测试里“第三个文件什么时候取”那一项是照现在的四个文件写的，要重写。这三件列在那个开关上面；查字体的测试里有一项守着开关，做完才打开。

## 人物页和没有自己的沙盘的站摆什么

全程沙盘（`scenes/route.json`）摆在沙盘栏里，和一站的沙盘是同一种栏：古名、今名，中间的一个按钮，题记那一条，“说明”。

| 页面 | 沙盘栏里 | 看哪一节 | 中间的按钮 |
|---|---|---|---|
| 人物页，首页 | 全程沙盘 | 头一节（全程） | 回到全程 |
| 有自己的沙盘、正文也写好了的站（徐州、黄州） | 这一站的沙盘 | 读到的那一节 | 回到这一节 |
| 没有自己的沙盘的站 | 全程沙盘 | 写着这一站的那一节（`sections` 里 `stop` 是这一站的 id）：到这一站去的来路 | 回到这一段 |
| 有自己的沙盘、正文还没写的站（眉州） | 这一站的沙盘 | 读者在正文那一栏的单子“沙盘上看的几处”里按的那一处；没按过是头一处 | 回到这一处 |

- 有自己的沙盘、正文还没写的站（2026-11-23 起数据和校验认这种站，见“正文还没写的站的沙盘”；页面 2026-11-24 起是下面的样子，程序在 `src/ui/StopPage.tsx`）。正文那一栏从上到下：抬头照旧；一句话“这一站的正文还没写。按下面的一行，沙盘就换到那一处；各处的时间写在每一行里，不一定都在上面这几年里。”（抬头里的“时间”“年纪”照 `figure.json`，说的是这一站在他一生里排在哪；各处有各处的时间，所以有最后半句。2026-11-24 第三段改的：原来说“沙盘已经做好了”，沙盘摆不出来、又没有图片的时候这句话不是真的；原来说“年份”，眉州的一行写的是“每年正月”，没有年份）；小标题“沙盘上看的几处”（黑体）；一张单子（`ol.views`），场景有几个画面就有几行，顺序相同，一行是一个按钮（`button.view-item`，`data-view` 是画面的名字），里面是名字（黑体）、年份（黑体的小字）、题记（宋体）；折着的一行“凭据”，里面只有“沙盘上的东西”一栏，出处是场景文件自己的 `sources`；末尾的两个链接照旧。没有“问讲解员”。
  - **按一行**，就是告诉版面“沙盘该摆这一处了”，同写好了的一站读到另一小节走的是同一条路，沙盘栏不用另做什么：滑过去还是直接换、减配的一档、放图片的时候，都同徐州一样。摆着的那一行（没按过是头一行）左边一道强调色（墨蓝）的线，3 像素宽，名字右边一个小标签“正在看”（也是墨蓝的；别的小标签是灰的，小注的类别除外），带 `aria-current="true"`（小标签读屏不念）。记号在按下去的那一下就换，不等画面到；画面到了没有，看沙盘栏的 `data-stage-section`。按了哪一处不记在地址里，也不添一条浏览记录；离开这一站再回来，从头一处开始。
  - **按摆着的那一行**（2026-11-24 第三段）：读者把沙盘转开、推近以后，按“正在看”的那一行，画面回到这一处——页面替读者按一下沙盘栏里的“回到这一处”。没有转开过，那个按钮是不管用的，这一下什么也不变。沙盘收着的时候按它，照下一条展开。
  - **沙盘收起来的时候按一行**（沙盘在上的窗口）：收起的沙盘栏不跟着换画面，所以页面替读者按一下栏里的“展开沙盘”，栏展开时直接摆到那一处；栏一展开，文字往下让出一截，下一帧页面把按的那一行挪回看得见的地方（沙盘栏下面、底下那一条上面）。
  - **那一句的前半句一上来就有**；后半句、单子、凭据要等这一站沙盘的数据读出来才有。数据还在读、或者没读出来的时候只有前半句（没读出来时沙盘栏里是“沙盘没能摆出来。”和“再试一次”，再试读出来了，后半句和单子就有了）。数据读出来了、立体的沙盘却摆不出来（起不来、浏览器画不了、设备太慢）的时候，单子照旧在：按一行，沙盘栏的题记跟着换，有图片可放时图片也换。
  - **认这种站看的是那张单子**（`.views`），测试等的、样式表选的都是它，不是页面上的那两个属性：写好了的一站正文这一次没读出来时，`data-stop-text` 也是 `none`、`data-stop-scene` 也是 `yes`，那时候正文那一栏说的是“这一站的正文没能读出来。”，没有单子。行上不写 `data-section`（那是正文小节的记号），画面的名字不是标题。
  - 用键盘：标题 → “到沙盘” → 单子的各行 → 凭据 → 回到各站目录 → 来源 → 底下那一条 → 沙盘栏的按钮。在一行上按回车或者空格就换到那一处，焦点留在那一行上。

## 校验规则

0. **格式**：文件读得出来，字段齐全，类型对。人物的 `id`（卡片上的、文件夹的名字）不能是 `sources`：地址 `#/sources` 是“来源”页。场景文件另外还查：没有不认识的字段；数字在说得通的范围里（距离、宽度大于 0，倾角 0 到 85，视角 10 到 40，朝向 `bearing`、`facing` 在 0 到 360 之间，`closest` 在 0.5 到 1 之间，`plainKeep` 在 0 到 1 之间，`hillAboveM` 比 `plainBelowM` 大，土丘的 `outerM` 比 `innerM` 大）。
1. **坐标**：`[经度, 纬度]`，经度在 −180 到 180 之间，纬度在 −90 到 90 之间。
2. **站点与轨迹**：站的 `id` 不重复，也不能叫 `route`（这个名字留给全程沙盘的文件）；`legs` 比 `stops` 少一个，并且依次首尾相连。
3. **文件齐全**：`status` 为 `complete` 的站必须同时有 `.md` 和 `.json`；为 `outline` 的站两个都没有。
4. **正文**：`complete` 的站正文在 800 到 1400 字之间，每个小节至少有一段，小节标题不重复（原文、图片、凭据、沙盘的镜头都靠标题对上小节）。
5. **小注**：`anchor` 必须在正文的段落里原样出现；`kind` 是历史、地理、人文、科学四类之一；`sourceIds` 至少一个，并且都能在 `sources` 里找到。
6. **原文**：`section` 是正文里的小节标题；`sourceId` 能在 `sources` 里找到；原文和白话都不为空。
7. **图片**：文件存在；`section` 是正文里的小节标题；`alt`、`caption`、`credit`、`license`、`sourceUrl` 都填写。
8. **凭据**：正文的每个小节都有一组凭据，每组至少一条；依据不是“编写时补的”时，至少填一个出处。
9. **没有占位**：首页的人物卡片、人物资料、`complete` 的站和场景文件里，不能留占位或待办的括注：“（待”开头的文字，以及括号里带“待核、待填、待补、待定、待查、待写、起步稿”的话。还没写的站（`outline`）的抬头不在此列，但也应当填好。场景文件里查不到的事，直接写“没有查到”。

下面九条是场景数据的（规则 10 到 15 查场景文件，规则 16 查可以点进去的人物有没有全程沙盘，规则 17、18 查工具做出来的文件）。规则 10 到 15 这里写的是站点沙盘的读法；全程沙盘的场景文件（写着 `"level": "route"` 的）另有一套读法，号码一样，列在后面：

10. **场景文件**：文件名和 `stopId` 一样；这一站在 `figure.json` 里有（`complete`、`outline` 都可以：沙盘可以比正文先做好）；`style` 是程序里有的样式；`credits` 至少一条；`relief` 是统一夸大；地形文件叫 `<站>.terrain.bin`，存在，大小正好是 行 × 列 × 2 字节，不超过 1.5 MB；地形文件盖得住整块沙盘。
11. **范围**：摆件、点缀（连同树的规则写的“这几圈里不种”，`exceptAreas`）、地名点、题签指的点、修整的范围和土丘的中心、水漫不进去的地方、急滩、河上过路的地方、镜头对准的点，都在沙盘里面。河和路的线可以伸出去（沿线摆的树和船不行，线要在沙盘里面）。远处的地点在沙盘外面。
12. **类别和依据**：该写的地方都写了 `class` 和 `basis`；`class` 是五类之一；真的、今天的位置、按史料摆的，至少有一个出处；出处都在这一站的 `sources` 里；点缀规则的类别只能是点缀或按史料摆的；`recipe` 和 `levels` 写了 `note`；`unsure` 是能接在“某某的”后面的一个词组（不以“在、搭、系、从、到”开头，不是“山比……”这样的半句话），末尾不带标点。“这一站的 `sources`”只在一处：`complete` 的站在 `stops/<站>.json` 里，场景文件不能再写 `sources`；`outline` 的站在场景文件自己的 `sources` 里，必须写，id 不重复，`basis` 是 `own-words`、`record`、`later` 之一，`cite` 不空。

    3. **精度（不编日子）**：`day` 写了 `month`、`day`，是历法上有的一天，不写范围，而且 `text` 自己说到了哪一天（年号、第几年、几月、哪一天，或者“除夜”“元日”，别的什么也不带）；`text` 只到月份、季节，或者带着“以前、以后、或、之间、没有查到”的，精度不许写 `day`；别的精度不许写 `month`、`day`，范围两头都写了、写法对、不止一天，`text` 自己已经说到哪一天的精度就该是 `day`；写法末一个字是“春夏秋冬”的，精度只能是 `season`、`before`、`after`；`month` 的范围不超过 60 天，`season` 的不超过 120 天；`year` 是最早那一天的公元年；`not-found` 的 `text` 里写着“没有查到”。

    5. **路**：`journey` 是全程沙盘里有的一趟，`stopYearsOf` 是它到的那一站；每一截的 `name`、`class` 和场景里的一样，`ways` 是那一截的全部，或者（写了 `partial`）其中连着的一段；同一趟的各段接起来正好是场景里这一趟的每一截路；全程沙盘里的每一趟都有人走；路上有位置的各处离这一段走的线不超过 25 公里，先后和走的方向一样；精确到日、又有位置的各处，日子落在这一段在时间轴上的头尾之间，一个不比一个早；路上各处的日子不出这一段的范围。
    6. **第一行说的是真话**：每一段在时间轴上碰到的每一个农历年里，它最晚的开始不晚于这一年的最后一天，最早的结束不早于这一年的正月初一；一段在时间轴上不比它的范围容得下的更长；在路上、到的日子不精确到日、在时间轴上超过 93 天的一段写了 `longRoad`。农历年末、括号里写公历年和月的那些天，对每一个这样的月份做同样的两样比较；担保不了的月份不算通不过，由工具列进时间轴用的那一份（`plainMonths`），时间轴在那些天只写年份——列得对不对由第十句守着。
    7. **站**：每一站都有住下来的一段；落在它讲的年月里的各段连在一起；住在这一站的各段碰到的农历年，都在这一站发布的年份（`figure.json` 的 `years`）里面。
    8. **两行字**：`label` 最多十个字（落在一站讲的年月里的最多七个），没有弯引号，不写日子，里面有数据里这个地方的名字；`says` 最多三十二个字；路上的一句以“匀着走的：”开头；沙盘上没有他的一段，头一个半句里说“沙盘上没有他”；小像站在沙盘上的一段不说“没有他”“没有标出”；站在线上、沙盘平时没有立名字的地方的一段不许再说“沙盘上没有立某地的名字”；`says` 里的日子都列在 `saysDates` 里，照日子的先后列，句子里也照这个先后；每一个都是照史料的写法缩短来的（只许整截地删，“二十八日”删不成“八日”；“以前、以后、或、之间、初”不删；留着“以前”“以后”的，它前面的那一截日子也留着）；删掉了年份的，年名要和句子里前一个日子的一样，头一个日子的要和这一段开始摆出来的那个农历年一样，而且这一段在时间轴上不跨着正月初一；删掉了月份还说着哪一天的，年名、月份都要和前一个日子的一样；日子前面、后面紧挨着的字在那两张单子上（日子旁边不添字）；没有列的日子不许有；`first`、`last` 照同样的长度查，`label` 里有头一段、最后一段的那个地方，句子里的日子照同样的办法查，`last` 说的“虚岁多少”是表里最后一年的岁数。**说不准的要说出来**：头尾有一个不精确到日（或者写了 `earliestIs`、`latestIs`）的一段，`unsure` 不能空着；写了字的至少两个汉字；句子里说到的、把路切成一程一程的路上一处，`note` 里写着另一种说法、对不上、是推出来的，这一处要写 `unsure`，而且是 `note` 里连着的一截。
    9. **农历年的表**：头一行是出生的那一年（`newYear` 是 `null`，虚岁一岁），后面一年接一年，虚岁每年加一；正月初一是历法上有的一天，在这个公元年里，比上一年的晚 353、354、355 天或者 383、384、385 天；年名是年号加第几年，同一个年号接着数，换了年号从元年起；出生、去世的日子落在表的头尾里；每一个日子的 `text` 开头的年号纪年，和照它的公元日子在表里查到的年名一样；精确到日的写法里的月、日，和它的公元日子离那一年正月初一的天数对得上（正月的日子、“除夜”“元日”一天不差）。
    10. **时间轴用的那一份**：`itinerary.bar.json` 在，和工具现在照手写的那一份和人物的名字做出来的一字不差。前九句有问题时这一句先不查。

    两行字里的每一个字都在随站的字体里，归规则 19 查。规则查的是日子；句子里的地方、做了什么事、住了多久，路上各处的位置，靠读（见“行迹·两行字”）。
