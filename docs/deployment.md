# 部署方案

状态：负责人已审核通过（2026-11-17）：沿用象棋项目（弈间）的那一套。

## 做法

- **代码在 GitHub 上**，开发在分支上进行。
- **推送 `main` 分支后自动跑三步**：类型检查、内容校验、单元测试和构建；浏览器端到端测试；发布到 GitHub Pages。前两步不通过就不发布。
- **负责人说“发布”，才合并到 `main` 并推送。** 在此之前不推送 `main`。
- **线上是纯静态站点。** 讲解员在线上先只有界面；带大模型的版本以后在本机运行。
- **本机启动脚本**：在电脑上起服务，电脑和家里局域网的平板、手机都能打开，用来审核和实测三维地图。

## 两套环境

| 环境 | 用途 | 部署在哪 |
|---|---|---|
| 本机 | 开发、审核、平板实测 | 本机启动脚本，局域网可访问 |
| 线上 | 公开访问 | GitHub Pages |

不单设预览环境，审核都在本机完成。

## 需要记住的限制

- GitHub Pages 规定发布的站点不能超过 1 GB，每月流量的软上限是 100 GB。以后自己托管地形瓦片时，只打包轨迹沿线的范围；人物多了可能要另找地方放瓦片。
- github.io 在国内访问不稳定。家里使用以本机启动脚本为准。
- 仓库公开，全部正文和设计文档也随之公开。

## 提交规矩

- 提交不使用公司邮箱。
- 公司内部的服务地址、密钥不进仓库。
- 只在负责人明确同意后提交和推送。
