# 整体设计

状态：负责人已审核通过（2026-11-17）。要改动本文件的内容，先改这里，再改实现。

## 一句话

选一位历史名人，以“我”的身份，沿着他一生走过的路一站一站读下去，在每个地方看见当时的时代、山川、风物和技艺。

## 设计原则

1. **是学习网站，不是游戏。** 没有分数、关卡、任务。
2. **用户就是他本人。** 全程用“我”来讲，只讲他当时看到和知道的事。
3. **内容为主。** 正文由人精心编写，AI 只在旁边答疑。
4. **自然。** 不刻意解释原因，把背景和处境写清楚，读的人自己明白。每位人物独立成篇，不刻意互相连接。不刻意求新奇。
5. **全年龄。** 正文孩子能独立读完，想深入的人点开小注。
6. **趣味来自具体。** 住哪里、吃什么、路多远、钱够不够，这些让人读得进去，不靠游戏机制。

## 网站结构

只有三层页面：

```
首页：挑选一位人物
 └─ 人物页：他是谁 + 一生轨迹的地图 + 各站目录
     └─ 站点页（沿轨迹排列，约 6–10 站）
         ├─ 地图：停在这一站
         ├─ 正文：“我”的自述
         ├─ 可点开：小注、原文、图片
         └─ 问讲解员（AI 答疑）
```

- **首页**：人物卡片，每张写名字、时代、一句话介绍，按时代排列。
- **人物页**：一张画着他全部轨迹的地图，站点既是地图上的点，也按先后列成目录。
- **站点页**：三维地图是页面的主视觉，占大部分面积；正文是旁边的一栏，窄屏时地图在上。页尾是“上一站”“下一站”。

## 一站里有什么

| 部分 | 内容 |
|---|---|
| 抬头 | 站名、年份、地点（古今地名）、他当时的年纪 |
| 正文 | 第一人称，约一千字，分几小节 |
| 小注 | 点开才出现，分历史、地理、人文、科学四类，只注正文里出现的东西 |
| 原文与图片 | 他本人的诗文书信（附白话）、文物、手迹、实地照片 |
| 地图 | 这一站在哪、从哪来，站内提到的地点 |
| 凭据 | 哪些话出自他本人或史书，哪些是编写时补的 |

## 地图

- **一套引擎，所有人物共用。** 每位人物只提供自己的数据：轨迹、站点、古今地名、每一站的镜头位置。
- **全程三维。** 从地球到一条山谷是连续的：人物页从地球上看整条轨迹，进入某一站时镜头降到当地，山脉、河谷、关口都是立起来的真实地形。
- **镜头跟着阅读走。** 读到哪一站，镜头就飞到哪一站；站与站之间沿着轨迹飞过去。
- **用户可以自己转动、倾斜、缩放**，旁边有一个“回到这一站”的按钮。
- **轨迹贴着地形画**，地名立在地面上并始终朝向读者，可切换古今地名。
- **底图只留自然地貌**，不画现代道路和城市。

## 讲解员（AI 答疑）

- 站在故事之外，用第三人称回答，不扮演人物。
- 以站内已编写的内容为依据，答不了就说不知道。
- 主要用途：解释字词，换一种说法讲给孩子听，回答“后来怎样了”。

## 人物与制作顺序

1. 先做一位，把整套骨架走通：苏轼。
2. 再做一位不同类型的，验证骨架通用：达尔文或徐霞客。
3. 然后扩到首批约十位。

## 原型的范围

- 首页：两三张人物卡片，只有苏轼可以点进去。
- 苏轼人物页：全程地图加八站目录。
- 一到两站的完整内容，能点开小注和原文。
- 讲解员先做出界面，答疑功能随后接入。
- 验证三维地图在平板和手机上是否流畅、地名是否清楚。

## 暂不做

账号与登录、阅读进度统计、搜索、人物之间的关联、评论与分享。
